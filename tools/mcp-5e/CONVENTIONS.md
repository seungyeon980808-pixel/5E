# mcp-5e 호출 규약 (CONVENTIONS)

> 설치는 `GUIDE_FOR_TEACHERS.md`(비개발자용) / `README.md`(개발자용).
> 이 문서는 **설치 후, Claude가 도구를 어떤 순서·문법으로 부르는가**를 정한다.
> 그리는 내용의 규칙(선·라벨·배치)은 `docs/FIGURE_DESIGN_PRINCIPLES.md`(바이블)가 정본이다.
> 작성 2026-07-31.

## 표준 호출 순서 (문법)

모든 그리기 작업은 이 여섯 단계를 따른다. 건너뛰어도 되는 단계는 표시해 뒀다.

```
① app_status                     연결 확인. 실패 안내문은 그대로 사용자에게 전달
② describe_schema (type 지정)     그 그림에 쓸 타입만. 21종 전체 나열은 첫 사용 때 한 번
③ set_page { page, create }      그림마다 페이지 하나. 기존 그림 위에 겹쳐 그리지 않는다
   set_artboard { w, h }          아트보드는 눈대중(바이블 §18) — 한 패널 90×60, 두 패널 150×50~60
④ add_objects / add_graph / add_circuit / add_incline_scene
                                  path 생략 = 열린 화면에 바로 (기본).
                                  한 그림을 여러 번에 나눠 넣지 말고 objects 배열로 한 번에.
                                  경사면 문항은 add_objects 로 조립하지 말고 add_incline_scene (아래)
⑤ export_image                    눈 확인. 겹침·잘림·라벨 위치를 보고 고친다
⑥ remove_objects → ④ 반복         수정 루프. 목표 2회 이내(바이블 §8)
```

**저장은 사용자의 손으로.** 화면에 그린 결과가 마음에 들면 사용자가 `Ctrl+S`(프로젝트 저장)
한다. Claude가 파일을 덮어쓰지 않는다 — 들어온 변경은 전부 Ctrl+Z로 되돌릴 수 있는 상태를
유지한다.

## 페이지·이름 규약

- **그림 하나 = 페이지 하나.** `set_page`/`add_objects.page` 로 반드시 지정한다.
- 기출 재현 페이지 이름: `10번`, `17번` 처럼 문항 번호.
- 창작 페이지 이름: `창작1`, `창작2` ….
- 파일로 만들 때(`path` 지정)는 기존 파일을 덮지 않고 새 이름으로 (`…_v2.json`).

## 좌표·값 규약 (자주 틀리는 곳)

- 단위 **mm**, 원점 **아트보드 중앙**, +y **아래**.
- 선 굵기 0.35 / 그래프 계열 0.4 (바이블 §17). 점선은 §17의 명칭 표대로.
- 라벨은 주인 객체에 (`labelInner/labelOuter`, `label`) — 독립 `formula`/`text`는
  주인이 없는 글자뿐 (바이블 §1).

## 장면 툴 — 좌표를 계산하지 않는다 (2026-07-31 추가)

`add_circuit`·`add_graph`·**`add_incline_scene`** 은 같은 사상으로 만들어졌다:
**모델에게 mm 를 묻지 않는다.** 좌표 산술이 남아 있는 한 어떤 모델도 거기서 틀린다.

| 무엇을 준다 | 무엇을 안 준다 (툴이 계산한다) |
|---|---|
| 경사각·면 이름·면 위 위치 `s`(0~1) | 접촉점, 블록 회전각과 그 **부호**(§16), 법선 방향, 띠의 안쪽/바깥쪽 |
| 선의 **이름**(외형선·기준선·가상선…) | `dashLength`·`dashGap` 숫자(§17 표) |
| 무엇을 그릴지 | 그리는 순서(z) — §19의 층 순서로 고정 |

`add_incline_scene` 의 면 이름은 둘뿐이다 — `경사면`(s=0 아래끝, s=1 꼭대기)·`수평면`.
빗면은 `triangle` 자산, 마찰 띠는 면 안쪽(§11), 블록은 면 바깥쪽으로 자동 배치된다.

**응답에 검산 리포트가 항상 붙는다.** 접촉 거리(§16 통과선 0.01mm)·되잰 각도·글자 간격(§11)을
만들어진 객체에서 **되짚어 재서** ✔/⚠ 로 돌려준다. ⚠ 가 있으면 값을 고쳐 다시 부른다
(같은 페이지에 다시 부르면 겹치므로 `remove_from_app` 이 먼저다).
이미지 판독이 약한 모델도 이 문장만 읽고 고칠 수 있다 — 그게 이 리포트의 목적이다.

## 치수 표시 — `add_dimension` (2026-07-31 추가)

기출 483장 중 **129장**이 치수 표시를 쓴다(이것 하나만 막고 있던 도판 **89장**).
치수선 본체는 원래 있었다 — **`line` 의 `lineMode:"lengthArrow"`** 가 양끝 화살촉 +
끝 캡(`dimensionVariant`) + 가운데 라벨(`dimensionLabel`)을 한 객체로 그린다.
`add_dimension` 은 **그 직선 도구의 확장**이고 새 객체 타입이 아니다 — 없던 것은
"두 기준점에서 치수선까지 뻗는 점선 연장선의 자동 정렬" 하나뿐이었다.

| 무엇을 준다 | 무엇을 안 준다 (툴이 계산한다) |
|---|---|
| **재는 두 점**(`from`·`to`) — 그림 위 실제 점 | 치수선의 좌표, 오프셋 방향의 **부호** |
| 어느 쪽으로 뺄지 이름(`side`: above/below/left/right) | 연장선 두 개의 시작·끝, 넘김(overshoot) |
| 방향(`direction`, 기본 auto) | 가로/세로/빗변평행 판정, 두 점의 높이가 다를 때의 기준선 |
|  | 점선 규격(치수보조선 §17: 굵기 0.35, 1.0/0.3) |

- **연속 치수는 `dims` 배열로 한 번에** 준다. 기준점을 공유하는 연장선은 자동으로 하나로 합친다
  (막대 문항의 `L·3L·2L·4L·4L` → 치수선 5 + 연장선 6).
- 빗면 위 치수는 `direction:"parallel"` — 진행방향 기준 `side:"left"|"right"` 로 고른다.
- 치수선이 짧아 화살촉이 라벨을 덮으면 `labelPos:"above"` 등으로 라벨만 밖으로 뺀다.
- 응답에 **잰 길이·오프셋·연장선 수**가 문장으로 온다. 반대쪽에 붙었으면 그 문장으로 안다.

**아직 안 되는 것**: 도르래(경사면 꼭대기)·다단 트랙(기둥–경사–고원–내리막).
엔진은 면을 일반적으로 다루게 짜 뒀으니 `add_track_scene` 을 얹으면 된다.

## 삽화 부품 — `add_part` (2026-07-31 추가)

사람·손·차량은 **그리지 않는다.** 기출 PDF 안에 600dpi 원본이 있으니 오려 쓴다.
만드는 절차는 `docs/PARTS_PIPELINE.md`, 결과는 `assets/exam-parts/manifest.json`.

- `part` 없이 부르면 **쓸 수 있는 부품 목록**이 온다. 먼저 그걸 본다.
- **쥔 그림은 두 조각이다.** 손바닥은 물체 뒤, 손가락은 물체 앞에 있어야 쥔 것으로 보인다.
  `between` 에 쥐는 대상을 주면 [뒤 조각 → 그 객체 → 앞 조각] 순서로 들어가 저절로 그렇게 된다.
- `gripAt` 에 물체의 모서리 좌표를 주면 쥐는 선이 거기 맞는다. `at`(좌상단)보다 이걸 쓴다.
- 크기를 안 주면 **기출 인쇄 크기 그대로**(손 가로 6mm). 시험지 도판은 작다 — 키우기 전에 원본 크기를 본다.

## 사선 배선 — `add_circuit` 의 `wires` (2026-07-31 추가)

삼각형·대각선·격자 회로는 `box` 대신 `wires` 를 준다. 구간마다 두 점을 찍고 소자를 얹으면
사선 위에서도 저항 지그재그가 알아서 기울어진다.

**이건 부품이 아니라 빌더 문제였다.** `circuit` 객체는 원래 p1·p2 를 받아 어느 각도로도
놓인다 — 없던 것은 "구간을 따라 놓고 남은 곳을 도선으로 잇는" 계산뿐이었다. 도판 분해에서
`diagonal_wiring` 을 "없는 부품"으로 적었던 것은 오진이다(§ 반드시 세 곳을 볼 것).

## 스탠드·레일 부착 — `add_stand_rig` (2026-07-31 추가)

스탠드(clamp)·용수철(spring)·블록(rect)은 원래 다 있었고, 없던 것은 **부착 관계**였다.
매다는 위치는 가로대에서의 `s`(0~1)로만 준다(0=기둥 쪽, 1=바깥 끝). mm 를 계산하지 않는다.
`rail` 을 주면 이중선 레일 위에 바퀴 달린 운반대를 얹는다.

## 하지 말 것

- **브라우저 콘솔로 앱 내부 모듈을 직접 호출하지 않는다** (`import('/js/state.js')` 류).
  2026-07-31 세션에서 이 뒷길로 그렸는데, 이는 앱 개발자 환경에서만 가능하고
  undo 스택·그룹 상태를 앱과 다르게 만들 수 있다. MCP 도구로 안 되는 일을 만나면
  그 일을 **아래 '공백 목록'에 적고 도구를 보강**하는 게 옳다.
- `path` 모드로 열려 있는 파일을 직접 수정하지 않는다 (앱과 충돌).

## 다른 사람에게 설치시키기 (요약)

`GUIDE_FOR_TEACHERS.md` 가 비개발자용 전체 안내다. 골자만:

1. **Node.js LTS 설치** (nodejs.org)
2. **5E 저장소 ZIP 다운로드** 후 압축 해제
3. `claude mcp add 5e -- node "<푼 경로>/tools/mcp-5e/server.js"`
4. 5E 를 `http://localhost` 또는 GitHub Pages 로 열고 **새로고침** → 왼쪽 아래 `MCP 연결됨` 배지 확인
5. Claude 에게 "지금 5E 화면에 ○○ 그려줘"

전제: Claude Code 를 쓸 수 있는 유료 구독. 5E 배포 페이지가 아니라 로컬 클론으로 열어도 된다.

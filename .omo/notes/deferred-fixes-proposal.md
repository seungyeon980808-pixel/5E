# 보류 항목 14개 수정 기획안

기준 제품 커밋: 529e7919. 이 문서는 제시한 기획안을 보존한다. 아직 구현하지 않았으며, 3D 실험은 별도 작업으로 유지한다.

## 1. AI 작업을 막는 오류 (9·10·13)
- 복수 레퍼런스를 한 구성으로 변환. 순서 및 가로/세로 연결을 배치 미리보기에서 정하는 방식을 제안한다. 구체 배치 방식은 확정 요구가 아닌 제안이다.
- 원본·기존 결과·생성 중 표시가 같은 표시 영역을 사용하도록 정리. 후속 변환 시 기존 결과를 밀거나 임의 축소하지 않는다.
- 코멘트를 결과 버전과 이미지 좌표에 연결. 확대·스크롤·버전 변경 후 위치, 작성·저장·편집·삭제 및 요청 반영을 검증한다.
- 대화와 코멘트는 초안이며 변환하기 클릭 시 대상과 내용을 확정. 실패 시 입력 보존.

## 2. 라이브러리 탐색 (3·4·6)
- Space 체크는 스크롤과 카드 위치 유지. 선택 목록 유무에 따른 높이 변화 방지.
- 선택 목록·개수·해제 조작을 결과 스크롤 밖에 고정. 긴 목록은 내부 가로 탐색.
- 파일 단위는 크롭 없는 전체 PDF 연속 스크롤. 페이지 단위는 검색 결과 3열 유지.
- 현재 및 주변 페이지만 우선 렌더링. 실제 327쪽 문서 처음·중간·끝 및 검색 없는 탐색 검증.

## 3. 공통 디자인 (1·2·5·8·12·14)
- 활성 토글/검색 종류/파일·페이지는 파란 배경. 카드 테두리는 균일한 한 겹.
- 소스 추가 같은 일반 실행 버튼은 중립색. 키보드 포커스는 식별 가능하되 선택 표시와 중복되지 않게 한다.
- 버전 드롭다운은 공통 색상·높이·간격 및 방향키·Enter·Esc 동작 적용.

## 4. 공간과 안내 (7·11)
- 상단 복귀·제목·소스 추가 배치 압축. 네이티브 창 조작 버튼 영역 확보.
- 내부 검사·모델·추론·프롬프트성 안내는 일반 화면에서 제거. 준비·진행·완료·실패 및 필요한 조치만 표시.
- 실행되지 않은 검수를 진행했다고 표시하지 않는다.

## 5. 완료 검증
로컬 PDF → 전체 탐색 → 복수 크롭 → 한 작업대 → 최초 변환 → 점/영역 코멘트 → 두 번째·세 번째 변환 → 이전 결과 선택 → 저장 → 재실행을 같은 작업에서 연속 검증한다.
창 크기·전체화면·Space 반복·Esc도 확인한다. 항목별 수정/설치본 확인/남은 문제를 구분하고 자동 테스트와 실제 생성 검증을 구분한다. 보고된 현상이 남으면 완료 처리하지 않는다.

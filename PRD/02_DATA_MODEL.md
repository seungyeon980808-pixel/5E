# 5E 튜토리얼(따라하기) — 데이터 모델

> 서버·DB가 없는 정적 웹앱이므로, 여기서 "데이터"는
> ① 코드에 내장되는 코스 정의(JS 객체)와 ② 브라우저에 남는 진행 기록(localStorage) 두 가지다.

---

## 전체 구조

```
[코스 Course] --1:N--> [단계 Step]
     |
     └─(id로 연결)─> [진행 기록 Progress]  (localStorage)

[도움말 주제 HelpTopic]  (코스와 독립 — 목록만 있는 평면 구조)
```

---

## 엔티티 상세

### Course (코스) — `tutorial-courses.js`에 내장
하나의 따라하기 커리큘럼. "첫걸음", "기출 검색→고쳐쓰기" 같은 단위.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| id | 고유 이름 (영문, 진행 기록의 키) | `first-steps` | O |
| title | 목록에 보이는 이름 | 첫걸음 | O |
| desc | 한 줄 소개 | 화면 구성과 대표 흐름을 한 바퀴 | O |
| minutes | 예상 소요 분 | 5 | O |
| next | 완료 후 추천할 코스 id 1~2개 | `["exam-search"]` | X |
| steps | 단계 배열 (아래 Step) | — | O |

### Step (단계)
코치 창 하나에 해당하는 최소 단위.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| target | 짚을 화면 요소를 돌려주는 함수 (CSS 선택자 배열 반환). 함수인 이유: 튜토리얼을 켜는 시점의 실제 요소를 잡기 위해 (HwpPalette와 동일한 이유). 여러 개면 전체를 감싸 구멍을 판다 | `() => ['#btn-exam-search']` | X (없으면 화면 가운데 안내) |
| title | 코치 창 제목 | 기출 검색 열기 | O |
| text | 설명 본문 (짧은 존댓말 단락) | 여기를 누르면 552문항이… | O |
| action | 이 단계 진입 시 1회 실행할 준비 함수 (연습 페이지 생성, 패널 펼치기 등) | `() => pages.create(…)` | X |
| wait | 실습 단계 여부. 값은 완료를 감지할 이벤트 서술 객체 | `{event:'click', on:'#btn-exam-search'}` | X (없으면 [다음] 버튼) |

### Progress (진행 기록) — localStorage
| 키 | 설명 | 예시 값 |
|------|------|------|
| `5e.tutorial.done` | 완료한 코스 id 목록 | `["first-steps"]` |
| `5e.tutorial.resume` | 중단 지점 `{courseId, stepIndex}` | `{"courseId":"draw-tools","stepIndex":4}` |
| `5e.tutorial.bannerDismissed` | 첫 방문 배너를 거절했는지 | `true` |

> ⚠️ 가정: 진행 기록은 전체 백업 ZIP에 포함하지 않는다 — 기기별 학습 기록이지 작업물이 아니므로. 아니라면 알려주세요.

### HelpTopic (도움말 주제) — `help-content.js`에 내장 (Phase 2)
HwpPalette `help_content.py`의 `TOPICS = [(제목, 본문)]` 구조를 그대로 옮긴다.

| 필드 | 설명 | 예시 | 필수 |
|------|------|------|------|
| title | 주제 제목 (목록 순서 = 배열 순서) | 기출 문항 검색 | O |
| body | 본문 (일반 글꼴, 표 없이 · 글머리표) | · 압축 코드 261101 = … | O |

## 왜 이 구조인가

- **내용과 엔진의 분리** — 코스 내용(`tutorial-courses.js`)과 연출 엔진(`tutorial.js`)을 나누면, 문구를 고칠 때 엔진 코드를 안 건드린다. HwpPalette가 `help_content.py` / `help_ui.py`를 나눈 것과 같은 원칙이고, 사용자의 "기능별 파일 분리" 대원칙과도 일치한다.
- **target을 함수로** — 5E의 패널·버튼은 상태에 따라 다시 그려진다. 선택자를 실행 시점에 평가해야 죽은 요소를 짚지 않는다.
- **확장성** — Phase 2에서 코스 6개를 추가할 때 `tutorial-courses.js`에 객체만 보태면 된다. 엔진·저장 구조는 그대로.
- **단순성** — 서버·계정이 없으므로 진행 기록은 키 3개면 충분하다. 과한 스키마를 만들지 않는다.

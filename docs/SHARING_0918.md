# AI 작업 문서 공유 (0918)

출발: `7ce6c2c2bb1618443e580cfbbe7ada61fdbbf574`, 독립 브랜치 `codex/5e-sharing-0918`.

## 구현 순서와 범위

1. 완료: 실제 AI 작업 스냅샷과 이미지 바이트를 인증과 분리한 문서로 묶기. 송신자 전체 작업 목록, 활성 작업, 원본/크롭, 생성 버전, 프롬프트, 생성 설정, 자유 배치, 비교 상태 포함. 실행 중인 서버 AI 대화는 이전하지 않음.
2. 완료: 1시간 서버 공유 저장/만료/해제, 수신 문서 IndexedDB 저장 및 독립 작업대 복원. 보기 전용은 앱 편집 제한. AI 실행에는 수신자 계정 사용.
3. 완료: 설정 → 파일 → 공유 → 튜토리얼 순서, 기존 SVG 선/크기/버튼 유지. 실제 개발 화면과 분리 데이터로 검증.

## 저장 방식과 남은 결정

현재 서버는 Render Free 시험 구성, 인증/생성 파일은 OS 임시 폴더. 개발 공유 저장도 인증과 별도 임시 폴더를 사용하며 생성 시각 기준 1시간에 접근 차단/삭제한다. 재시작·재배포·휴면 시 그 전에 사라질 수 있어 1시간 접근 가능성은 보장하지 않는다. 수신 완료한 브라우저 문서는 TTL과 독립적이나 브라우저 데이터 삭제/저장소 회수에는 영향을 받는다.

공식 근거: [Render Free](https://render.com/docs/free), [Persistent Disks](https://render.com/docs/disks).

보존 선택지: (A) 유료 Render 서비스+영속 디스크: 현재 파일 저장 구조를 유지할 수 있음. 백업 스냅샷에 삭제 자료가 남을 수 있어 삭제 정책 결정 필요. (B) 별도 영속 DB/오브젝트 저장소: 무료 런타임 재시작과 문서 보존을 분리, TTL 접근 차단과 실제 삭제 작업/운영 책임 필요. 서비스 생성·가입·과금·배포는 별도 사용자 결정. 어느 방식도 장애 중 접근까지 보장하는 것은 아님.

## 검증/반영 기록

소스 구현과 로컬 개발 검증만 수행. 커밋·푸시·배포·설치본 생성은 별도 승인 범위.

- 공유 단위/HTTP 검증: `node --test tests/test-ai-sharing.mjs` 11개 통과. 이미지 바이트·여러 PDF 페이지/크롭 정보·생성 버전·배치/설정·인증 제외·정확한 1시간 경계·실제 파일 삭제·해제·저장 실패·CORS/기존 인증 격리·익명화된 시간 기록 확인.
- 실제 Chromium, 분리한 송신/수신 프로필: `tests/manual/ai-sharing-qa.cjs` 8개 시나리오 완료, pageerror 0. 실제 PNG 크롭 두 개와 저장된 생성 PNG 버전 복원, 클립보드 복사, 보기 전용 입력/AI/삭제 차단, 버전/비교/원본 선택, 편집 사본 코멘트 보존, 만료 후 IndexedDB 재열기, 새 브라우저의 만료 접근 차단, QuotaExceededError, 링크 해제, localStorage 작업대 목록 소실 후에도 수신 편집 유지 확인. 시계 주입으로 1시간 경계를 검증했으며 실제 1시간 대기 테스트는 아님. 생성 결과는 기존 결과 PNG를 사용했고 유료 AI 새 실행/실계정 로그인은 수행하지 않음.
- 375/768/1280 화면과 정상/만료/저장 실패 상태 캡처: `/tmp/5e-sharing-0918-qa/`, `report.json`. 첫 검토에서 한국어 줄바꿈/저장 오류 설명을 보완한 뒤 전체 화면을 새로 캡처했음. 두 독립 시각 검토 결과는 같은 폴더의 `review-functional.md`, `review-fidelity.md`에 기록.
- 변경 JavaScript 문법 검사, `git diff --check` 통과. LSP 서버는 설치되지 않아 LSP 검증을 수행하지 않음.
- 관련 기존 UI/코멘트/시간/원본 작업 테스트 35개 중 34개 통과. `desktop/ai-workbench-stages.test.cjs`의 과거 전환 애니메이션 소스 정규식 검사 1개는 시작 HEAD의 소스에서도 동일하게 실패. 기존 게이트웨이/결과/프록시 9개 중 2개는 `AI result view source changed`, `AI panel source changed`로 실패하며, HEAD 원본을 변환 함수에 전달해 동일 실패 확인. Render 시험용 `/editor/` HTML 소스 변환기는 기존 통합 UI와 맞지 않음. 공유 API 자체와 현재 정적 앱 수신 경로는 별도로 검증했고, 이 관련 없는 변환기는 변경하지 않음.
- 지정 개발 명령 `scripts/start-library-repair-dev.command`로 실행. 원래 복구 캔버스를 유지하고 네이티브 툴바 순서와 공유 창 안내를 직접 확인. 마지막 한국어 오류/안내 문구 보완은 소스와 최신 Chromium 화면에서 확인했으며, 네이티브 창은 미저장 사용자 작업 때문에 강제 종료하지 않았으므로 저장 후 재실행이 필요. 기존 개인 PDF 1개 및 제공 PDF 72개/이미지 998개 연결, 2025/2026 검색과 PDF 본문 일치 페이지 확인. 검증용 검색어와 제공 자료 선택은 원래 상태로 복원.
- 로컬 공유 서버 `http://127.0.0.1:19618` 실행 중. 현재 개발 앱은 `FIVE_E_SHARING_BASE_URL`로 이 서버를 사용하므로 같은 컴퓨터 브라우저에서 확인할 수 있음. 외부 사람에게 전달 가능한 배포 링크는 아직 아님. 사용자 미저장 캔버스를 보존하기 위해 종료 경고에서 취소했고, 임의 파일 저장/폐기는 하지 않음.

## 사용자가 직접 확인할 순서와 합격 기준

1. 열려 있는 미저장 캔버스 작업을 먼저 저장하고 개발 실행창을 종료한 뒤 `FIVE_E_SHARING_BASE_URL=http://127.0.0.1:19618 scripts/start-library-repair-dev.command`로 재실행. 라이브러리에서 기존 자료가 검색되는지 확인. 서로 다른 PDF/이미지의 필요한 부분을 AI 작업에 추가하고 생성 결과가 있는 작업을 선택. 원본/생성 버전/배치가 기대한 상태여야 함.
2. 상단 공유 → 보기 전용 → 링크 만들기 → 링크 복사. 같은 컴퓨터의 별도 브라우저 프로필에서 링크 열기. 두 원본과 생성 버전, 선택 원본/비교 배치가 동일하고 보기 전용 표시가 나와야 함. 프롬프트 수정·AI 실행·작업 삭제는 차단되어야 하며 버전/비교/확대 이동은 가능해야 함.
3. 편집 가능 링크를 새로 만들어 다른 프로필로 열고 결과에 코멘트 추가 후 다시 열기. 수신 사본에만 코멘트가 남고 송신 작업은 바뀌지 않아야 함. 실제 AI 재실행은 수신자의 로그인으로 확인 필요.
4. 수신 저장 완료 후 송신 창에서 그 링크 공유 해제. 이미 받은 브라우저는 새로고침해도 문서/편집이 남고, 처음 여는 새 프로필은 만료/해제 오류를 보여야 함. 실제 운영 서버의 휴면·재시작·장시간 만료와 외부 수신은 배포/저장 방식 결정 후 확인 필요.

## 남은 일

외부 배포 승인, 임시 저장 유지 또는 영속 저장 서비스 선택, 배포 후 실제 계정 AI 재실행·외부 수신 확인. 로고 교체와 썸네일 자산 변경은 보류하며 대상(메신저 카드/앱 아이콘)에 따라 별도 시안을 선택. 소스와 로컬 개발 실행창에 반영했고 설치본·운영 서버에는 미반영. 커밋은 결과 확인 후 사용자 명시 승인 필요.

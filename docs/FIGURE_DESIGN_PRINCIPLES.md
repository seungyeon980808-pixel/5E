## 0. 대원칙 — 재현이지 창작이 아니다

노바 프롬프트의 첫 문장이 그대로 우리 기준이다.

- **의미를 재해석하지 않는다.** 구조·구도·상대 위치·상대 크기를 원본 그대로 둔다.
- **요소를 더하거나 빼지 않는다.** 라벨·숫자·기호·개수·관계가 원본과 1:1이어야 한다.
- **실선/점선의 의도를 지킨다.** 점선은 "숨은 선·보조선·골(骨)" 같은 의미를 지고 있다.
- 스캔 원본의 결함(기울기, 번짐, 종이 질감, 손필기)은 **재현 대상이 아니다.** 그건 걷어낸다.

우리가 원본보다 나아져야 하는 것은 **선의 균일함과 수평·수직의 정확함**뿐이다.
그 외에 "더 예쁘게"는 전부 오류다.

## 1. 자산 우선 (Asset First) — 오늘 가장 크게 어긴 원칙

**직접 도형을 조립하기 전에, 5E에 이미 그 물건이 있는지 먼저 본다.**

2026-07-30 실패 사례: 10번의 도르래를 `ellipse` 3개(바깥 회색 원 + 안쪽 흰 원 + 가운데 점)로
손수 조립했다. 그런데 5E에는 **`optics` 의 `pulley`**, **`apparatus` 의 `pulley`** 가 이미 있다.
원기둥도 마찬가지로 `solid3d(kind:cylinder)` 가 있는데 음영 필드를 안 찾아보고 넘어갔다.

### 그리기 전 점검 순서

1. `describe_schema` 를 **type 없이** 호출해 28종 목록을 훑는다.
2. 그리려는 물건이 전용 타입에 있는지 본다:

| 원본에 있는 것 | 5E 자산 |
|---|---|
| 도르래 | `optics(pulley)` · `apparatus(pulley)` |
| 원기둥·원판·직육면체·빗면·책상·수평면 | `solid3d` (kind: box/slab/cylinder/wedge/desk/plane) |
| 용수철·실 | `spring` (springStyle: helix=코일, line=실) |
| 진자 | `pendulum` |
| 전기력선·점전하 | `chargefield` |
| 자기력선·막대자석·도선 | `fieldlines` |
| 정상파(줄·열린관·닫힌관) | `standingwave` |
| 렌즈·거울·광원·스크린 | `optics` |
| 회로 소자 | `circuit` (`add_circuit`) |
| 좌표평면·그래프 | `coordplane` + `add_graph` |
| 자·각도기 | `gauge` |
| 지시선 + ㉠㉡ 이름표 | `labeler` |
| 지면 위 원호·포물선 궤적 | `groundarc` · `parabola` |

3. 없을 때만 기본 도형으로 조립한다.

### 라벨도 자산이다 — 객체에 붙은 label 을 먼저 쓴다 (2026-07-30 지적)

`rect`·`ellipse`·`line`·`circuit`·`optics` 는 **자체 `label`** 을 갖고 있다. 상자 옆 A·B·C 같은
이름표는 **반드시 그 상자의 라벨로 넣는다.** `formula` 를 따로 얹으면 사용자가 상자를 옮길 때
**라벨이 따라오지 않는다.** 실무에서 이게 제일 아프다.

> 실패: 10번에서 상자 6개 전부 `label:null` 로 두고 `formula` 16개를 따로 얹었다.
> 원인은 "`rect` 의 label 은 `m_B` 를 첨자로 못 바꾼다"(DRAWING_GUIDE 1장)를
> **"rect label 은 쓰지 말자"로 잘못 일반화**한 것이다.

**2026-07-30 해소**: 상자 라벨이 **안쪽·바깥 두 슬롯**이 되면서 이 실패의 원인 자체가 없어졌다.
안쪽은 물리량이면 **수식 렌더러를 타서 `m_B` 의 B 가 아래첨자로 나온다.** 그래서 이제
`formula` 를 얹을 이유가 없다 → `docs/BOX_LABEL_DUAL_SPEC.md`

| 원본 | 넣는 곳 |
|---|---|
| 상자 안 `m_B`·`3m` | `labelInner` + `labelInnerType:"quantity"` |
| 상자 밖 `A`·`B`·`C` | `labelOuter` + `labelOuterPos`(위/아래/왼쪽/오른쪽) |
| 실·용수철 옆 `실`·`S` | 그 `line`·`spring` 의 `label` + `labelShow:true` |
| `(가)`·`(나)`·`수평면` | 객체에 속하지 않는 **설명 글자** → `text` (11장) |

10번 재현본은 이 규칙으로 **객체 50개 → 36개**가 되었고, `formula` 는 `d` 하나만 남았다.

> **바깥 슬롯은 위·아래·왼쪽·오른쪽 4방향뿐이다.** 원본이 대각선(상자 오른쪽 **위**)이면
> 가장 가까운 한 방향을 고르고 그 선택을 기록한다. 10번 (나)의 `A` 가 그 경우다 —
> `above` 로 두면 실 위에 글자가 얹혀 9장을 어기므로 `right` 로 갔다.
> **원본과 다르게 둔 곳은 반드시 보고에 적는다.**

**규칙**: 글자를 놓기 전에 "이 글자의 주인 객체가 있는가?"를 묻는다.
있으면 그 객체의 `label`, 없을 때만 독립 `formula`/`text`.

**왜 중요한가**: 전용 타입은 평가원 관례에 맞게 이미 그려져 있고, 나중에 사용자가 앱에서
드래그로 고칠 수 있다. 손조립 도형은 객체 수만 늘고 수정이 어렵다.

**참고 창도 자산이다.** `기출문항 검색`(Ctrl+Shift+F) → `참고 창 열기` 로 원본을 옆에 띄울 수 있다.
문항별 메모도 붙는다(`js/reference-window.js`). 원본을 눈으로 대조할 때 쓴다.

## 2. 글꼴 — 평가원 조판을 흉내 낸다

노바 규칙: *"Latin point labels such as A, B, P, Q, R, S, T … should be upright, stable,
exam-print roman text rather than overly slanted italic"* — 5E 로 옮기면:

| 무엇 | 어떻게 | 예 |
|---|---|---|
| **점·물체·영역 이름표** | `formula` + `italic:false` + 명조 계열 | A, B, C, P, Q, R, S₁ |
| **물리량**(변하는 양) | `formula` 기본(이탤릭) | m_B, θ, d, v, λ |
| **한글 문장** | `text` (돋움) | 수평면, 실, 균일하고 강한 자기장 영역 |
| **로마숫자 영역** | `text` 의 `{roman1}`~`{roman12}` | I, II, III |

**㉠㉡㉢(한글 원문자)과 ⓐⓑⓒ(라틴 원문자)를 절대 섞지 않는다.** 노바 프롬프트가 마지막 줄에서
따로 경고할 만큼 자주 나는 실수다. 5E 에서는 `labeler` 가 ㉠㉡ 계열을 담당한다.

**크기**: 기출 원본의 영역 이름표는 대문자 높이 **4.6~5.0mm**. `formula fontSize:5` 는
실측 5.66mm 로 **너무 크다** → **4.2~4.3** 이 맞는다.

## 3. 음영과 채움 — 인쇄된 회색은 정보다

노바 규칙: *"If a math diagram contains intentionally printed shaded regions, preserve those
filled regions as meaningful information."*

- 원본의 회색 영역은 **경계와 농도를 그대로** 옮긴다. 그 회색은 매질·영역 구분이라는 뜻이다.
- **회색값은 감으로 넣지 말고 원본에서 잰다.** `np.median` 으로 영역 안을 찍어 본다.
  실측 예(2027-06 9번): 밝은 회색 **229**, 진한 회색 **203**, 배경 255.
- 5E 는 `fillLevel` 0(검정)~255(흰색). 원본에서 잰 값을 그대로 쓴다.
- 감으로 168 을 넣었다가 대조 점수가 0.25 까지 떨어진 적이 있다(203 으로 고쳐 0.58).

## 4. 반복 요소는 결정론적으로

노바 규칙: *"Never use random dot placement or random jitter."*

- 격자·점열·파면·입자는 **정확히 같은 간격**으로 놓는다. 눈대중으로 흩뿌리지 않는다.
- 간격은 원본에서 재서 **하나의 단위 u** 로 정하고, 모든 좌표를 u 의 정수배로 쓴다.
  실측 예(2027-06 6번): 격자 한 칸 = 45.8px = 7.78mm = **반파장**.
  파면 원의 반지름은 전부 u 의 정수배(마루=홀수배, 골=짝수배)였다.
- 이렇게 하면 P·Q·R 같은 점이 **파면의 교점에 정확히** 떨어진다 → 5장의 제약 검사와 직결된다.

## 5. 물리 제약이 최종 심판이다

점수도 눈도 못 잡는 오류를 이것이 잡는다. **그림마다 제약을 하나 이상 적어 두고 검산한다.**

| 그림 종류 | 검사할 제약 |
|---|---|
| 파동·간섭 | 진행 방향 ⊥ 파면 / 지정한 점이 두 파면의 **교점**에 있는가 |
| 반사 | 입사각 = 반사각. 수직 입사광이 θ 경사면에 반사되면 법선과 **2θ** |
| 굴절 | 밀→소에서 법선에서 멀어지는가. 임계각 표시가 법선 기준인가 |
| 역학 | 실의 장력 방향, 도르래 양쪽 실이 평행한가, 물체가 바닥에 닿아 있는가 |
| 용수철 | 늘어남/압축이 문항 조건과 같은 방향인가 |
| 전기·자기 | 전기력선이 +에서 나와 −로 들어가는가, 자기력선이 N→S 인가 |

**측정값부터 의심한다.** 9번에서 오염된 측정치(21°)로 검산했다가 "원본이 물리를 안 지킨다"는
틀린 결론을 냈다. 제대로 재니(32.1°) 원본은 2.6° 오차로 제약을 지키고 있었다.

## 7. 완성 기준 (실무 투입 가능선)

아래를 다 만족해야 "시험지에 넣을 수 있다"고 말한다. 하나라도 어기면 미완이라고 보고한다.

- [ ] 차이 이미지에 **빨강 덩어리가 없다**(빠뜨린 요소 없음)
- [ ] 파랑은 선 굵기·글꼴 차이에서 오는 얇은 테두리뿐이다 — **덩어리진 파랑은 실패다**
      (마스크 테두리, 중복 라벨 같은 잔해가 여기 걸린다)
- [ ] 물리 제약을 수치로 검산했고 기록에 남겼다
- [ ] 이름표는 정체, 물리량은 이탤릭, 한글은 돋움
- [ ] 임시 객체(마스크·테스트 도형)가 남아 있지 않다
- [ ] **전용 타입을 썼다** — 도르래·원기둥·용수철·진자 등을 기본 도형으로 조립하지 않았다
- [ ] **글자가 도형·채움 영역과 겹치지 않는다** (아래 9장)
- [ ] **글자는 주인 객체의 `label` 로 붙어 있다** (독립 formula 는 아래첨자가 필요할 때만)
- [ ] 문항별 **치수표**(각도·단위 길이·주요 좌표)를 남겼다 — 나중 수정이 이것 없이는 전면 재작업이 된다

## 9. 겹침 금지 (2026-07-30 지적)

**원본에 명확히 그렇게 인쇄된 것이 아니면, 글자는 무엇과도 겹치지 않는다.**

- 글자 ↔ 채움(회색) 영역, 글자 ↔ 선, 글자 ↔ 도형 테두리, 글자 ↔ 글자 — 전부 안 된다.
- 원본이 겹쳐 보여도 **그대로 베끼지 않는다.** 스캔 원본은 인쇄·해상도 사정으로 붙어 보이는 경우가 많다.
  실측 예(10번): 원본의 "수평면"은 y 405~439 로 바닥선(410)과 회색 띠(410~430)를 가로지른다.
  그래도 재현본에서는 **띠 밖으로 빼서** 글자가 온전히 읽히게 한다.
- 판단이 애매하면 **띠·도형 바깥**으로 뺀다. 읽히는 쪽이 항상 옳다.

`text` 의 흰 테두리(halo)에 기대지 않는다. halo 는 겹침을 가려 줄 뿐 없애 주지 않는다.

## 10. 선은 자산에 **접하게** 붙인다 (2026-07-30 지적)

도르래에 걸린 실, 물체에 붙는 줄·용수철은 **자산의 가장자리에 정확히 접해야 한다.**
좌표를 눈대중으로 넣으면 선이 도형 안으로 파고들거나 허공에 뜬다.

- 반지름 `r`, 중심 `(cx, cy)` 인 도르래에 걸린 **수직 실**의 x 좌표는 **정확히 `cx ± r`** 이다.
  (`cx ± (r - 0.35)` 처럼 어림하면 실이 테두리 안쪽에서 시작해 어색해진다.)
- 실의 위쪽 끝은 도르래 **중심 높이(cy)** 까지 올린다. 그래야 실이 도르래를 감고 도는 것처럼 보인다.
- 용수철·실이 상자에 닿는 지점은 상자 변의 **정확한 좌표**를 쓴다(상자 y + h 등).

**규칙**: 자산에 붙는 선의 좌표는 **자산의 x/y/w/h 에서 계산해서 넣는다.** 손으로 어림한 숫자를 넣지 않는다.

## 11. 캡션·설명 글자는 그림 요소와 떨어뜨린다 (2026-07-30 지적)

"수평면"·"균일하고 강한 자기장 영역" 같은 **설명 글자**는 회색 띠·선·도형과 **닿지도 않게** 둔다.
9장(겹침 금지)의 강화판이다 — 겹침뿐 아니라 **접촉·근접**도 피한다.

- `text` 의 앵커가 글자 상자의 어디인지(위/기준선) 확인하고 배치한다. 앵커를 착각하면
  "띠 아래로 내렸다"고 생각한 글자가 실제로는 띠에 걸친다(실제로 두 번 틀렸다).
- 배치 후 **반드시 `export_image` 로 확인한다.** 좌표만 보고 "떨어뜨렸다"고 판단하지 않는다.

### 앵커 착각을 없애는 방법 — `getBBox()` 로 실측한다 (2026-07-30 3회째)

세 번째로 같은 실수를 했다. 눈으로도 export 로도 "떨어뜨렸다"고 보였는데 실제 간격은 **0.04mm**였다.

**`text` 의 `y` 는 앵커일 뿐이고, 글자가 차지하는 실제 상단은 그보다 위다.**
실측(fontSize 5mm, halo 켜짐): **bbox 상단 = `y` − 0.86mm**. halo 테두리(`fontSize × 0.16`)의
절반이 위로 삐져나오는 몫이 여기 들어 있다. 그래서 "띠 밑 + 0.9mm" 는 사실상 **닿은 것**이었다.

절차 — 배치 후 브라우저에서 이걸 돌려 숫자로 확인한다. 통과선은 **1mm 이상**.

```js
// 회색 띠(fillLevel 205)와 모든 글자의 bbox 를 비교한다
const bands = objs.filter(o => o.type==='rect' && o.fillLevel===205)
                  .map(o => ({top:o.y, bottom:o.y+o.h}));
document.querySelectorAll('#scene [data-id]').forEach(g => {
  const bb = g.getBBox();   // halo 포함 실측
  // bb.y < band.bottom && bb.y+bb.height > band.top  → 닿았다
});
```

**규칙**: 글자와 띠의 간격은 `y` 값끼리 비교해서 판정하지 않는다. **bbox 로 재서 판정한다.**

### 글꼴 폭이 달라 원본 좌표를 그대로 쓰면 붙는다 (2026-07-31 지적)

우리 한글 글꼴은 평가원 조판보다 넓다. 17번 "마찰 구간 Ⅰ"은 원본 18.8mm 인데 재현본은
23.8mm 였다 — 원본의 x 를 그대로 넣으면 글자 끝이 띠 끝에 **0.1mm** 까지 붙는다.

**원본의 왼쪽 x 가 아니라, 부딪히는 쪽 끝(오른쪽 x)을 맞춘다.** 그리고 배치 후
가장 가까운 요소까지의 거리를 재서 확인한다(17번: 7.5mm, 18번 축 이름: 1.25mm).

### 마찰 구간은 면 **아래**로 들어간다 (2026-07-31 지적)

바닥의 마찰 구간이 바닥선 아래에 깔리듯, **경사면의 마찰 구간도 경사면 선 아래(안쪽)** 다.
면 위에 얹으면 물체가 지나갈 자리를 막는 그림이 된다.

실측(17번): 띠의 회색 픽셀은 모든 행에서 경사선의 **오른쪽**(= 면 안쪽)에 있고, 폭은
수직으로 10px 다. 즉 띠의 윗변이 곧 경사면 선이다.

**계산**: 수선의 발을 내리고 **안쪽 법선**으로 두께 절반만큼 민다(10장의 접선 규칙과 한 쌍).
붙었는지는 좌표로 검산한다 — 17번 재현본은 띠·상자 모두 경사면과 0.004mm 이내다.

## 12. 자산의 기하 제약을 먼저 계산한다 (2026-07-30 지적)

자산은 `x/y/w/h` 를 자기 공식으로 해석한다. **원하는 반지름·중심을 정한 뒤 공식을 역산**해야
하고, 역산이 안 되는 조합도 있다. 좌표를 넣어 보고 눈으로 맞추면 반드시 어긋난다.

실측 예 — `apparatus(pulley, ceiling)`:

```
r  = min(w/2, h × 0.40)
cx = x + w/2
cy = y + h − r          → 고정판(천장)에서 바퀴 위까지 = h − 2r ≥ 0.5r
```

10번 원본은 반지름 8mm 에 브래킷이 **1.4mm**뿐이다. 그런데 위 식으로는 r=8 일 때 브래킷이
**최소 4mm** 다 — 원본을 그대로 만들 수 없다. 이때 선택은 둘이다.

1. 반지름을 6.87mm 로 줄인다 → **바퀴 크기가 14% 틀린다**
2. 반지름 8mm 를 지키고, **고정판을 천장 회색 띠 안(-41.9)에 넣고 띠를 나중에 그려 덮는다**
   → 띠 아래로 나온 브래킷만 보이므로 결과가 원본과 같아진다

**2번을 택했다. 크기가 맞는 쪽이 옳다.** 자산 렌더러를 고치는 대신 **그리는 순서(z)로 푼다** —
띠·바닥처럼 넓은 채움은 뒤에 그려 덮개로 쓸 수 있다.

## 13. 회색 띠는 테두리를 채움과 같은 회색으로 둔다 (2026-07-30 지적)

원본의 천장·바닥 띠는 **한쪽 변에만 잉크 선이 있다.** 실측(10번): 천장 띠는 아래쪽 선만,
바닥 띠는 위쪽 선(바닥선)만 있고 **띠의 나머지 세 변에는 선이 없다.**

5E 도형은 채움과 테두리를 따로 끌 수 없으므로:

```
띠   : rect, fillLevel 205, strokeLevel 205   ← 테두리를 채움과 같은 회색으로 (선이 안 보인다)
바닥선: line, strokeLevel 0                    ← 잉크 선은 별개 객체로 딱 필요한 변에만
```

예전 재현본은 열린 `polyline` 로 3변만 그리는 편법을 썼는데, 원본에 없는 좌우 변 선이 남았다.
**"채움 도형 + 필요한 선" 두 객체로 나누는 쪽이 단순하고 정확하다.**

## 14. 자산 후보가 둘이면 둘 다 그려서 고른다 (2026-07-30 지적)

이름이 같은 자산이 두 타입에 있으면(도르래는 `optics` 와 `apparatus` 양쪽에 있다)
**설명을 읽고 고르지 말고 둘 다 그려서 원본과 대조한다.**

10번 실측:

| 후보 | 형태 | 대조 점수(F1) |
|---|---|---|
| `apparatus(pulley, ceiling)` | 회색 림 도넛 + 진회색 축 + 천장 브래킷 | **0.886** |
| `optics(pulley)` | 원 하나 + 가운데 점 | 0.848 |

원본에는 림·축·브래킷이 다 있으므로 눈으로도 `apparatus` 가 맞고, 점수도 같은 방향이었다.
**눈과 점수가 엇갈리면 눈을 믿는다**(점수의 한계는 DRAWING_GUIDE 4장).

### 자산은 '있는지'가 아니라 '어디까지 해 주는지'를 본다 (2026-07-31 지적)

자산을 썼다고 끝이 아니다. **그 자산이 대신해 주는 일을 손으로 다시 하고 있으면 안 쓴 것과 같다.**

| 손으로 그렸던 것 | 실제로는 자산이 해 준다 |
|---|---|
| 축 2개 + 화살촉 + 눈금 + 눈금 글자 + 원점 0 | `coordplane` (`tickLabelMode:"text"` 로 `t_0`·`8v_0` 같은 첨자 눈금까지) |
| 점 두 개에서 축으로 내리는 점선 | `coordplane.annGuides` (③표시 탭의 **수선의 발**) |
| 꺾은선 그래프 | 평면에 묶인 `funcgraph` + `curveStyle:"straight"` |
| 치수 화살표 + 그 옆 글자 | `line` 의 `lineMode:"lengthArrow"` + `dimensionLabel` |
| 상자 밖 질량 표기 | 상자의 **바깥 라벨**(`labelOuterType:"quantity"`) |

> **함정**: 좌표로 찍은 계열을 기본값(`smooth`)으로 두면 Catmull-Rom 이 꼭짓점을 둥글려
> **꺾은선이 S자 곡선이 된다.** `curveStyle:"straight"` 를 반드시 준다.

> **내장 기능의 제약은 그대로 받아들인다.** 18번 원본은 v₀ 가 8v₀ 의 1/8 자리에 있지 않다
> (손으로 그린 눈금). 좌표평면은 눈금이 균일해야 하므로 이건 재현할 수 없다 —
> **균일한 쪽이 옳으므로 그대로 두고 보고한다.**

### 이어진 면은 polyline **하나**다 (2026-07-31 지적)

기둥→경사→고원→내리막→바닥처럼 **한 붓으로 이어지는 면은 `line` 여러 개가 아니라
`polyline`(꺾은선) 하나로 그린다.**

- 17번 트랙은 이렇게 했는데(꼭짓점 6개 + 둥근 모서리), **18번 경사면은 `line` 두 개로
  따로 그려서 어겼다.** 같은 그림 안에서 원칙이 갈라진 실패 사례다.
- 왜 하나여야 하나: ① 꺾이는 점이 **정확히 한 점**이 된다(선 두 개는 끝점이 미세하게
  어긋나거나 겹친다) ② 사용자가 앱에서 면을 옮길 때 **한 번에 잡힌다** ③ 모서리를
  둥글릴 수 있다(`rounded` + `cornerRadius`) — 선 두 개로는 불가능하다.
- `line` 을 쓰는 것은 **정말로 독립인 선**뿐이다: 실, 벽, 기준선, 치수선.

### 반복 요소의 개수는 원본에서 센다

용수철 감은 수를 기본값(14)으로 두면 길이가 다른 두 용수철이 같은 바퀴 수로 그려져
짧은 쪽이 촘촘해진다. **원본에서 센다** — 나선은 한 바퀴에 중심선을 두 번 지나므로:

> 중심 x 열의 잉크 런 수 ÷ 2 = 감은 수. 10번 실측 (가) 16런 → 8바퀴, (나) 11런 → 6바퀴.
> 코일 폭 30px × 0.17 ≈ 5.1mm → `radius` 2.5.

4장(반복 요소는 결정론적으로)의 구체적 실행법이다.

## 15. 물체 기본형 — 사각형과 원 (2026-07-31 교사 결정)

물체를 나타내는 기본형은 **둘뿐이다: 사각형(블록)과 원(공·입자·점 물체).**
임의의 다각형·자유형으로 물체를 조립하지 않는다. 전용 자산(도르래·수레 등)이 있는
물체는 §1대로 자산이 우선이다.

- **블록** = `rect`. 비율은 상황에 따라:
  - **기출 재현** → **원본 실측 비율을 유지**한다 (기출 블록은 대개 1.16:1 직사각형이다.
    §0의 "상대 크기 원본 그대로"가 그대로 적용된다).
  - **새로 만드는 그림**(기출이 아닌 창작 도판) → **정사각형**을 기본으로 한다.
- **원** = `ellipse` 정원. 공·구슬·입자·점전하 같은 **둥근 물체** 전용이다.
  도르래는 원이 아니라 자산으로 그린다(§1·§14).

## 16. 면에 붙는 블록·띠는 스냅(접촉 계산)으로 (2026-07-31 교사 결정)

**적용 대상: 경사·바닥·천장에 닿는 블록과 마찰 띠.** (점·용수철 끝은 §10의 접선 규칙으로
충분하다 — 스냅 검산까지는 요구하지 않는다.)

- 앱에서 손으로 그릴 때는 **면 접촉 스냅 기능**으로 붙인다.
- 코드로 생성할 때는 스냅과 같은 계산을 한다: **면 위 수선의 발 → 법선 방향으로
  (두께 절반)만큼 이동**. 블록은 바깥쪽, 마찰 띠는 안쪽(§11 하위절).
- 회전각은 면의 경사각과 일치시킨다. **부호 주의**: 오른쪽으로 올라가는 면은 반시계(−),
  내려가는 면은 시계(+) — 18번에서 17번의 부호를 그대로 옮겨 써서 밑변이 면과
  반대로 기운 실측 사례가 있다(45° 마름모라 눈으로는 안 보였다).
- **배치 후 밑변–면 거리를 좌표로 검산한다.** 통과선은 0.01mm 이내.
  (17번 실측: 띠·블록 모두 0.004mm 이내 / 18번 수정 후 0.003mm 이내)

## 17. 선 표준 (2026-07-31 교사 확정)

### 굵기 — 두 값뿐이다

| 무엇 | 굵기 |
|---|---|
| 모든 선(도형·실·보조선·화살표) | **0.35mm** |
| 그래프 계열(funcgraph) | **0.4mm** |

원본에서 굵기를 재지 않는다. 이 두 값이 표준이다.

### 선의 명칭과 지정 (2026-07-31 개정 — 제도 표준 용어 도입)

기계제도 표준(**ISO 128 / KS B 0001**)의 선 분류를 우리 도판 용어로 쓴다.
"점선 두 개가 나왔다"가 아니라 **"가상선과 안내선"** 이라고 부를 수 있어야
분해(§19)·지시·수정이 정확해진다.

**실선 계열**

| 명칭 (제도 용어) | 뜻 | 예 | 지정 |
|---|---|---|---|
| **외형선** | 구조·물체의 보이는 윤곽 | 트랙·블록·벽 | 실선 0.35 |
| **강조 외형선** | 특별히 굵게 강조된 물체 | 15번 도선 고리, 그래프 계열 | 0.4 (계열) ~ 0.7 (도선 고리) |
| **치수선** | 길이를 재는 양끝 화살표 | 17번 H·4h·h | 내장 치수선(§14) |
| **지시선** | 요소를 가리키는 인출선 + 이름 | ㉠㉡ 콜아웃 | `labeler` |

**파선 계열** — 전부 "점선"이라 뭉뚱그리지 않는다

| 명칭 (제도 용어) | 뜻 | 예 | 지정 |
|---|---|---|---|
| **기준선** | 위치·높이의 기준을 나타내는 보조 직선 | 17번 r–s 레벨, 8번 연직선, 9번 법선 | 점선3 (1.0/0.3) |
| **가상선** (phantom) | **이동 후·가상 위치**의 물체 윤곽 | 17번 파선 블록, 8번 파선 공 | 파선 상자 (1.3/0.9) |
| **궤적선** | 운동 경로 | 8번 진자 호 | 점선3 |
| **숨은선** (hidden) | 보이지 않는 구조 | 6번 파면 골 | 점선2 (0.5/0.3) |
| **치수보조선** (extension) | 치수 화살표를 대상까지 연장하는 짧은 파선 | 17번 H 위·아래 파선, 10번 d 파선 | 점선3 |
| **경계선** (지도학) | 영역(자기장·매질)의 범위 파선 테두리 | 15번 영역 Ⅰ·Ⅱ 테두리 | 점선2 |
| **안내선** (수선의 발) | 그래프의 점→축 투영 파선 | 8·15·18번 (나) | **내장** `annGuides` |
| **제2계열 파선** | 그래프에서 둘째 계열 구분 | 15번 Ⅱ, 화학 b1-10 ㄴ | **내장** 그래프 선 종류 "파선" (1.9/0.9) |

- 실선/파선의 **의미**(§0)가 먼저고, 위 표는 그 의미별 명칭과 규격이다.
- 표에 없는 용도를 만나면 가장 가까운 분류를 쓰고 보고에 적는다.
- 제도 표준의 1점쇄선(중심선)·2점쇄선은 기출 물리 도판에 거의 안 나온다 —
  나오면 그때 행을 추가한다.

### 움직임 화살표 — 표준으로 통일, 실측하지 않는다

- **길이 5mm · 굵기 0.35 · `lineMode:"arrow"`**. 원본에서는 **위치와 방향만** 읽는다.
- 짧은 지시 화살표(d·h₀ 표기의 바깥→안 화살표 쌍)는 **길이 3mm**.
- 길이 표시는 여전히 내장 치수선(§14 표)이다 — 이 절은 '움직임' 화살표 이야기다.

## 18. 실측은 판단이 걸린 곳만 — 빠르게 그린다 (2026-07-31 교사 지시)

**모든 것을 실측하지 않는다.** 실측은 토큰과 시간을 먹는다. 판단이 필요 없는 지점은
대략 보고 빠르게 넘어간다.

**정밀하게 재는 것 (여기만):**
1. **접촉·접선이 걸린 구조** — 경사각, 면의 직선식, 도르래 중심·반지름 (§10·§16 검산에 필요)
2. **회색값** (§3 — 감으로 넣으면 크게 틀린다)
3. **반복 단위** — 격자 한 칸, 코일 감은 수 (§4)

**대략 보고 넘어가는 것:**
- **아트보드** — 원본 종횡비를 눈으로 보고 어림 잡는다 (한 패널 ≈ 90×60, 두 패널 ≈ 150×50~60)
- **글자 위치** — 원본에서 어느 요소 옆인지만 보고 놓는다. bbox 검산(§11)은
  **띠·선에 가까운 글자만** 한다
- **화살표** — 위치·방향만 (§17)
- **선 굵기** — 표준값 (§17)
- **전체 배율** — 주요 요소 하나(블록 폭 등)로 대충 잡고 나머지는 상대 배치

**검증도 가볍게:** 중간 반복은 `export_image` 눈 확인으로 충분하다.
`compare-exam-figure.py` 대조는 **완성 직전 1회**만 돌린다(§6 절차의 5번을 마지막으로 미룬다).

## 19. 그림 분해 — 이름 붙여 읽는다 (2026-07-31 교사 지시)

원본을 "선과 글자 무더기"로 보지 않는다. **정해진 층 순서로 파편화하고, 조각마다
§17의 명칭을 붙인다.** 이름이 붙어야 지시("가상선만 고쳐라")와 수정이 정확해진다.

읽는 순서 = 그리는 순서 = z순서다:

| 층 | 무엇 | 조각의 명칭 | 5E 구현 |
|---|---|---|---|
| ① **골격** | 지면·벽·트랙·경사 | 외형선 | `polyline` 하나(§14) + 독립 `line` |
| ② **영역** | 회색 채움과 그 범위 | 채움 + 경계선 | `rect`(§13) — 경계 파선이 있으면 점선2 |
| ③ **물체** | 블록·공·자산 | 외형선 / 강조 외형선 | `rect`·`ellipse`(§15)·자산(§1) |
| ④ **연결** | 실·용수철·도선 | 외형선 | `line`·`spring` — 접선 규칙(§10) |
| ⑤ **보조** | 기준선·가상선·궤적선·숨은선 | §17 파선 계열 | 각 지정값 |
| ⑥ **주석** | 치수·라벨·움직임 화살표·캡션 | 치수선·치수보조선·지시선 | 내장 치수선·객체 라벨·`text` |

- 분해가 끝나면 **조각 목록이 곧 체크리스트**다: 층마다 "원본에 있는 조각을 다 넣었나"만 본다.
- 실측(§18)도 이 분해를 따른다: 정밀 측정은 ①·④의 접촉 구조와 ②의 회색값뿐이다.
- 실전 예 (15번): ① 없음(축이 골격을 겸함) ② 영역 Ⅰ·Ⅱ + 경계선 ③ 도선 고리(강조 외형선)·점 p
  ④ 없음 ⑤ 안내선(수선의 발) ⑥ 문자 눈금·로마숫자·캡션.

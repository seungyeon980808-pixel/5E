# Windows 프로젝트 저장·열기 개발 반영 (2026-09-18)

Windows x64용 프로젝트 실행 파일 저장과 설치 앱 우선/웹 대체 경로를 소스에 추가했다. macOS의 승인된 파란 아이콘과 원본 프로젝트 형식을 공유한다. 커밋·프리뷰 배포·설치본 생성/교체는 하지 않았다.

## 동작과 범위

- Windows 웹 및 데스크톱의 프로젝트 저장은 원본 UTF-8 프로젝트 데이터와 약 88.6KB 실행기를 담은 `.exe`다. 편집기 전체나 별도 런타임을 파일마다 넣지 않는다. 선택한 파란 접힌 문서의 16/32/48/256px ICO를 실행 파일에 포함했다. 아이콘의 `.5e`는 브랜드 글자이며 실제 확장자는 `.exe`다.
- 실행기는 자신의 데이터 크기와 SHA-256을 확인한다. 업데이트된 설치 앱의 `Software\5E\ProjectLauncher` 등록(Version=1, 실행 파일 경로)이 있으면 그 앱에 `--project-file`로 전달한다. 사용자/컴퓨터 설치 모두 같은 64비트 레지스트리 뷰를 사용한다. 지원 표시가 없는 구버전은 웹 경로를 사용한다.
- 등록은 기존 NSIS 설치 단계에 추가했다. 제거할 때 현재 설치 경로와 일치하는 등록만 지운다. 실제 NSIS 컴파일과 설치는 이 Mac에서 검증하지 못했다. 캐시된 컴파일러 실행은 `bad CPU type`으로 실패했으며 설치본을 새로 만들지 않았다.
- 설치 앱이 없으면 원본 JSON만 웹 수신 API로 POST하고, 확인한 편집기 주소를 기본 브라우저로 연다. 쿠키·AI 인증·세션은 보내지 않는다. 웹 연결 실패 시 오류를 표시하고 원본 실행 파일은 보존한다. 원본은 공유 링크의 만료와 관계없이 파일 안에 남는다.
- 설치 앱 전달에는 시스템 임시 폴더에 원본 복사본과 소유권 확인 파일을 만든다. 실제 수신 코드가 읽어 메모리에 보관한 뒤 확인 파일/원본 해시/정규 임시 경로가 맞는 복사본만 삭제한다. 일반 사용자 파일과 원래 `.exe`는 삭제하지 않는다.
- 파일 → 프로젝트 열기 및 드롭으로 `.exe`를 불러올 때 실행하지 않는다. 내부 데이터만 검증해서 기존 프로젝트 읽기와 렌더링을 사용한다. 손상된 파일을 열어도 현재 작업은 보존한다. 일반 `.5e`/`.json` 불러오기도 유지한다.
- 기존 실행형 프로젝트를 덮어 저장하면 이전 파일을 `.previous-시각`으로 보존한다. 관련 없는 실행 파일·폴더·심볼릭 링크는 덮어쓸 수 없다.
- 개발 데스크톱에서 저장한 파일은 해당 개발 실행기와 프로필을 사용한다. 다른 컴퓨터에 전달하는 배포 파일이 아니다. API가 없는 정적 웹은 기존 `.5e` 저장을 유지한다.

## 직접 확인한 내용 (경량화 후)

- Windows GUI x64 PE 실행기 빌드 성공: **88,576바이트**. 이전 Go 실행기 7,174,656바이트 대비 **98.77% 감소**다. 아이콘을 제외한 수치가 아니라 16/32/48/256px PNG 리소스를 모두 포함한 실제 실행 파일 크기다.
- 실행기를 C와 Windows 기본 WinHTTP/BCrypt/프로세스·레지스트리 API로 교체했다. Zig 0.15.2로 빌드하며 런타임을 따로 설치하지 않는다. cJSON v1.7.19 원본과 배포 라이선스를 포함한다. 설치 앱 우선/웹 대체, 원본 해시, 인증 정보 없는 전송, 임시 복사본 정리 규약은 유지한다.
- 변경 범위 Node 테스트 **16개 통과**, Windows 운영체제가 필요한 네이티브 API 테스트 **4개는 건너뜀**. 작은 파일의 실행기 포함 추가 용량이 512KiB 미만이어야 통과하는 검사도 포함한다.
- 동일한 C 원본 읽기·URL 검사·인수 따옴표 함수를 macOS에서 직접 컴파일해 UBSan으로 실행했다. 실제 저장 파일의 한국어/내장 이미지 원본 일치, 손상/과대/잘린 데이터 거부, 인증서 위치·패딩, 다른 원점/자격 증명 거부, Unicode/따옴표/끝 역슬래시 처리 6개 테스트를 통과했다. Windows 전용 실제 WinHTTP·레지스트리·프로세스 어댑터는 테스트 코드를 마련하고 크로스 컴파일했지만 실행하지 못했다.
- C 코드의 경고를 오류로 처리한 빌드 통과. 공유 코어/인수 및 Windows 공통·전달·전송·진입점에 대한 Clang 정적 분석 진단 0건. ASLR/NX PE 플래그와 동일한 아이콘 리소스 바이트를 확인했다.
- 이전 Go 파서는 새 PE에서 동일한 프로젝트 데이터를 읽는 상호운용 검증용으로 남겨 두었다. 기존 공통 Go 테스트 7개도 통과했다. 이것을 새 C 실행기의 Windows 실기기 검증으로 주장하지 않는다.
- 분리 Chromium에서 Windows 플랫폼 선택으로 실제 메뉴 저장을 실행했다. `5E 프로젝트.exe`(**205,643바이트**, 한국어·이미지 포함 원본 약 112KB)를 받고 새 편집기에 불러와 두 페이지와 객체 수 3/1, 텍스트·사각형·내장 이미지가 복원됐다. 손상 파일은 거부하고 현재 문서를 보존했다. 페이지 오류는 0건이다. 호스트는 macOS이며 운영체제 선택만 Windows로 설정했다.
- 지정된 `scripts/start-library-repair-dev.command`로 실제 개발 앱을 재시작하고 별도 테스트 프로필에서 같은 `.exe`의 데이터 불러오기를 확인했다. 두 페이지/객체 3·1 복원, 페이지 오류 0건, 기존 PDF 자료 검색 항목 1,312개/‘생명’ 결과 38개를 확인했다. 기존 사용자 개발 프로필과 PDF 자료 경로는 유지했다. 테스트 앱만 종료했다.
- 서버는 저장할 때 실행기 파일을 새로 읽으므로 로컬 개발 서버 19624에서 새 실행기를 사용한다. Windows 수동 검증 워크플로도 새 C 코드용으로 바꿨지만 원격 실행/푸시는 하지 않았다.

## 사용자 확인과 합격 기준

실제 Windows 10/11 x64 PC가 이 환경에 없어 아래 운영체제 검증은 남아 있다. 설치 지원은 업데이트된 설치본의 등록이 있어야 동작한다. 현재 설치된 구버전에 소스 변경만으로 등록이 생기지는 않는다.

1. **Windows에서 개발 서버 실행:** 소스와 실행기 파일이 있는 Windows PC에서 `node experiments/web-codex-auth/sharing-dev.cjs 19624`를 실행한 뒤 그 PC의 `http://127.0.0.1:19624/`에 접속한다. 도해와 이미지를 넣고 파일 → 프로젝트 저장을 누른다. 정상은 파란 아이콘의 `.exe` 저장이다.
2. **설치 앱 없음:** 저장한 파일을 탐색기에서 더블클릭한다. 서버가 실행 중이고 네트워크 연결이 있는 상태에서 기본 브라우저에 원래 페이지·텍스트·이미지가 모두 복원되면 합격이다.
3. **업데이트된 설치 앱 있음:** 배포 확인 단계에서 설치 등록을 완료한 후, 앱 종료/실행 상태에서 각각 더블클릭한다. 브라우저 대신 설치 앱에 원본이 복원되면 합격이다. 미저장 작업이 있으면 취소 시 현재 작업 보존, 열기 시 저장한 원본 복원도 확인한다.
4. **파일 자체 보존:** 같은 `.exe`를 파일 → 프로젝트 열기로 읽어도 동일하게 복원돼야 한다. 앱 전달 후 원래 실행 파일은 남고, 수신한 임시 복사본만 없어져야 한다.

현재 Mac 개발 서버의 `127.0.0.1` 주소가 들어간 파일을 다른 Windows PC로 보내면 그 주소는 Windows PC 자신을 가리킨다. 그대로 보내는 파일의 다른 컴퓨터 사용이 검증된 상태는 아니다. 위처럼 Windows PC 자체의 개발 서버에서 저장하거나, 공개 웹 패키지/수신 API를 배포한 뒤 그 주소로 생성해야 한다.

## 배포 전 남은 일

실제 탐색기 아이콘과 더블클릭, 등록된 설치 앱의 cold/warm 수신, NSIS 컴파일·설치 등록, Windows 브라우저의 실행 파일 다운로드 정책을 확인해야 한다. 개별 생성 프로젝트 실행 파일의 Authenticode 서명 및 인터넷 다운로드 후 SmartScreen 확인도 남아 있다. 현재 결과는 서명되지 않은 개발 파일이며 경고 없이 열리는 배포 파일로 검증되지 않았다. 서명 후에도 원본을 읽을 수 있도록 인증서 테이블과 정렬 패딩 위치 처리는 구현/형식 테스트했지만 실제 인증서 서명 검증은 아니다. 공개 웹 API도 아직 배포하지 않았다.

기존 다른 기능의 전체 테스트는 이 변경의 합격 근거로 사용하지 않는다. 이전 검토에서 전체 테스트 래퍼가 의도보다 넓게 실행되어 관련 없는 기존 실패가 발견됐고, 이번 검증은 변경 범위의 직접 테스트만 실행했다.

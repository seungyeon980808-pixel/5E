# PDF 자료 라이브러리·웹 체험판·설치형 통합 기획

> 상태: 핵심 자료팩·공통 PDF.js 런타임·검색 UI 구현 및 검증, 프로덕션 자료 URL 배포 전  
> 작성 기준: 2026-09-10 · 5E v1.5.3  
> 관련 구현: 5E 기출 이미지 라이브러리, 이미지 작업대, 웹 AI 실험, ExamPool PDF 검색

## 1. 제품 결정

5E는 하나의 편집기 코드를 웹앱과 설치형에서 함께 사용한다.

- **웹앱**은 설치 없이 최근 3년 기출을 검색하고, 필요한 도판을 캔버스에 넣거나 AI로 변환해 보는 체험 경로다.
- **설치형**은 같은 기능에 사용자의 기출·교과서 폴더 연결, 영구 색인, 폴더 일괄 작업을 더한 장시간 작업 경로다.
- 기출과 교과서의 기준 자료는 미리 잘라 둔 PNG가 아니라 **원본 PDF**다.
- PNG는 검색 카드 썸네일, 확대 미리보기, 캔버스 삽입, AI 입력이 필요한 순간에만 만든다.
- 자료는 앱 저장소와 분리된 **자료팩** 또는 사용자가 연결한 로컬 폴더로 관리한다.

제품 안내의 핵심 문장은 다음과 같다.

> 웹에서 최근 기출을 바로 검색하고 이미지 변환을 체험해 보세요. 마음에 들면 설치형에서 가지고 있는 기출과 교과서 폴더 전체를 연결해 사용할 수 있습니다.

## 2. 해결하려는 문제

현재 기출 라이브러리는 수천 개의 PNG와 매니페스트를 저장소에 포함한다. 이 방식은 다음 문제를 만든다.

- 같은 원본 PDF에서 나온 이미지가 별도 파일로 계속 누적된다.
- 저장소, Git 기록, GitHub Pages 게시물의 크기가 함께 커진다.
- 미리 잘라 두지 않은 문항과 자료는 검색하거나 사용할 수 없다.
- 원본의 출처, 페이지, 문항과 크롭 이미지의 관계를 별도로 관리해야 한다.
- 새 연도 자료를 추가할 때 앱 배포와 자료 배포가 결합된다.

새 구조에서는 PDF와 검색 색인이 자료 계층을 맡고, 5E는 검색 결과를 편집과 변환 작업으로 연결한다.

## 3. 사용자 경험

### 3.1 공통 흐름

```text
자료 검색
  → 자동 크롭 카드 확인
  → Space로 고해상도 확대
  → 캔버스에 넣기 / AI로 변환 / 범위 조정
  → 결과 편집·저장
```

사용자에게 PDF 페이지 탐색과 화면 캡처를 요구하지 않는다. PDF는 내부 원본이고, 기본 검색 결과의 단위는 자동으로 찾은 **문항 또는 도판 후보**다.

### 3.2 검색 결과 카드

각 카드는 다음 정보를 가진다.

- 자동 크롭한 저해상도 썸네일
- 과목, 학년도, 시행 구분, 문항 번호
- 검색어가 포함된 짧은 문장
- 원본 PDF 이름과 페이지
- 도판이 여러 개인 경우 도판 순번

카드를 한 번 클릭하면 선택 상태가 된다. 선택 상태는 키보드 포커스와 시각적 테두리로 함께 표시한다.

### 3.3 Space 확대 미리보기

- 입력란 밖에서 선택된 카드에 `Space`를 누르면 고해상도 미리보기를 연다.
- `Space`를 다시 누르거나 `Esc`를 누르면 닫는다.
- 확대 중 `←`와 `→`로 이전·다음 검색 결과를 본다.
- 검색창, 메모, AI 요청문 등 입력란에서는 `Space`가 정상적인 띄어쓰기로 동작한다.
- 확대 화면에서도 `캔버스에 넣기`, `AI로 변환`, `범위 조정`을 실행할 수 있다.
- 카드는 작은 썸네일을 먼저 보여주고, 확대할 때만 PDF에서 고해상도로 렌더링한다.

### 3.4 자르기

기본 동작은 자동 자르기다.

1. 문항 번호와 문항 경계를 찾는다.
2. 문항 안의 그림·그래프·표 후보를 찾는다.
3. 후보가 하나면 해당 영역을 기본 선택한다.
4. 후보가 여러 개면 각각을 검색 결과의 하위 카드로 제공한다.
5. 자동 경계가 맞지 않을 때만 `범위 조정`에서 사각형을 드래그한다.

크롭에는 글자나 선이 잘리지 않도록 작은 안전 여백을 둔다. 사용자가 조정한 범위는 같은 원본·페이지·문항에 다시 접근할 때 재사용할 수 있다.

### 3.5 선택 후 동작

| 동작 | 결과 |
|---|---|
| 캔버스에 넣기 | 선택 영역을 고해상도 이미지 객체로 현재 페이지에 삽입 |
| AI로 변환 | 선택 영역을 새 이미지 작업으로 만들고 변환 대기열에 추가 |
| 범위 조정 | 원본 페이지 위에서 크롭 영역을 수정한 뒤 앞의 두 동작 실행 |
| 원문 보기 | 원본 페이지와 검색어 위치를 함께 표시 |

AI 변환은 기존 복잡도와 출력 방식 선택을 그대로 사용한다. 검색 화면이 별도의 변환 규칙을 만들지 않는다.

## 4. 웹앱과 설치형의 범위

| 기능 | 웹앱 | 설치형 |
|---|---|---|
| 최근 3년 기출 검색 | 제공 | 제공 |
| 검색 카드·Space 확대 | 제공 | 제공 |
| 자동 크롭·범위 조정 | 제공 | 제공 |
| 캔버스 삽입 | 제공 | 제공 |
| AI 변환 | 원격 서버 사용 | 로컬 실행 경로 우선 |
| 개인 PDF 몇 개 열기 | 선택 파일 범위에서 제공 | 제공 |
| 폴더와 하위 폴더 영구 연결 | 제한적 | 제공 |
| 교과서·기출 전체 로컬 색인 | 제공하지 않음 | 제공 |
| 폴더 일괄 변환 | 제공하지 않음 | 후속 제공 |

웹앱의 목적은 핵심 가치를 설치 없이 경험하게 하는 것이다. 브라우저 폴더 권한과 저장공간을 장기 보존 수단으로 전제하지 않는다.

설치형은 색인, 원본, 프로젝트, 변환 결과를 사용자 컴퓨터에 유지한다. 사용자가 AI 변환을 실행한 경우에만 선택한 크롭과 요청 정보가 AI 처리 경로로 전달된다.

## 5. 자료 구조

### 5.1 자료팩

자료팩은 앱 버전과 독립적으로 추가·업데이트·삭제한다.

```text
pack/
├── pack.json              자료팩 ID·버전·종류·지원 앱 버전
├── catalog.json           문서·페이지·문항·도판 위치와 검색 메타데이터
├── search-index.json      웹용 사전 생성 검색 색인
├── documents/             원본 PDF 또는 원격 PDF 목록
└── checksums.json         파일 무결성 값
```

`pack.json`의 최소 정보는 다음과 같다.

- `id`, `version`, `title`
- `kind`: 기출, 교과서, 교육과정, 사용자 자료
- 과목과 학년도 범위
- 문서 수와 페이지 수
- PDF와 색인 파일의 위치
- 생성 시각과 체크섬
- 호환 가능한 최소 5E 버전

최근 3년 기출은 웹 기본 자료팩으로 제공하되 앱 저장소에는 넣지 않는다. 초기 배포 후보는 GitHub Releases이며, 실제 연결 전 HTTPS, 교차 출처 요청, 메타데이터 우선 로딩, 선택한 PDF의 전체 다운로드·체크섬 검증, 최대 256MiB 제한, `%PDF` 파일 서명 검증, 캐시 동작을 검증한다. 검색이나 앱 시작 시 전체 corpus를 내려받지 않는다. 요구 조건을 만족하지 않으면 같은 자료팩 구조를 유지한 채 파일 저장소만 바꾼다.

### 5.2 설치형 로컬 자료

설치형은 사용자가 선택한 폴더를 하위 폴더까지 재귀 탐색한다. 원본을 앱 내부로 복사하지 않고 다음 정보만 로컬 DB에 저장한다.

- 자료팩 또는 연결 폴더 ID
- 파일의 절대 경로와 표시용 상대 경로
- 파일 크기, 수정 시각, 선택적 해시
- 문서 종류와 과목
- 페이지별 검색 텍스트
- 문항·도판 경계 좌표
- 마지막 색인 시각과 상태

재색인할 때 새 파일은 추가하고, 변경 파일은 갱신하고, 사라진 파일의 색인과 캐시는 제거한다. 연결 해제는 원본 파일을 삭제하지 않는다.

### 5.3 캐시

- 저해상도 카드 썸네일은 필요할 때 만들고 캐시한다.
- 고해상도 크롭은 캔버스 삽입이나 AI 변환 시 만들고 재사용한다.
- 웹 캐시는 브라우저가 정리할 수 있으므로 언제든 원본 PDF에서 복구 가능해야 한다.
- 설치형 캐시는 앱 데이터 폴더에 두고 사용자가 `캐시 비우기`를 실행할 수 있게 한다.
- 검색 색인과 사용자가 조정한 크롭 좌표는 이미지 캐시와 분리한다.

## 6. 검색·렌더링 구조

### 6.1 설치형

ExamPool의 다음 구현을 재사용한다.

- PyMuPDF 기반 폴더 재귀 탐색과 페이지 텍스트 추출
- SQLite FTS5와 `bm25()` 관련도 정렬
- 페이지 렌더링과 검색어 좌표 표시
- 문항 번호와 문항 경계 탐지
- 문항 단위 PNG 렌더링
- 열린 PDF와 렌더링 결과의 제한된 캐시

ExamPool에 기록된 기존 실측은 606페이지 최초 색인 7.9초, 검색 2ms 이하다. 이 수치는 참고 기준이며 5E 제품 성능은 실제 대상 자료와 설치 패키지에서 다시 측정한다.

텍스트 층이 없는 스캔 PDF는 현재 검색 색인에서 건너뛴다. 설치형의 로컬 OCR을 색인 경로에 연결해 검색 가능하게 하고, OCR 사용 여부와 진행률을 사용자에게 표시한다.

### 6.2 웹앱

웹 기본 자료는 배포 전에 텍스트, 문항 경계, 도판 후보를 색인한다. 브라우저는 다음만 수행한다.

1. 작은 자료팩 매니페스트와 검색 색인을 가져온다.
2. Web Worker에서 검색해 화면 멈춤을 막는다.
3. 사용자가 연 선택 문서만 최대 256MiB의 전체 PDF로 지연 다운로드하고, 자료팩 체크섬과 `%PDF` 파일 서명으로 검증한다.
4. PDF.js로 필요한 페이지의 썸네일 또는 고해상도 크롭을 렌더링한다.

웹 검색은 ExamPool의 결과 형식을 따르되, 최근 3년 범위에는 순수 JavaScript 검색을 사용한다. 기존 DocFinder의 BM25 로직을 이식 대상으로 우선 검토하며 새 검색 서버를 만들지 않는다.

### 6.3 공통 경계

검색 화면은 데이터 출처를 알 필요가 없도록 공통 결과 형식을 사용한다.

```json
{
  "sourceId": "2026-csat-physics1",
  "page": 3,
  "itemNumber": 5,
  "title": "2026학년도 수능 물리학Ⅰ 5번",
  "snippet": "...전자기 유도...",
  "crop": { "x": 0.12, "y": 0.28, "w": 0.72, "h": 0.31 },
  "cropKind": "figure",
  "score": 0.92
}
```

좌표는 PDF 페이지 너비와 높이에 대한 0~1 비율로 저장해 렌더링 해상도와 무관하게 사용한다.

## 7. AI 작업과 동시 처리

- 브라우저 한 세션에서 최대 10개 크롭을 한 번에 작업으로 추가할 수 있다.
- 각 작업은 원본 위치, 크롭 좌표, 복잡도, 출력 방식, 결과, 오류를 독립적으로 가진다.
- 설치형은 로컬 실행 환경이 감당하는 범위에서 최대 10개를 병렬 처리한다.
- 웹 서버는 세션당 접수 한도와 서버 전체 실행 한도를 분리한다.
- 서버가 즉시 실행하지 못하는 작업은 품질을 낮추지 않고 대기열에 둔다.
- 여러 사용자가 접속해도 결과 품질은 같고, 부하에 따라 대기 시간만 늘어날 수 있다.
- 현재 웹 실험의 목표는 동시 세션 5개다. `5세션 × 10작업`을 항상 50개 프로세스로 즉시 실행한다는 뜻은 아니다. 배포 환경의 메모리를 기준으로 전체 실행 슬롯과 사용자 간 공정 대기열을 정한다.

운영 배포 전에는 한 사용자 10개 병렬, 다섯 사용자 동시 접수, 세션 종료 후 자원 회수, 실패 작업 재시도를 실제 서버에서 각각 검증한다.

## 8. 저장소와 배포 전환

현재 작업 폴더에서 이미지 자료는 약 409MB이며 기출 라이브러리는 약 294MB, 부품 라이브러리는 약 131MB다. PDF 자료팩 경로가 제품에서 동작하기 전에는 기존 파일을 제거하지 않는다.

전환 순서는 다음과 같다.

1. PDF 자료팩 생성기를 만들고 최근 3년 자료팩을 생성한다.
2. 웹 검색·크롭·캔버스 삽입·AI 변환을 실제 자료로 검증한다.
3. 설치형에서 사용자 폴더 연결과 재색인을 검증한다.
4. 기존 PNG 라이브러리와 결과를 비교해 필요한 예외 자료를 선별한다.
5. 현재 브랜치에서 대체된 PNG와 생성 산출물을 제거한다.
6. GitHub Pages 게시물과 설치 패키지가 자료팩 없이도 정상 실행되는지 확인한다.
7. 별도 백업과 명시적 실행 결정 후 과거 Git 기록에서 대형 이미지 경로를 제거한다.
8. 새 복제본으로 저장소 실제 크기와 배포를 확인한다.

최신 커밋에서 파일을 삭제하면 게시 크기는 줄지만 과거 Git 기록은 남는다. 실제 복제 크기를 줄이려면 `git-filter-repo` 같은 기록 재작성과 원격 강제 갱신이 필요하다. 이 작업은 커밋 ID와 기존 복제본에 영향을 주므로 기능 전환과 분리해 수행한다.

웹앱은 당분간 GitHub Pages를 유지한다. 설치 파일과 초기 자료팩 후보는 GitHub Releases를 사용한다. 서비스가 상업화되거나 Pages 용량·트래픽·운영 기능이 부족해지면 사용자 주소를 유지한 채 정적 호스팅만 교체할 수 있도록 독립 도메인과 외부 자료 URL을 설정으로 분리한다.

## 9. 구현 단계

- 검색 Web Worker와 지연 PDF 로딩 연결
- 카드 선택과 Space 확대 구현

**완료 조건:** 새 브라우저에서 설치 없이 단어 검색 후 원하는 문항을 확대해 볼 수 있다.

### 단계 3 · 크롭에서 편집으로 연결

- 자동 크롭과 범위 조정
- 고해상도 캔버스 삽입
- AI 작업 생성과 10개 선택 추가
- 원본·크롭·결과 출처 보존

**완료 조건:** 검색부터 캔버스 삽입 또는 AI 변환 시작까지 PDF 파일을 직접 열지 않고 끝난다.

### 단계 4 · 설치형 로컬 폴더

- ExamPool 색인 모듈을 설치형 런타임에 연결
- 폴더 선택, 진행률, 중단, 증분 재색인 구현
- 삭제된 파일의 오래된 색인 자동 정리
- 스캔 PDF OCR 색인 연결

**완료 조건:** 앱을 다시 실행해도 연결 폴더와 색인이 유지되고, 추가·수정·삭제된 파일만 반영된다.

### 단계 5 · 자료팩 관리와 저장소 경량화

- 자료팩 설치·업데이트·비활성화·삭제 화면

- 게시물과 설치 패키지 크기 측정
- 기능 검증 후 Git 기록 정리

**완료 조건:** 앱 코드 저장소에 전체 기출 PNG가 없어도 웹과 설치형의 핵심 흐름이 동작한다.

### 단계 6 · 다중 사용자 운영 검증

- 한 세션 10개 작업 실제 실행
- 다섯 세션 동시 접수와 공정 대기열
- 서버 전체 슬롯, 메모리, 실패 복구 측정

**완료 조건:** 부하가 늘 때 작업이 유실되거나 품질이 바뀌지 않고, 대기 시간만 명확히 표시된다.

## 10. 검증 기준

기능 기준:

- 최근 3년 자료에서 과목·학년도·시행·단어로 검색할 수 있다.
- 검색 결과 카드가 자동 크롭 썸네일로 보인다.
- 선택 카드에서 Space 확대, Space/Esc 닫기, 좌우 이동이 동작한다.
- 입력란에서 Space 단축키가 가로채지지 않는다.
- 자동 크롭이 실패해도 범위 조정으로 작업을 완료할 수 있다.
- 크롭을 캔버스 이미지와 AI 작업 중 원하는 경로로 보낼 수 있다.
- 10개 결과를 선택해 독립 작업으로 추가할 수 있다.
- 자료팩과 로컬 파일을 제거하면 관련 색인과 캐시가 남지 않는다.
- 원본 PDF와 사용자가 연결한 폴더는 앱이 삭제하지 않는다.

성능 목표는 고정 보장이 아니라 실제 QA의 합격 기준으로 사용한다.

| 장면 | 초기 목표 |
|---|---:|
| 웹 기본 자료 검색 응답 | 일반 교사 노트북에서 300ms 이내 |
| 설치형 색인 완료 후 검색 응답 | 200ms 이내 |
| 캐시된 카드의 Space 확대 시작 | 100ms 이내 |
| 선택한 크롭을 캔버스에 넣는 조작 | 검색 후 2회 이내 |

검색·렌더링·AI 변환 시간은 따로 측정한다. AI 처리 시간이 길어져도 검색과 캔버스 편집이 멈추지 않아야 한다.

## 12. 범위 밖

이번 기획은 다음 기능을 포함하지 않는다.

- PDF 자체의 본문을 편집하는 기능
- 사용자의 전체 교과서 폴더를 원격 서버에 업로드하는 기능
- 모든 PDF 페이지를 PNG로 미리 생성해 저장하는 기능
- 웹 브라우저 저장공간을 영구 백업으로 간주하는 기능
- 서버가 바쁠 때 AI 결과 품질을 낮추는 기능
- 자동 크롭 실패를 숨기고 잘못된 범위를 그대로 확정하는 기능

## 13. 기존 명세와의 관계

- `EXAM_LIBRARY_SPEC_20260706.md`의 PNG 파일명 중심 계약은 전환 완료 전까지 유지한다. 이후 이 문서의 PDF·자료팩 계약이 상위 기준이 된다.

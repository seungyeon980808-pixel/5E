# 모바일 캔버스 재기획 · 2026-09-19

상태: 확인·기획·별도 시안. 이 문서는 제품 수정 승인이 아니다. 기존 모바일 구현은 유지하며, 승인된 화면 계약을 구현하기 전까지 아래 사항은 제안이다. 시안은 저장소 밖 `~/.codex/visualizations/2026/09/18/01a0b47a-3437-7c81-bdef-0cc8a8bdc439/mobile-canvas-0919/`에 분리했다.

## 결론

현재 구현은 모바일 AI 작업창이며, 요청한 모바일 편집기가 아니다. 캔버스에 그림을 올리고 라이브러리·AI 변환·자르기·선택·회전·라벨러·텍스트를 터치로 쓰는 흐름으로 바꿔야 한다. 크롭 비율 입력은 모바일 기본 화면에서 없애고, 이미지와 선택 영역을 크게 보여준다. 비교는 원본/결과를 같은 크기의 화면에서 전환하며, 두 개의 작은 이미지를 큰 검은 영역에 위아래로 쌓지 않는다.

- 실제 계정/유료 AI 요청은 0회. 사용자 프로필·PDF·도해는 사용하지 않고 독립 브라우저 상태와 임시 도형으로 확인했다.

## 최신 화면 방향 · 독립 변환기와 후처리 캔버스

사용자와 논의한 방향은 **독립 변환기 유지 → 필요할 때 캔버스 후처리**다. 앞의 캔버스 중심 제안에서 변환 작업을 캔버스에 통합하는 해석은 이 절로 대체한다.

- 변환기는 전체 화면에서 자료/사진 입력, 직접 크롭, 요청 작성, 변환, 같은 프레임 원본/결과 비교를 담당한다. 결과만 저장해 캔버스 없이 작업을 끝낼 수 있다.
- 선택 결과의 ‘캔버스에서 편집’은 명시적인 전달이다. ‘선택한 그림 교체 / 새 그림으로 추가’를 구분하고 기존 라벨과 텍스트를 보존한다.
- 캔버스의 ‘변환기’ 버튼은 선택 그림을 가져가거나 이전 변환 작업으로 돌아가는 진입점이다. 실제 제품에서는 새 입력이면 결과를 해당 입력과 다시 연결하고, 이전 입력/요청/결과를 작업 단위로 보관한다. 시안은 한 예시 자료만 사용하므로 새 이미지별 결과 연계는 보여주지 않는다.
- 화면 이동은 변환 요청/결과와 캔버스 편집 상태를 유지해야 한다. 요청 변경 후 재변환과 취소 정책, 별도 저장 형식은 실제 구현 합격 조건으로 둔다.
- 새 시안: `http://127.0.0.1:19622/`, 저장소 밖 `mobile-converter-0919/`. 예시 SVG 원본에는 인쇄 문구를 보이고 결과에서는 이를 제거한다. 실제 사진/AI 생성 결과가 아니다. 추가는 예시 이미지 한 개의 추가·Undo까지만 보여준다. 저장·자료 검색·사진 업로드·실기기 키보드는 미연결이다. 기존 시안은 보존한다.

## 화면과 조작 계약 제안

- 기존 5E 어두운 패널과 파란 강조색 유지. 도해는 흰 캔버스에서 최대한 크게 표시한다. 색은 기존 `css/style.css` 토큰을 따른다.
- 상단: 라이브러리, AI 변환, 저장. 별도의 큰 제목/상태/작업 레일을 편집 영역 위에 겹겹이 두지 않는다.
- 하단: 선택·자르기·회전·라벨러·텍스트 5개. 누른 도구만 추가 조작을 연다. 기본 터치 목표 최소 44×44 CSS px, 본문 14px, 입력 16px, 간격 12px.
- 캔버스: 화면의 남은 높이를 사용하고 가로 넘침이 없다. 도해 맞춤은 실제 렌더 비율로 계산한다. 작은 화면에서 장비 그림이 조그맣게 축소되지 않도록 편집할 부분을 확대한다. 두 손가락 팬/확대와 하단 맞춤/확대 버튼을 함께 제공한다.
- 비교: 같은 프레임에서 원본/변환 결과를 전환하고 확대 위치를 공유한다. 미리보기 전환은 캔버스의 객체를 바꾸지 않는다. 결과를 수락하는 **캔버스에 넣기** 동작은 별도로 명시한다.
- 크롭: 그림 위 4개 모서리를 끌어 크기 조절, 상자 안을 끌어 위치 조절, 빈 영역에서 새 상자 지정. 바깥 영역만 어둡게 처리한다. 아래에는 취소/적용만 둔다. 숫자 비율/좌표를 입력하지 않아도 완료해야 한다. 크롭은 선택 이미지에만 적용하고 다른 라벨·텍스트는 보존한다.
- 선택: 탭해 선택, 선택한 객체 드래그로 이동. 빈 곳 탭으로 선택 해제. 작은/겹친 객체는 확대와 선택 후보 목록으로 접근한다. 키보드 다중선택은 기본 흐름에서 요구하지 않는다.
- 회전: 선택 이미지의 ±90° 버튼과 슬라이더. 비율 변경 없이 중심을 기준으로 돌리고 한 동작을 실행 취소 한 번으로 복원한다. 두 손가락 비틀기 회전은 필수가 아니다.
- 라벨러: 가리킬 지점 탭 → 글자 위치 탭 → 입력 창 → 완료. 가리킬 점은 손가락에 가리지 않는 보조 표시를 제공한다. 라벨 문자/지시선 끝점은 별도 편집 가능한 기존 `labeler` 객체로 저장한다.
- 텍스트: 위치 탭 → 입력 → 완료. 한글 조합 중에는 객체 생성·단축키가 개입하지 않는다. 선택 후 **글자 수정**과 삭제/크기를 명시한 조작으로 고친다. 더블클릭·우클릭·Enter를 필수로 하지 않는다.
- 키보드: 입력 창과 완료 버튼이 실제 보이는 영역 안에 있어야 한다. 키보드가 열려도 선택한 그림 위치와 입력 내용을 유지한다. 시안의 브라우저 입력은 실제 휴대폰 키보드 검증을 대신하지 않는다.
- 결과: AI PNG는 이미지 객체다. 새로 단 라벨/텍스트는 객체로 재편집 가능하지만 PNG 안에 이미 인쇄된 글자가 자동으로 독립 텍스트가 되는 것은 아니다. 기존 인쇄 글자 제거는 AI 요청이나 이미지 영역 편집으로 처리한다.
- 저장: 현재 캔버스 PNG 출력과 기존 편집 상태 저장/실행 취소를 재사용한다. 다운로드 성공과 iOS 사진 앱 저장은 별개로 확인한다.

## 휴대폰에서 가능한 범위와 판단 조건

위 7개 도구는 터치만으로 설계할 수 있다. Pointer Events는 터치/펜/마우스 및 여러 접점을 처리하는 모델이며, 앱의 제스처와 브라우저 스크롤을 `touch-action`으로 분리해야 한다. 이는 기술적 가능성이고 현재 제품의 정상 작동 증거가 아니다. [W3C Pointer Events 3](https://www.w3.org/TR/pointerevents3/), [MDN Pointer events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events).

키보드는 레이아웃 영역과 실제 보이는 영역을 다르게 바꿀 수 있다. [MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport). 기존 모드를 단순 CSS 확대하는 대신, 제스처의 소유자를 결정해야 한다.

| 입력 | 동작 | 보호 규칙 |
|---|---|---|
| 한 손가락 탭 | 선택/지점 배치 | 실제 이동과 구분, 이중 입력 금지 |
| 선택한 대상 한 손가락 드래그 | 객체 이동/크롭 핸들 | 화면 이동과 혼동하지 않음 |
| 두 손가락 | 캔버스 팬/확대 | 첫 손가락의 객체 이동을 취소하고 원위치 보존; 손가락이 모두 떨어져야 다음 조작 |
| 브라우저가 조작 취소/탭 배경 전환 | 현재 드래그 취소 | 초안 롤백, 자동 AI 재요청 금지 |
| 패널 안 스크롤 | 자료/설정 스크롤 | 캔버스 제스처와 분리 |

휴대폰에서 정밀한 라벨링을 쉽게 하려면 확대, 넓은 터치 판정, 가림을 피하는 지점 표시가 필수다. 실제 iPhone Safari와 Android Chrome에서 아래 합격 기준을 통과하기 전에는 터치 편집 완성으로 표시하지 않는다. 실기기 없는 자동화는 대체 검증으로만 기록한다.

## 승인 후 구현할 묶음과 합격 기준

제품 수정은 시안 승인/수정 시작 지시 후 진행한다. 관련 기능 1~2개씩 구현하고 해당 개발 실행창에서 확인한다. 커밋/푸시/배포는 각각 기존 승인 원칙을 따른다.

1. **캔버스와 선택**: `js/mobile-entry.js`, `js/mobile-image.js`, `css/mobile-image.css`, `js/main.js`의 모바일 진입을 편집 중심으로 전환. 기존 `state/render/viewBox` 재사용. `js/touch-drag.js`, `js/transform.js`, `js/viewport.js`는 모바일 경로의 제스처 소유권을 정리하고 데스크톱 경로를 보존. 탭/이동/두 손가락/취소/Undo와 320/375/회전 화면을 확인한다. 화면 숨김과 이동 탐색 실패를 먼저 해결한다.
2. **자르기와 회전**: 사진/라이브러리 입력 크롭과 캔버스 이미지 크롭의 사각형 판정/미리보기/적용 경로를 재사용. `js/cut-tool.js`의 자유 분할을 모바일 사진 크롭으로 오인하지 않는다. `js/image-cutout.js`, `js/image-paste.js` 및 `js/transform.js`의 기존 이미지/회전을 연결. 네 모서리/영역 이동/경계/회전된 이미지 좌표/취소/Undo/EXIF를 확인한다.
3. **라벨러와 텍스트**: `js/tools/click-placement.js`, `js/text-editor.js`, `js/selection-visuals.js`와 기존 객체 저장을 재사용. 라벨 추가/문구 변경/지시선 조절/이동/삭제/한글 조합/키보드/Undo/새로고침 복원을 확인한다. 그림 자체의 회전과 라벨 회전은 선택한 대상만 적용한다.
4. **라이브러리와 AI 변환**: `js/exam-library.js`, `js/unified-library-ui.js`, `js/library/provider.js`의 제공 자료 검색/미리보기/크롭/삽입을 단순 모바일 화면에 연결. 내 사진은 모바일 파일 선택기와 브라우저 저장소를 사용하며, Mac의 PDF 경로나 폴더 API에 의존하지 않는다. 실제 검색과 캔버스 삽입을 확인한다. `js/ai-panel.js`의 기존 선택 이미지→변환→결과 삽입/저장을 연결하되, 재생성 시 기존 라벨/텍스트를 임의 삭제하지 않는다. 현재 이미지 대체는 기존 확인 절차와 위치·크기 보존을 따른다. 사용자가 고른 이미지/요청의 유료 실행 승인 후에 실제 인증·AI 1회·원본/결과 비교·캔버스 삽입·라벨링·PNG 저장을 확인한다.

각 묶음의 검증은 독립 데이터로 Chromium 터치 입력, WebKit 포인터/탭 자동화, 현재 데스크톱 경로의 해당 기능 대조를 수행한다. 새 테스트는 터치 경계(중복, 취소, 두 손가락 전환)와 실제 객체/출력 보존을 검증하며 내부 함수 구조를 그대로 복제하는 테스트를 만들지 않는다. 사용자 프로필로 전체 테스트나 설치 검증을 반복하지 않는다.

## 별도 시안과 검증 한계

- `http://127.0.0.1:19621/`은 별도 HTML/SVG 조작 시안이다. 예시 도형·라벨만 가지고 있으며 제품 계정·AI·자료팩·저장소와 연결되지 않는다.
- 도구 선택, 크롭 모서리 드래그, 예시 그림 회전, 라벨/텍스트 추가·수정·이동, 실행 취소, 확대 조작을 보여준다. 라이브러리/AI/저장 버튼은 연결 방식의 시안이며 실제 검색·변환·저장을 하지 않는다. 원본/결과 버튼은 같은 예시 그림을 사용한다.
- 시안에서 터치 조작이 통과해도 기존 제품 엔진의 구현 완료로 보고하지 않는다. 시안의 SVG 예시 크롭은 사각형 클리핑이며, 제품 이미지 바이트·좌표·저장 검증을 대신하지 않는다.
- 직접 확인용 순서: 자르기 → 모서리 드래그(영역만 변함) → 취소(기존 그림 유지); 라벨러 → 대상/글자 위치 탭 → 입력/추가(지시선과 글자 생성); 선택 → 글자 탭 → 글자 수정(내용 변경) → 드래그(글자 이동); 회전 → +90°(그림만 회전) → 실행 취소(원상복귀).
- 제품 전체 합격 흐름: 자료/사진 선택 → 크롭 → AI 변환 → 결과를 캔버스에 넣기 → 라벨러/텍스트 → 선택/이동/회전 → PNG 저장 → 재열기. 실제 휴대폰에서 외장 키보드/마우스 없이 완료해야 한다. 실제 계정/유료 AI/사진 앱 저장이 남으면 해당 항목은 미검증으로 남긴다.

## 보류

수식 전문 편집, 복잡한 벡터 분할·객체화, 다중 라벨 분기, 모든 데스크톱 도구, 네이티브 모바일 앱, 장치 간 개인 폴더 동기화는 이번 7개 기능 기획 범위에서 제외한다. 현재 자료팩 서버·AI 런타임 서버·배포 설정을 임의로 바꾸지 않는다. 모바일 자료 소스에서 추가 서버 지원이 필요하면 근거와 범위를 먼저 제시한다.

## 이번 시안에서 확인한 범위

2026-09-19 별도 시안의 Chromium/WebKit 28개 상태를 새로 캡처했다. 320·375·768·1280px와 가로 화면에서 가로 넘침을 확인했고, 크롭 조절/취소, 라벨 추가/문구 수정, 텍스트 추가, 그림 이동/회전/실행 취소를 독립 상태로 확인했다. Chromium은 CDP 터치 드래그·탭·동시 두 손가락 확대를 사용했고, WebKit 드래그는 마우스 포인터이며 탭은 터치 입력이다. 일반 도구 버튼은 자동화 클릭이므로 터치만의 전체 사용 흐름이 검증된 것은 아니다.

자동 측정은 보이는 버튼·input·select의 최소 높이/너비 43px 미만 여부를 확인했으며, SVG 핸들/객체·textarea를 모두 측정한 결과가 아니다. 첫 손가락 이동 후 두 번째 손가락 진입 시 롤백, 빈 곳 선택 해제, 새 크롭 상자, 지시선 끝점 편집은 시안의 검증 범위 밖이다. 가로 화면의 전체 맞춤은 도해가 작아지므로 실제 기기에서 확대 사용성을 확인한다. 제품 소스는 이전 해시와 동일하며, 이번 반영은 문서와 저장소 밖 시안뿐이다. 개발 실행창/설치본/배포에는 이 재기획을 반영하지 않았다.

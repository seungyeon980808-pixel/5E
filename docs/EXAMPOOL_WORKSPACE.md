# ExamPool 문항 설계 작업 공간

5E의 **문항 설계**는 흰색 문항 편집 영역과 자료 열람 패널을 나란히 배치한다. 기존 ExamPool의 `static/index.html` 문항 설계/근거 검색과 `static/js/question.js`의 성취기준·원문·근거 연결 흐름을 참고했다. 중앙에서 번호·지문·사진/그림·발문·보기·선지 ①~⑤를 입력하면서 옆에서 자료를 확인한다. 작은 화면에서는 ‘문항 작성 / 자료 열람’으로 전환하며 작업 내용을 유지한다. 앱의 어두운 테마에서도 문항과 원문은 화이트톤이다.

**성취기준**은 원래 ExamPool의 `app/seed/standards.json`을 그대로 가져온 수록본이다. 교육부 고시 제2022-33호 [별책 9] 과학과 교육과정의 20개 과목·371개 기준이며, 과목·단원·핵심어로 찾고 기준 문장, 해설, 탐구 활동과 지도 시 고려 사항을 읽는다. 임의의 기준을 생성하지 않는다. 선택한 기준의 코드·본문·해설·출처와 출제 의도를 문항에 저장한다. 데이터 출처는 자료 패널 하단에 표시한다.

**교과서 / 참고자료**에서 사용자의 PDF·PNG·JPEG·WebP·텍스트 파일을 연다. 기존 5E PDF 런타임으로 PDF 원문을 렌더링하고 텍스트를 추출한다. 파일명과 본문을 검색하며 쪽수 이동·확대·텍스트 인용을 제공한다. 스캔 PDF는 원문 열람을 지원하지만 OCR은 자동 수행하지 않으며 검색 한계를 결과 화면에 안내한다. 자료의 쪽수와 인용/메모를 문항 전체·지문·발문·보기·개별 선지에 연결할 수 있다. 연결한 근거에서 원문을 다시 열 수 있다. 파일별 50 MB, 텍스트 1 MB, PDF 3,000쪽, 자료 100개 제한을 적용한다. 원본 교과서 파일을 새로 배포하거나 가짜 자료를 기본값으로 채우지 않는다.

문항을 만들거나 선택할 수 있고 입력 후 자동 저장한다. 저장 중에도 입력 초점은 유지한다. 명시적인 저장과 창을 닫거나 다른 문항을 선택할 때의 저장도 제공한다. 출력 미리보기는 설계 정보·근거를 제외하고 문항 내용과 그림만 보여준다.

문항은 해당 브라우저/주소의 IndexedDB `5e-exampool/questions`, 자료 원문과 검색 텍스트는 `resources`에 보관한다. 저장소 버전 2로 올릴 때 기존 문항을 보존하고 자료 저장소만 추가한다. 이전 문항 파일의 새 설계 필드는 선택적이며 계속 열린다. 원래 ExamPool의 SQLite 데이터와 별도이며 양방향 DB 동기화는 이번 범위에 포함하지 않는다. 다른 포트·브라우저·컴퓨터에서 이어서 작업하려면 **문항 파일 저장 → 문항 파일 열기**를 사용한다. `.exampool` JSON 파일에는 문항 구조, 성취기준·출제 의도·근거 연결, 자료 원문, 사진, 작업 그림, 확정 그림, 편집 가능한 5E 원본이 함께 들어간다. 파일 열기는 기존 자료를 지우지 않고 추가하며, 동일 ID의 서로 다른 내용은 거부한다. 문항과 자료 가져오기는 단일 트랜잭션으로 처리하고 저장 버전 충돌도 거부한다. 전체 파일은 최대 128 MB이다.

그림은 **현재 5E 그림 가져오기** 또는 **사진 파일 열기**로 작업본을 만든다. **작업본 확정**은 픽셀과 원본을 복제해 확정본으로 보관한다. 새 작업본을 가져와도 이전 확정본은 유지된다. 두 버전이 다르면 화면에서 각각 확인할 수 있다. **5E 원본 편집**은 이미 연결된 작업 탭으로 돌아가거나, 새 탭으로 원본을 복원한다. 다른 탭을 덮어쓰지 않는다. 일반 사진에는 편집 가능한 5E 원본이 없지만 원본이 포함된 PNG는 기존 `readEditablePng` 경로로 복원한다.

**한글로 보내기**는 발문이 없거나 사진/그림이 미확정이면 거부한다. 기존 RHWP 작업 공간의 본문 커서에 번호·지문·확정 그림·발문·보기·선지를 순서대로 넣는다. 전체 삽입은 네이티브 실행 취소 한 번으로 되돌릴 수 있다. 그림 중앙 정렬이 이후 문단에 전파되지 않는다. 기존 `.hwp`/`.hwpx` 저장과 원본 포함 PNG 연결을 이용한다. 사진/그림 없는 문항도 전달할 수 있다. 첫 전달 구현은 로컬 웹 미리보기용이며, 설치 앱의 별도 한글 창 IPC 전달은 후속 범위다.

## 다른 한글 작업 브랜치와의 연결 계약

`initRhwpExamWorkspace(...)` 반환값에 `receiveQuestion(packet): Promise<void>`를 추가했다. 소비자는 `initExamPoolWorkspace(...)`이며, 기존 ExamPool 명칭을 유지한 다음 구조를 전달한다.

```js
{
  format: '5e-exampool', version: 1,
  question: { id, number, passage, ask, bogi_items: [{id, label, text}], choices: [{id, ord, text}] },
  figure: null || { assetId, id, name, confirmedAt, capturedAt,
    png, source, render, widthMm, heightMm, pixelWidth, pixelHeight }
}
```

`figure`는 확정 스냅샷만 전달한다. 작업본이나 현재 캔버스를 전달 함수에서 다시 읽지 않는다. `source`는 기존 `serialize`의 단일 활성 페이지 프로젝트이며 `prepareLoadedProject`로 검증한다. `png`는 실제 확정 픽셀이다. 편집 원본은 기존 `embedEditablePng`로 한글 그림에 포함한다. 일반 사진은 `source:null`이다.

문항·선지·보기·그림 자산·그림 수정본에는 각각 고정 ID를 사용한다. 원래 ExamPool DB의 정수 PK를 가장하지 않는다. 한글에 들어간 5E 그림에는 `exampool:{questionId,assetId,confirmedRevisionId,confirmedAt}` 메타데이터를 남긴다. 한글 문서에서 나중에 편집한 그림은 그 문서의 수정본이며, Pool의 확정본을 자동 변경하지 않는다.

한글 기능 고도화 브랜치의 팔레트/양식 채우기가 합쳐지면 `receiveQuestion` 안에서 기존 문항 필드를 팔레트 슬롯으로 매핑할 수 있다. 현재 구현은 팔레트 이식 코드에 의존하지 않는다. 공통 수정 지점은 `js/main.js`, `js/rhwp-exam-workspace.js`, `js/rhwp-exam-bridge.js`, `index.html`이며, 신규 `exampool-*` 파일은 독립적이다. `RhwpExamBridge.transaction`은 외부 배치 안에서 기존 삽입 도우미를 호출할 때 네이티브 undo를 중복 만들지 않는다.

## 검증

- `tests/test-exampool-model.mjs`: 고정 ID, 확정본 분리, 파일 계약, 잘못된 구조 거부.
- `tests/test-exampool-references-browser.cjs`: 두 엔진에서 저장소 버전 1의 기존 문항 보존, 실제 성취기준·해설 대조, PDF 두 쪽의 실제 추출/렌더링·검색·확대, 텍스트·이미지 원문, 선지 근거 저장, 새 브라우저에서 자료 포함 파일 재열기, 근거 원문 복원, 화이트톤 및 세 화면 너비 검수.
- `tests/test-exampool-browser.cjs`: Chromium/WebKit에서 저장·새로고침·파일 재열기·원본 복원·확정본만 전달·본문 순서/정렬·한 번 실행 취소·HWP/HWPX 저장 후 재열기·사진 교체·저장 충돌/원자적 가져오기 및 데스크톱/좁은 화면.
- 기존 한글 그림/원본/프로젝트 단위 검사와 기존 Hwp 연결 메뉴 검사를 병행한다.

2026-10-13 검수 결과: 관련 단위 검사 45개 통과, 문항 및 자료 열람 브라우저 검사 Chromium/WebKit 모두 통과. HWP/HWPX 파일을 실제 저장한 뒤 다시 열어 확정 수정본 ID와 편집 원본이 유지되는 것도 확인했다. 검수 생성물은 `_work/exampool/verification/`와 `_work/exampool/references/`에 로컬 전용으로 남긴다.

기존 `test-rhwp-exam-workspace-browser.cjs`는 기준 커밋에서 이미 제거된 `#exam-workspace-open`을 찾으므로 전체 실행에 실패한다. 제품에 옛 버튼을 복원하지 않고, 현재 `[data-exam-document-open]` 경로를 사용하는 검사로 이번 변경을 확인한다.

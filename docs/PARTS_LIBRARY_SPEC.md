# 부품 라이브러리 규격 (PARTS_LIBRARY_SPEC.md)

> 퍼블릭 도메인 과학 도해(SVG)를 모아 두고, 쓸 때 **흑백 선화로 바꿔** 캔버스에 넣는다.
> 기출문항 라이브러리(`docs/EXAM_LIBRARY_SPEC_20260706.md`)와 **같은 구조**로 만들었다 —
> 서버·API 없이 정적 파일만으로 돌고, 앱 시작 부하가 0이다.
>
> 착수 2026-07-31.

---

## 1. 왜 원본을 저장하고 쓸 때 변환하나

선화로 미리 바꿔서 저장하지 않는다. **원본(컬러)을 저장하고 삽입 시점에 변환한다.** 이유 셋:

1. **최적 위계가 그림마다 다르다.** 실측에서 증류 장치는 L2가, 식물 세포는 L3가 맞았다.
   미리 하나로 굽으면 그 선택권이 사라진다.
2. **변환기가 계속 나아진다.** 실제로 `viewBox` 없는 SVG에서 그림이 통째로 사라지는 버그가
   있었고(11장 중 5장), 고친 뒤 재변환으로 전부 살렸다. 원본이 없었으면 다시 수집해야 했다.
3. **변환이 싸다.** 한 장에 수십 ms다. 결과는 캐시한다.

## 2. 파일 배치

```
assets/parts-library/
  manifest.json     목록(생성물) — tools/build_parts_manifest.py 산출
  meta.json         사람이 손보는 정보 — 한글 이름·분류·검색어·출처
  svg/<id>.svg      원본 SVG (컬러 그대로, 손대지 않음)
js/parts-library.js 창 UI
js/lineart.js       선화 변환 (순수 모듈)
css/parts-library.css
tools/build_parts_manifest.py
tools/parts_wanted.py   무엇을 모을지 — 기출 분해 결과에서 자동 추출
```

**meta.json 과 manifest.json 을 나눈 이유**: 손으로 적은 정보(한글 이름·분류)와 기계가 재는
정보(파일 크기·요소 수)를 한 파일에 섞으면, 다시 생성할 때 사람이 쓴 게 날아간다.

## 3. manifest 항목

```json
{
  "id": "c_distillation",
  "file": "c_distillation.svg",
  "subject": "c", "subjectLabel": "화학",
  "part": "실험 기구",
  "name": "증류 장치",
  "keywords": ["증류", "냉각관", "플라스크", "distillation"],
  "license": "Public domain",
  "source": "https://commons.wikimedia.org/wiki/File:Simple_distillation_apparatus.svg",
  "elements": 40,
  "bytes": 20480,
  "defaultLevel": "L2"
}
```

- **`license` 와 `source` 는 항목마다 반드시 박는다.** 나중에 출처를 다시 조사하지 않기 위해서고,
  라이선스가 애매한 게 섞이면 그것만 골라 뺄 수 있게 하기 위해서다.
- `elements` 는 복잡도 대용치 — 위계 기본값을 고를 때의 힌트다.
- `subject` 는 `p`(물리) `c`(화학) `b`(생명) `e`(지구) `x`(공통).
- `part` 문자열은 팔레트 카테고리와 **글자까지 같게** 맞춘다.

## 4. 선 위계 4단계

원본을 얼마나 걷어낼지의 손잡이다. `js/lineart.js` 의 `LINEART_LEVELS`.

| 단계 | 이름 | 하는 일 |
|---|---|---|
| L0 | 전부 | 색만 벗긴다. 아무것도 안 지운다 |
| L1 | 세밀 | 아주 작은 조각만 정리 |
| L2 | 표준 | 글자 크기 요소 + 지시선 제거 ← 대개 이것 |
| L3 | 단순 | 큰 구조만 남긴다 |

채우기는 2종. **`none`(채우기 없음)이 기본**이다 — `white`는 앞뒤 가림을 유지하는 대신
내부 구조를 덮어버린다(미토콘드리아 크리스타가 실제로 사라졌다).

선 굵기는 **"몇 mm 폭으로 놓을 것인가"에서 역산**한다: `선굵기 = viewBox폭 × (0.35 / 목표폭mm)`.

### 상자를 그림에 맞춰 줄인다 (2026-08-01)

원본 SVG 는 그림 둘레에 빈 여백을 크게 두는 경우가 흔하다. 실측에서 단진자 도해는
**상자의 46%만 그림**이고 가로 38%·세로 26%가 여백이었다. 그대로 두면 캔버스에서 선택 상자가
그림보다 훨씬 크게 잡혀 배치가 어렵다.

그래서 `toLineArt` 가 **지우고 남은 것들의 실제 bbox 로 viewBox 를 다시 잡는다**(선 굵기의
절반을 여유로 둔다 — 원본 여백이 부족해 잉크가 살짝 넘치는 파일도 있다).
여백이 3% 미만이면 건드리지 않는다.

| 부품 | 크롭 전 채움률 | 크롭 후 |
|---|---:|---:|
| 단진자 | 46% | 98% |
| 증류 장치 | 90% | 99% |
| 꽃의 구조 | 92% | 98% |

## 5. 성능 규약 (기출 라이브러리와 동일)

- **앱 시작 시 로드 0.** manifest 는 창을 처음 열 때 1회만 가져온다.
- 썸네일은 `loading="lazy"` — 화면에 보이는 것만 읽는다.
- 검색은 클라이언트 선형 스캔, 그리드는 상한을 두고 그린다.
- 원본 SVG 는 **고른 항목만** 가져온다. 1000장을 등록해도 시작 시간이 안 변한다.

### 실측 근거 (2026-07-31)

| 잰 것 | 결과 |
|---|---|
| 자산 1000개 등록(디코드+문자열) | 10ms · 램 65MB |
| 캔버스에 자산 200개 | 다시 그리기 22ms (25개면 3ms) |
| 팔레트 아이콘 1000개 생성·배치 | 10ms |

자산은 `<image>` 한 장으로 그려지므로 **그림 안 도형이 584개든 40개든 캔버스 비용은 같다.**
문제가 되는 건 오직 "코드에 박아 시작할 때 전부 읽는" 방식이고, 그래서 정적 파일 + 지연 로딩으로 간다.

## 6. 삽입 규약 — **두 갈래**

기출 라이브러리가 [이미지로 삽입] / [객체로 변환] 두 갈래를 주는 것과 같은 이유로,
부품 라이브러리도 두 갈래를 준다. **한 갈래만으로는 자르기 도구가 안 먹는다.**

| 갈래 | 결과 | 자르기(가위) | 언제 |
|---|---|---|---|
| **이미지로 넣기** | `svgAsset` 1개 (`<image>`) | ✗ | 그대로 쓸 때. 가볍다(객체 1개) |
| **선 객체로 넣기** | `polyline`/`ellipse`/`rect` 여럿 | ✓ | 잘라내고 고칠 때 |

`js/cut-geometry.js` 의 `isCuttable()` 은 line·polyline·curve·ellipse·rect·triangle 만 받는다.
`<image>` 는 자를 기하가 없어서 원리상 불가능하다 — 그래서 **객체로 푸는 갈래**를 따로 둔다.

### 선 객체로 넣기 (`js/svg-to-objects.js`)

**래스터 객체화(`image-vectorize.js`)를 쓰지 않는다.** 원본이 이미 벡터라 SVG 경로를 그대로
5E 객체로 옮기면 정밀도 손실이 없다. 래스터로 구웠다 되돌리면 품질이 떨어진다.

- `<path>` → `polyline`(균등표본 → RDP) · `<circle>/<ellipse>` → `ellipse` · `<rect>` → `rect`
- 좌표는 `getCTM()` 으로 중첩 `transform` 을 전부 푼 최종 좌표
- 회전이 섞인 상자·원은 축평행으로 못 담으니 폴리라인으로 떨어뜨린다
- 전부 같은 `groupId` — 통째로 옮기고 Shift+G 로 풀어 낱개로 자른다
- 점이 20,000개를 넘으면 표본 간격을 자동으로 늘린다(`reduced: true`)

**실측(미토콘드리아 L2)**: 선화 62요소 → 객체 62개(polyline 31 + ellipse 31), 점 534개,
`isCuttable` 통과 62/62, 가위로 실제 분할 확인.

### 지우개 — 진짜 구멍을 뚫는다 (`js/erase-tool.js`, Shift+E)

자르기가 **둘로 나누는** 것이라면, 지우개는 **일부를 없애는** 것이다. 흰색으로 덮는 게 아니라
마스크로 실제 투명하게 만든다 — 뚫린 자리를 클릭하면 **뒤에 있는 객체가 잡힌다**(실측 확인).

- 올가미(자유 경로)로 두르면 겹치는 모든 `image`·`svgAsset` 에 `poly` cutout 이 추가된다
- 기존 cutout 을 지우지 않고 이어붙인다 — 여러 번 지울 수 있다
- 좌표가 상자의 0~1 분수라 이동·크기변경·회전에 자동으로 따라붙는다
- Undo 1스텝, 저장 왕복 보존

### 이미지로 넣기

`svgAsset` 타입으로 넣되 `src` 에 변환 결과 data URI 를 담는다. 렌더러가
`obj.src || asset.dataUri` 를 읽으므로 코드 레지스트리에 등록하지 않아도 그려지고,
**저장 파일이 라이브러리 폴더 없이도 자기완결**된다(기출 라이브러리가 dataURL 로 넣는 것과 같은 이유).

`partId` · `lineLevel` · `lineFill` 을 함께 저장해 두면 나중에 "원본에서 다시 뽑기"가 가능하다.

## 7. 무엇을 모으나

`tools/parts_wanted.py` 가 기출 도판 분해 936장(물리 483·화학 280·지구 104·생명 69)에서
"그림이 없어 못 그린다"고 표시된 항목을 뽑아 `docs/PARTS_WANTED.md` 로 만든다.

세 갈래로 나뉜다 — **이 구분이 중요하다**:

| 갈래 | 건수 | 조치 |
|---|---:|---|
| 가) 이미 만든 부품으로 해결됨 | 84 | 수집 대상 아님(화학 `vessel` 타입 등) |
| 나) 기출 크롭 정책 | 200 | `docs/PARTS_PIPELINE.md` — 600dpi에서 오린다 |
| 다) 웹 수집 대상 | 79 | **이것만 모은다** — 40여 종 |

분해 데이터는 **부품 제작 이전 스냅샷**이라 그대로 믿으면 안 된다. 부품을 더 만든 뒤
`parts_wanted.py` 를 다시 돌리면 목록이 자동으로 줄어든다.

수집 규모는 **40여 종 × 종당 3~5장 = 150~200장**이 적정하다. 커먼즈 카테고리 실측으로
SVG physics 500+ · biology 308 · astronomy 259 · 실험기구 93 · 백지도 57 · anatomy 44 ·
**geology 10(거의 없음)** 이고, 라이선스 필터를 걸면 쓸 만한 건 400~600장이다.

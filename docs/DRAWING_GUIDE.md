# 기출 그림 재현 지침 (DRAWING_GUIDE.md)

> MCP(mcp-5e)로 5E에 그림을 그릴 때 **매번 읽는다.** 여기 적힌 것은 추측이 아니라
> 실제로 그려 보고 틀려 본 결과다. 새로 알아낸 것은 그때그때 여기에 더한다.
>
> 최초 작성 2026-07-27 (물리1 2027-06 4번 재현 중)

---

## 1. 필드 이름 — 여기서 제일 많이 틀린다

| 타입 | 글자를 담는 필드 | 틀리기 쉬운 것 |
|---|---|---|
| `text` | **`text`** | `label` 로 주면 **조용히 빈 글자**가 된다 |
| `formula` | **`source`** | `label` 로 주면 **아무것도 안 보인다** |
| `rect` / `ellipse` | `label` | 맞다. 단 아래 2번 참고 |
| `anglearc` | `label` | `theta_1` → θ₁ 자동 변환 |

**아래첨자**: `rect` 의 `label` 은 `m_B` 를 그대로 "m_B" 로 그린다 — **첨자로 안 바꾼다.**
상자 안에 `m_B` 를 넣어야 하면 상자는 라벨 없이 두고 **상자 중심에 `formula` 를 따로 얹는다.**

**화살표**: `line` 에 `arrowEnd` 같은 필드는 **없다**(조용히 무시된다).
`lineMode: "arrow"` + `arrowHead: "end"` 를 쓴다. `arrowHead` 는 `none|end|start|both`.

**모르는 필드는 조용히 버려진다.** 그래서 `describe_schema` 를 먼저 부르는 습관이 필수다.
`add_objects` 는 필드가 틀리면 오류를 내지만, **정의에 없는 여분 필드는 통과시킨다.**

## 2. 좌표·각도

- 단위 mm, 원점은 아트보드 **중앙**, **+y 는 아래쪽**.
- `anglearc` 의 `startAngle`/`sweepAngle` 은 **수학 관례**(반시계 +, +Y 위)다.
  화면 좌표(y 아래)에서 방향을 구했으면 **y 부호를 뒤집어** 각을 계산한다.
  예: 화면 벡터 (22, −30) → 수학 (22, +30) → `atan2(30, 22) = 53.7°`
- 각도 호는 **두 선분의 실제 교점**을 꼭짓점으로 잡고, 두 선분 방향에서 각을 계산한다.
  눈대중으로 넣으면 호가 엉뚱한 각을 가리킨다.
- `formula` 의 w/h 는 앱이 실측하므로 MCP 가 넣는 값은 추정치다(경고가 뜬다). 정상이다.

## 3. 글꼴 — 물리량과 이름을 구분한다

| 무엇 | 어떻게 |
|---|---|
| **물리량**(변할 수 있는 양: θ, λ, v, m, R) | `formula` 기본값 = Latin Modern **이탤릭** |
| **이름표**(물체 A·B, 점 P·Q, 파원 S₁) | `formula` + `italic:false` + 신명중명조 계열 `fontFamily` |
| 한글 문장(수평면, 진행 방향) | `text` (돋움) |

`anglearc` 는 `labelType:"quantity"` 가 기본이라 θ 가 자동으로 이탤릭이 된다 — 따로 안 해도 된다.

로마숫자 영역 표시는 `{roman1}`~`{roman12}`. 실제로 I·II·III 로 렌더된다.

## 4. 검증 절차 — 점수 게이트는 쓰지 않는다

### 왜 "일치율 95%" 게이트가 안 되는가 (두 번 시도해서 두 번 실패)

원본은 **스캔 이미지**, 재현본은 **벡터**다. 선 굵기가 3~4배, 글꼴·여백·배율이 전부 다르다.

- 단순 픽셀 IoU: 잘 맞은 그림 **0.042**, 기울기가 뒤집힌 그림 **0.037** — 구별 불가.
- 허용오차(선 굵히기) + 평행이동 정렬을 넣어도 **0.251 대 0.296** 으로,
  **틀린 그림이 더 높은 점수**를 받았다. 파면처럼 주기적인 무늬는 반주기만큼 밀려도
  그럴싸하게 겹치기 때문이다.

임계값을 걸면 맞는 그림이 계속 탈락하고 틀린 그림이 통과한다. **점수는 참고용으로만 쓴다.**

### 실제로 오류를 잡은 것

**① 물리적 제약 검사 (가장 강력했다)**
"진행 방향 화살표는 파면과 직각이어야 한다" — 이 제약으로 파면 기울기가 뒤집힌 것을 찾았다.
눈으로는 두 번 놓쳤고 픽셀 비교로도 못 잡았다. 그림마다 이런 제약이 있다:
굴절 방향, 힘과 가속도의 방향, 전기력선이 +에서 나와 −로 들어가는 것, 실의 장력 방향 등.

**② 차이 이미지 육안 확인**
`tools/compare-exam-figure.py` 가 만드는 겹침 이미지 — 빨강=원본에만, 파랑=재현본에만,
검정=둘 다. 위치가 밀린 것·비율이 다른 것·빠뜨린 요소가 한눈에 보인다.
**숫자 하나보다 이 그림이 훨씬 정확한 피드백이다.**

```bash
python tools/compare-exam-figure.py <원본.png> <재현본.png> <차이이미지.png>
```

**③ 요소 체크리스트** (그릴 때마다 훑는다)
- [ ] 영역 개수·음영·비율이 원본과 같은가
- [ ] 물리량은 이탤릭, 이름표는 정체인가
- [ ] 각도 호가 있는가, 올바른 각을 가리키는가
- [ ] 화살표에 화살촉이 있는가 (`lineMode`+`arrowHead`)
- [ ] 아래첨자가 첨자로 렌더됐는가
- [ ] 원본에 있는데 빠뜨린 요소가 없는가
- [ ] 라벨이 도형을 뚫거나 선에 겹치지 않는가

**④ 반복 상한 4회.** 못 맞추면 멈추고 "여기가 안 됩니다"라고 보고한다. 무한 루프가 가장 위험하다.

## 5. 재현할 수 없는 것은 먼저 걸러낸다

- **캐릭터 삽화**(학생 얼굴 등) — 5E 오브젝트에 없다. 예: 물리1 2027-06 **2번**.
  칠판 안 자료(궤적·구간 표시)만 그리는 것은 가능하다. 문항을 고를 때 원본을 먼저 보고 판단한다.
- 사진, 손그림 질감, 복잡한 3D 음영.

## 6. MCP 로 그릴 때의 함정

**어느 창에 그리는지 먼저 확인한다.** `app_status` 가 창 표식(cid)과 주소를 알려준다.
5E 를 여러 개 열어 두면(다른 Claude Code 세션이 검증용으로 띄운 것도 포함) 마지막에 연 창이
통로를 가져간다. 확인 없이 그리면 **남이 쓰던 문서에 그림이 들어간다**(실제로 일어났다).

**앱 탭을 두 개 열지 않는다.** 브라우저 탭 두 개가 서로 연결을 뺏으면 그림이 두 문서로 흩어진다.

**돌아가는 앱의 자동저장 DB(IndexedDB `5e-autosave`)를 지우지 않는다.** 상태가 스냅샷 사이를
오가며 꼬인다.

**`remove_from_app` 이 0개를 돌려주면** 대상이 다른 창에 있다는 뜻일 수 있다. id 가 확실히
존재하는데 0개면 `app_status` 로 붙은 창을 다시 확인한다.

**결과를 눈으로 본다.** `export_image` 로 PNG 를 받아 확인한다. `read_app` 은 좌표만 주므로
선이 안 이어졌는지·라벨이 도형을 뚫었는지 알 수 없다.

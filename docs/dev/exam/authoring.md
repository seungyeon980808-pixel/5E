## ExamPool 문항 데이터·조판 설계 기준

2026-10-14 사용자 답변으로 정리한 요구사항이다. 구현 완료 보고서가 아니다.

### 목표

문항은 엑셀과 같은 데이터 시트에서 관리한다. 선택한 문항은 실제 시험지 규격으로 렌더링하고, 글·표·그림의 조판을 사용자가 만족할 때까지 편집한 후 한글로 전달한다. 한글에서 최종 서식을 처음 잡아야 하는 흐름은 목표에 맞지 않는다.

### 데이터 시트

- 항목은 행, 문항은 열이다. A열에 항목 이름을 고정하고 B열부터 문항을 나란히 관리한다.
- 기본 항목 순서는 문항유형, 대단원, 중단원, 소단원, 성취기준, 핵심개념, 문항관리번호, 발문, 자료, 사진, 지문, 선지, 보기이다.
- 핵심개념은 한 문항에 여러 개를 연결할 수 있다.
- 문항관리번호와 시험지에 인쇄하는 문항 번호를 구분한다.
- 선지·보기 등 여러 값을 가진 항목은 하위 행으로 펼쳐 입력할 수 있게 한다.
- 시트의 항목 순서는 관리 순서다. 시험지에 인쇄하는 구성 순서와 동일하게 강제하지 않는다.
- 평소에는 시트를 넓게 사용한다. 문항 머리글을 누르면 해당 문항의 미리보기를 연다.
- 셀 선택, F2/더블클릭 편집, 방향키 이동, Enter/Tab 확정, Esc 취소, 범위 복사·붙여넣기, 되돌리기 조작을 유지한다.
- 내려받은 XLSX도 세로 항목 구조를 제공한다. 표의 실제 셀, 그림 개체, 자료 연결, 조판 설정은 왕복 후에도 유지해야 한다.

### 문항 시작과 유형

처음에는 기출 문항 모양을 선택하고, 그 틀에 자료와 내용을 채운다. 선택 후에도 다음 세 요소를 독립적으로 변경할 수 있게 한다.

1. 자료 제시 방식: 일반 자료, 실험·탐구, 대화 등. 과정·결과·가설·결론과 같은 하위 구성을 포함한다.
2. 답 선택 방식: 정답형, 합답형, 서술형.
3. 선지 표현 방식: 글·수식, 보기 조합, 대응표, 그림·그래프.

사진·표는 개수뿐 아니라 상위 자료, 표시 순서, 나란히 배치, 글과의 어울림, 표 셀 안 배치까지 저장한다. ‘실험형’을 고른다는 이유로 항상 표와 그림을 강제로 하나씩 추가하지 않는다.

### 조판 편집

- 기본 시험지는 A4·2단이다. 다른 용지·단 설정도 선택할 수 있다.
- 기출 모양을 적용한 후 미리보기의 글·그림을 직접 선택해 수정한다.
- 글: 글꼴, 글자 크기, 자간, 장평, 줄 간격, 문단 간격, 정렬, 들여쓰기.
- 그림: 너비·높이, 비율 유지, 글자처럼 취급, 어울림, 정렬·위치, 글과의 상하좌우 간격.
- 표: 행 높이·열 너비, 병합, 셀 여백, 테두리, 셀 글의 정렬, 셀 안 그림.
- 보기·선지: 상자 여백과 제목, 번호 정렬, 가로·세로 배치, 항목 사이 간격. 사용자가 제공한 원본처럼 `<보 기>`를 상단 테두리 중앙에 배치하고 제목 자리에서 선을 끊는다. 가는 검은 테두리와 `ㄱ.·ㄴ.·ㄷ.` 표기, 기호 뒤 본문에 맞춘 내어쓰기를 기본으로 한다.
- 문항 단위 미리보기와 여러 문항을 배치한 시험지 전체 미리보기를 제공한다. 전체 미리보기에서 단·쪽 나눔과 자료 잘림을 확인한다.
- 공통 조판 설정을 다른 문항에 적용하되 개별 문항의 예외 설정을 보존한다.

### 한글 전달과 완료 조건

글·표·그림은 각각 편집 가능한 한글 요소로 유지한다. 문항 전체를 한 장의 그림으로 고정하는 것은 선택한 기본 방식이 아니다.

미리보기와 전달 결과는 동일한 조판 원본을 사용해야 한다. 화면용 HTML을 따로 배치한 뒤 한글로 보낼 때 다시 조판하는 방식만으로 완료라고 보고하지 않는다.

검수 항목은 내용·그림·표 구조 외에 글자 서식, 줄바꿈, 그림 크기·어울림·간격, 셀 크기·여백, 단·쪽 경계다. 저장한 HWP/HWPX를 다시 열어 확인한다. 글꼴 대체나 용지·단 너비 차이가 있으면 차이를 표시하고 완료 상태와 구분한다. 외부 한컴 한글의 실제 표시를 검수하지 않았다면 외부 한글에서도 완전히 동일하다고 보고하지 않는다.

자료나 글을 수정하면 기존 조판 확인 상태를 무효화한다. 이전 조판 초안은 보관하고 다시 확인해야 한다. 정답·해설 등 교사용 정보는 학생용 문항에 섞지 않는다.

### 현재 구현과 확인된 차이

- 항목은 행·문항은 열인 세로 시트와 같은 구조의 XLSX를 구현했다.
- 문항 머리글은 실제 RHWP 조판을 열며 저장한 HWPX 문항 범위를 네이티브로 시험지에 넣는다.
- 글·표·수식·그림의 내용과 조판 재열기 배치를 검수하며, 저장 파일의 배치가 달라지면 최종 모양을 다시 표시한다.
- 좁은 머리글의 단위 줄바꿈·행 높이·셀 여백을 반영하고 표의 불필요한 들여쓰기를 없앴다. 실험 상자의 각주 넘침과 중첩 셀의 글 겹침을 검사하며 문제가 있는 조판은 저장·전달하지 않는다.
- 그림 크기·어울림과 글자·문단 모양은 실제 문서 편집기에서 조절한다. 공통 서식의 여러 문항 일괄 적용은 아직 별도 기능으로 제공하지 않는다.
- HWP에서는 일부 표 다음 문단이 HWPX보다 약 4 px 이동하는 엔진 차이가 확인됐다. 차이가 있는 HWP 출력은 중단하고 HWPX를 안내한다.
- 보기 제목을 상단 선 중앙에 놓고 0.4pt 테두리, 150% 줄 간격과 실제 기호 너비에 맞춘 내어쓰기를 적용했다. 중첩 보기 셀도 글과 테두리를 편집 가능하게 유지하며 HWPX 재열기를 검수했다.
- 중첩 셀의 문단 서식을 직접 변경하는 문서 엔진 명령은 아직 제약이 있다. 기본 보기 내어쓰기는 HWPX 문단 서식으로 적용한다.
- 외부 한컴 한글 앱의 폰트 대체·줄바꿈 검수는 남아 있다.

### 남은 확인 사항

사용자는 LaTeX 또는 한글 수식 문법으로 입력하고 완성된 수식 모양을 확인하는 방식을 선택했다. 수식은 한글 수식 개체로 보관한다. 현재 구현은 `$...$`, `\(...\)`, `{{수식:...}}` 입력을 실제 문서 엔진의 수식 개체로 변환하며 분수·첨자를 검수했다. 행렬 등 복잡한 식의 범용 입력 품질은 개별 검수가 필요하다.

## 엑셀과 한글을 하나의 문항으로 관리

2026-10-14 사용자 요청: 데이터 시트와 한글 문항이 거의 한몸처럼 작동해야 한다. 사용자가 범위를 명확히 했다: 한글로 출력하면 작업이 끝나며, 외부 한글 수정의 시트 역반영은 현재 필수 범위가 아니다.

### 현재 확인된 동작

시트의 문항 구조와 내용을 편집 가능한 한글 문서로 조판하고, 실제 한글 엔진으로 렌더링한다. 조판 저장 시 원래 글·수식·그림과 일치하는지 확인하며, HWPX로 재열기한 문서의 배치와도 비교한다. 현재 한글 조판 화면에서 본문 내용을 바꾸면 시트 내용과 달라졌다는 이유로 저장을 차단한다. 따라서 양방향 내용 편집은 아직 완성된 상태가 아니다.

### 확정한 구현 방향

같은 문항 ID 아래에 내용·구조·조판 서식을 함께 보관한다. 사용자의 추가 설명에 따라 도구 안의 시트와 한글 문항 화면 모두에서 내용을 수정하는 것을 목표로 한다. 외부 한글 파일의 수정 내용을 되가져오는 기능과는 별개의 요구다. 사용자가 만족한 문항을 편집 가능한 한글 파일로 내보낸 뒤에는 역반영을 요구하지 않는다.

- 시트의 발문·자료·보기·선지를 바꾸면 해당 문항의 렌더링을 갱신한다. 기존 조판 서식을 유지할 수 있는 부분과 다시 배치해야 하는 부분을 구분한다.
- 문항 내용은 시트와 도구 안의 한글 문항 화면 양쪽에서 수정할 수 있도록 연결한다. 글꼴·자간·내어쓰기·표·그림 배치 등 조판도 문항 화면에서 조정한다. 표 안의 자료, 보기, 그림 선지처럼 구조가 있는 항목도 대응 위치를 명확히 유지한다. 현재 한글 화면의 내용 변경 저장을 차단하는 동작은 이 목표를 구현한 것이 아니다.
- 글꼴·크기·자간·내어쓰기·표 여백·그림 배치 같은 조판 설정은 같은 문항에 저장한다. 시트 내용 편집 때문에 사용자가 승인한 서식을 무조건 초기화하지 않는다.
- XLSX 왕복 시 문항 ID와 구조 및 조판 정보를 잃지 않도록 검증한다. HWPX는 같은 문항에서 만들어지는 편집 가능한 출력이다.
- 변경 전 내용과 승인한 조판을 보존한다. 두 화면의 변경이 충돌하거나 문항 구조를 판별하지 못하면 덮어쓰지 않고 사용자가 확인할 수 있게 한다.
- 갱신된 배치는 글 겹침·셀 및 단 너비 넘침·출력 재열기 차이를 검사한다. 검사에 실패한 모양을 승인된 조판으로 저장하지 않는다.

### 우선 작업: 문항 한 개를 위한 좁은 한글 용지

사용자는 전체 시험지를 모두 출력하여 완성된 시험지로 보는 기능을 후순위로 지정했다. 우선 한글 문서의 실제 용지 좌우 너비를 줄여 한 문항만 편집하고 렌더링한다. 확대율만 바꾸거나 A4 화면을 잘라 보이는 방식으로 대체하지 않는다.

- 문항의 본문 폭은 기준 시험지 한 단의 폭과 같게 한다. 현재 A4 2단, 좌우 여백 15mm, 단 간격 8mm 기준으로 한 단은 86mm다. 예를 들어 좁은 용지에 좌우 3mm 여백을 두면 용지 폭은 92mm가 된다. 이 규격을 실제 문항 용지에 적용하고 HWPX 재열기로 검수했다.
- 한 문항 용지는 1단으로 구성한다. 글자 크기를 축소하지 않고 같은 본문 폭에서 글·표·수식·그림의 배치를 확인한다.
- 한 문항은 시트의 한 열과 연결한다. 문항 ID와 열의 대응은 용지 높이 또는 실제 페이지 수에 따라 바뀌지 않는다.
- 고정된 높이의 한 페이지로 내용을 제한하지 않는다. 문항 편집 영역은 내용에 따라 높이가 늘어나고 세로로 스크롤하며, 지문·표·그림·보기·선지를 같은 문항으로 유지한다.
- 기준 시험지 한 단의 출력 가능 높이를 가이드로 표시한다. 이를 넘으면 출력 기준 높이 초과를 안내하고 사용자가 분량이나 배치를 조정한다. 자동 글자 축소, 내용 잘라내기 또는 데이터 삭제로 한 페이지에 맞추지 않는다.
- 기준 시험지 규격과 문항 편집용 용지 규격을 구분하여 보관한다. 나중에 전체 시험지에 넣을 때 같은 단 폭을 사용해 줄바꿈과 문항 배치를 유지하도록 검수한다.
- 사용자 선택은 문항 단위로 제한하고, 문항 화면과 시트의 항목 대응 정보를 유지한다. 자유로운 한글 새 문서 전체를 즉시 시트 구조로 변환하는 기능은 현재 우선 작업에 포함하지 않는다.

기존 저장 검수는 A4·B4·A3 원본 용지만 허용하므로, 좁은 용지를 구현할 때 용지 생성·프로필 변경·저장·재열기 검수·문항 전달의 규격 처리도 함께 수정해야 한다. 단순히 화면의 종이 폭만 줄여 저장이 실패하거나 줄바꿈이 달라지는 상태로 끝내서는 안 된다.

## ExamPool 문항 설계 작업 공간

5E의 **문항 설계**는 흰색 문항 편집 영역과 자료 열람 패널을 나란히 배치한다. 기존 ExamPool의 `static/index.html` 문항 설계/근거 검색과 `static/js/question.js`의 성취기준·원문·근거 연결 흐름을 참고했다. 중앙에서 번호·지문·사진/그림·발문·보기·선지 ①~⑤를 입력하면서 옆에서 자료를 확인한다. 작은 화면에서는 ‘문항 작성 / 자료 열람’으로 전환하며 작업 내용을 유지한다. 앱의 어두운 테마에서도 문항과 원문은 화이트톤이다.

**성취기준**은 원래 ExamPool의 `app/seed/standards.json`을 그대로 가져온 수록본이다. 교육부 고시 제2022-33호 [별책 9] 과학과 교육과정의 20개 과목·371개 기준이며, 과목·단원·핵심어로 찾고 기준 문장, 해설, 탐구 활동과 지도 시 고려 사항을 읽는다. 임의의 기준을 생성하지 않는다. 선택한 기준의 코드·본문·해설·출처와 출제 의도를 문항에 저장한다. 데이터 출처는 자료 패널 하단에 표시한다.

**교과서 / 참고자료**에서 사용자의 PDF·PNG·JPEG·WebP·텍스트 파일을 연다. 기존 5E PDF 런타임으로 PDF 원문을 렌더링하고 텍스트를 추출한다. 파일명과 본문을 검색하며 쪽수 이동·확대·텍스트 인용을 제공한다. 스캔 PDF는 원문 열람을 지원하지만 OCR은 자동 수행하지 않으며 검색 한계를 결과 화면에 안내한다. 자료의 쪽수와 인용/메모를 문항 전체·지문·발문·보기·개별 선지에 연결할 수 있다. 연결한 근거에서 원문을 다시 열 수 있다. 파일별 50 MB, 텍스트 1 MB, PDF 3,000쪽, 자료 100개 제한을 적용한다. 원본 교과서 파일을 새로 배포하거나 가짜 자료를 기본값으로 채우지 않는다.

문항을 만들거나 선택할 수 있고 입력 후 자동 저장한다. 저장 중에도 입력 초점은 유지한다. 명시적인 저장과 창을 닫거나 다른 문항을 선택할 때의 저장도 제공한다. 출력 미리보기는 설계 정보·근거를 제외하고 문항 내용과 그림만 보여준다.

문항은 해당 브라우저/주소의 IndexedDB `5e-exampool/questions`, 자료 원문과 검색 텍스트는 `resources`에 보관한다. 저장소 버전 2로 올릴 때 기존 문항을 보존하고 자료 저장소만 추가한다. 이전 문항 파일의 새 설계 필드는 선택적이며 계속 열린다. 원래 ExamPool의 SQLite 데이터와 별도이며 양방향 DB 동기화는 이번 범위에 포함하지 않는다. 다른 포트·브라우저·컴퓨터에서 이어서 작업하려면 **문항 파일 저장 → 문항 파일 열기**를 사용한다. `.exampool` JSON 파일에는 문항 구조, 성취기준·출제 의도·근거 연결, 자료 원문, 사진, 작업 그림, 확정 그림, 편집 가능한 5E 원본이 함께 들어간다. 파일 열기는 기존 자료를 지우지 않고 추가하며, 동일 ID의 서로 다른 내용은 거부한다. 문항과 자료 가져오기는 단일 트랜잭션으로 처리하고 저장 버전 충돌도 거부한다. 전체 파일은 최대 128 MB이다.

그림은 **현재 5E 그림 가져오기** 또는 **사진 파일 열기**로 작업본을 만든다. **작업본 확정**은 픽셀과 원본을 복제해 확정본으로 보관한다. 새 작업본을 가져와도 이전 확정본은 유지된다. 두 버전이 다르면 화면에서 각각 확인할 수 있다. **5E 원본 편집**은 이미 연결된 작업 탭으로 돌아가거나, 새 탭으로 원본을 복원한다. 다른 탭을 덮어쓰지 않는다. 일반 사진에는 편집 가능한 5E 원본이 없지만 원본이 포함된 PNG는 기존 `readEditablePng` 경로로 복원한다.

**한글로 보내기**는 발문이 없거나 사진/그림이 미확정이면 거부한다. 기존 RHWP 작업 공간의 본문 커서에 번호·지문·확정 그림·발문·보기·선지를 순서대로 넣는다. 전체 삽입은 네이티브 실행 취소 한 번으로 되돌릴 수 있다. 그림 중앙 정렬이 이후 문단에 전파되지 않는다. 기존 `.hwp`/`.hwpx` 저장과 원본 포함 PNG 연결을 이용한다. 사진/그림 없는 문항도 전달할 수 있다. 첫 전달 구현은 로컬 웹 미리보기용이며, 설치 앱의 별도 한글 창 IPC 전달은 후속 범위다.

### 다른 한글 작업 브랜치와의 연결 계약

`initRhwpExamWorkspace(...)` 반환값에 `receiveQuestion(packet): Promise<void>`를 추가했다. 소비자는 `initExamPoolWorkspace(...)`이며, 기존 ExamPool 명칭을 유지한 다음 구조를 전달한다.

```js
{
  format: '5e-exampool', version: 1,
  question: { id, number, passage, ask, bogi_items: [{id, label, text}], choices: [{id, ord, text}] },
  figure: null || { assetId, id, name, confirmedAt, capturedAt,
    png, source, render, widthMm, heightMm, pixelWidth, pixelHeight }
}
```

`figure`는 확정 스냅샷만 전달한다. 작업본이나 현재 캔버스를 전달 함수에서 다시 읽지 않는다. `source`는 기존 `serialize`의 단일 활성 페이지 프로젝트이며 `prepareLoadedProject`로 검증한다. `png`는 실제 확정 픽셀이다. 편집 원본은 기존 `embedEditablePng`로 한글 그림에 포함한다. 일반 사진은 `source:null`이다.

문항·선지·보기·그림 자산·그림 수정본에는 각각 고정 ID를 사용한다. 원래 ExamPool DB의 정수 PK를 가장하지 않는다. 한글에 들어간 5E 그림에는 `exampool:{questionId,assetId,confirmedRevisionId,confirmedAt}` 메타데이터를 남긴다. 한글 문서에서 나중에 편집한 그림은 그 문서의 수정본이며, Pool의 확정본을 자동 변경하지 않는다.

한글 기능 고도화 브랜치의 팔레트/양식 채우기가 합쳐지면 `receiveQuestion` 안에서 기존 문항 필드를 팔레트 슬롯으로 매핑할 수 있다. 현재 구현은 팔레트 이식 코드에 의존하지 않는다. 공통 수정 지점은 `js/main.js`, `js/rhwp-exam-workspace.js`, `js/rhwp-exam-bridge.js`, `index.html`이며, 신규 `exampool-*` 파일은 독립적이다. `RhwpExamBridge.transaction`은 외부 배치 안에서 기존 삽입 도우미를 호출할 때 네이티브 undo를 중복 만들지 않는다.

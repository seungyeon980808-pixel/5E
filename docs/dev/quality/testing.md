# 검사 운영

## 1. 원칙

| 원칙 | 내용 |
|---|---|
| 새 실패만 막는다 | 목록(`tests/known-failures.json`)에 있는 실패는 막지 않고, 목록 밖의 새 실패만 막음. 목록에 새로 넣지 않고 검사를 느슨하게 하지 않음 |
| 고쳤으면 눌러 본다 | 고칠 때마다 로컬 서버로 바로 띄워 사람이 확인. 검사 통과만으로 끝내지 않음(조판 출력이 바뀌면 전후 비교 → 승인 → 커밋) |
| 검사는 가볍게 | 두 엔진 전체 회귀는 합치기·배포 전에만 |
| 품질 기준 | UI 망가짐·디자인 불통일·버벅임·긴 로딩을 없앰. 고칠 때마다 눌러 보고, 맞추고, 숫자로 잼 |
| 검사 쪽을 고쳐 맞추기 | 낡은 기대값은 확인 기준을 그대로 두고 바로잡음. 알려진 실패에 몰래 넣지 않음 |

## 2. 순서

| 언제 | 하는 일 | 시간 |
|---|---|---|
| 고칠 때마다 | 로컬 서버(저장소 루트를 캐시 없이 제공)로 띄워 새로고침해 확인 | 몇 초 |
| 사람이 보는 동안 | 뒤에서 단위 검사 + 고친 기능의 브라우저 검사 1개(크롬만) | 2~3분 |
| 여러 개 고쳐 커밋하기 전 | 고친 영역의 묶음을 한 번 | 5~10분 |
| 합치기·배포 전 | **전체 회귀** 한 번 | 약 75분 |

- 검사가 끝날 때까지 사람의 확인을 미루지 않고, 고칠 때마다 「근처 검사」를 넓게 잡거나 두 엔진으로 돌리지 않습니다.
- 전체 회귀는 별도 작업 폴더에서 돌려 그동안에도 다른 것을 고칠 수 있게 합니다. 결과는 새 실패와 흔들리는 검사를 나눠 봅니다.
- 한계: 사파리에서만 나는 문제나 다른 화면으로 번진 문제는 전체 회귀에서 발견됩니다. 머지 전에 고칩니다.

## 3. 명령

| 용도 | 명령 |
|---|---|
| 단위 검사 | `npm run test:unit` (= `npm test`, `desktop/run-unit-tests.cjs`) |
| 브라우저 검사 전체 | `npm run test:browser` (`tests/run-browser-tests.cjs`) |
| 한 개만 | `node tests/run-browser-tests.cjs --only tests/<검사>.cjs` |
| 알려진 실패와 대조 | `--known-failures tests/known-failures.json`, 결과 파일은 `--report <파일>` |
| 한 엔진만 | `BROWSER_ENGINE=chromium` (이 환경 변수를 따르는 검사 파일만. 나머지는 항상 두 엔진) |
| 스모크 | `npm run test:smoke-contract`, 설치판 `npm run test:desktop`, 이미지 `npm run test:image` |
| 출시 신원 | `npm run verify:release-identity` |
| 웹 배포물 | `npm run test:web-artifact` |
| 기출 모티프 점검 | `npm run audit:exam-motifs` |

환경 변수:

| 변수 | 뜻 |
|---|---|
| `APP_ENTRY=/` | 브라우저 검사는 저장소 루트를 입구로 돌림(기본값 `/preview/`는 옛 사본이라 틀림) |
| `EVIDENCE_DIR=<빈 폴더>` | 증거 파일 위치. 없으면 그래프 검사 10개가 추가로 실패함(환경 문제) |
| `BROWSER_SUITE_TIMEOUT_MS` | 검사 파일마다 제한(전체 회귀는 600000) |
| `BROWSER_SUITE_RETRIES` | 목록 밖 실패 재실행 횟수(0~3, 전체 회귀는 1) |
| `TASK2_ENGINE=chromium\|webkit` | 필수 묶음의 엔진 |

전체 회귀 재현:

```
APP_ENTRY=/ EVIDENCE_DIR=<빈 폴더> BROWSER_SUITE_TIMEOUT_MS=600000 BROWSER_SUITE_RETRIES=1 \
  node tests/run-browser-tests.cjs --known-failures tests/known-failures.json
```

## 4. GitHub 검사 (`test.yml`)

| 단계 | 내용 |
|---|---|
| 단위 | `npm run test:unit` |
| 필수 묶음 | 다섯 검사(AI 인라인 라벨 편집·라이브러리 Space 흐름·크롭 확인·부분 편집·AI 라이브러리 전달)를 두 엔진으로, 실패하면 엔진마다 1회 재실행. 이어서 버튼 디자인 검사 |
| 전체 브라우저 | 알려진 실패를 뺀 새 실패만 막음. 목록의 검사가 통과하면 경고로 알림 |

- 필수 검사 이름: 「Test」, 「Release Identity」. main은 관리자도 적용되고 PR은 main 최신이어야 합니다.
- 실제 맥에서 잰 성능 기준값 검사(`check-browser-performance-reference.cjs`)는 코드가 바뀔 때마다 다시 재야 하므로 막는 단계에서 빼고 수동 진단(`browser-performance.yml`)으로 둡니다. 웹·윈도우 릴리스 워크플로에서는 그대로 돕니다.
- 시간 기준 검사는 GitHub 가상 컴퓨터에서는 참고 경고만 내고(`tests/helpers/performance-reference.cjs`의 `timingCheck`) 실제 맥에서는 막습니다.
- 소스 검사(`web-release.yml`)는 약 3시간이며 유지합니다.

## 5. 알려진 실패 (`tests/known-failures.json`)

| 항목 | 내용 |
|---|---|
| 형식 | `schemaVersion: 1`, `description`, `measuredAt`, `sourceCommit`, `suites[{path, reason}]` |
| 현재 | 111묶음(2026-11-15 측정: 10-18 목록 + 11-15 전체 검진에서 이전 끝 코드에서도 실패한 검사) |
| 이유 분류 | 시간 초과, 기대값이 낡음, 화면이 바뀜, 저장소 밖 자료 필요, 성능, 증거 폴더·환경, 옛 설계 전제 |
| 규칙 | 목록에 새 항목을 더하지 않음(이미 있던 실패만 인정). 검사를 고치거나 지우면 목록에서 뺌. 통과하기 시작한 검사는 목록에서 뺌 |
| 1.7.1 | 목록을 줄이는 것이 목표: 고치거나 낡은 검사는 지움 |

알려진 함정:

- `test-rhwp-exam-menu-focus`는 증거 폴더가 남아 있으면 두 번째 실행부터 `EEXIST`로 실패합니다. 돌리기 전에 그 증거 폴더를 지웁니다.
- 숨겨진 브라우저 창에서는 `requestAnimationFrame`·스크롤 이벤트가 안 돌아 측정이 틀립니다. 측정은 Playwright WebKit으로 합니다.
- 흔들리는 검사: 타이밍에 민감한 몇 개는 재실행하면 통과합니다. 새 실패로 단정하기 전에 단독 재실행합니다.
- 교사 흐름 검사 중 일부는 시작 단계에서 멈출 수 있습니다. 끝낼 때는 내가 띄운 프로세스만 끕니다(서버를 넓게 끄지 않음).

## 6. 밤샘·무인 점검 규칙

- 사용자가 자는 동안에는 묻지 않고 추천대로 진행하고, 안 되는 일은 기록하고 넘어갑니다.
- 맡은 영역을 실제 사용자처럼 끝까지 써 봅니다(두 엔진, 세 화면 색, 창 1440×900과 1100×800).
- 기능 고장·오류(콘솔 오류, 반응 없음, 데이터 사라짐, 겹침·잘림)는 원인을 찾아 고치고 그 동작을 지키는 검사를 더해 작은 커밋으로. 화면 모양·배치를 바꾸는 개선은 고치지 않고 지금/바꿀 모습 비교 시안으로 남깁니다.
- 성능을 숫자로 잽니다: 키 입력 → 글자 표시 100ms 이하, 50ms 넘는 긴 작업, 끌기·스크롤 중 프레임 멈춤(50ms 초과), 창 여는 시간, 같은 동작 20번 반복 뒤 메모리·DOM 증가. 느린 컴퓨터 흉내(크롬은 CPU 4배 제한, 웹킷은 같은 동작 반복)도 봅니다.
- 금지: 푸시·배포, 통합 갈래에 직접 커밋, 다른 사람의 작업 폴더 수정, 실제 AI 생성(계정 사용량), Worker·D1·KV 변경, 알려진 실패 목록에 항목 추가, 서버 넓게 끄기.

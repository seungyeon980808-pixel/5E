# Safari 한글 입력(IME)과 표 칸 블록 단축키(M·S·H·W)

## 증상

실제 Safari에서 **한글 입력 상태**로 표 칸을 블록으로 잡고 M(합치기)·S(나누기)·H(같은 높이)·W(같은 폭)를 누르면 단축키가 동작하지 않고 글자(ㅡ·ㄴ·ㅗ·ㅈ)가 들어갔다. 영문 입력에서는 정상. 자동 검사(Playwright WebKit의 가짜 IME 이벤트)는 통과해서 잡지 못했다.

## 원인

| 번호 | 원인 | 위치 |
|---|---|---|
| 1 (주원인) | 네 글자를 「조합 중이 아닐 때만」 단축키로 판정. macOS Safari는 한글 입력에서 `compositionstart`를 그 키의 `keydown`보다 **먼저** 보내서(크롬과 순서가 다름) keydown 시점에 이미 `isComposing`이 참 → 단축키 판정이 비고 IME 분기로 빠져 네 글자 모두 글자로 들어감 | `js/rhwp-exam-shortcuts.js` |
| 2 | 편집기(rhwp-studio)의 잔여 글자 막기 장치가 `e.key`가 ㄴ·ㅡ·`Process`이거나 조합 중일 때만 켜져, H(ㅗ)·W(ㅈ)는 단축키가 실행돼도 뒤따르는 글자가 들어갈 수 있음 | `vendor/rhwp-studio/assets/*.js`의 `arm()` |

## 고친 방식 (반영됨 — 코드 `rhwp-exam-shortcuts.js`의 `blockLetter` 주변)

1. 칸 블록 상태에는 글자를 넣을 커서가 없으므로, 그 상태에서 시작된 조합은 모두 잘못된 조합이다 → **조합 여부와 관계없이** 키 자리(`event.code`: KeyM·KeyS·KeyH·KeyW)로 단축키 처리.
2. 이미 시작된 조합은 숨은 입력칸(textarea)을 `blur()` 후 바로 `focus()`해서 버린다(Safari에서 조합을 끊는 일반적인 방법).
3. 편집기의 잔여 글자 막기(`input._cellBlockLetterImeGuard.arm`)를 우리 쪽에서 호출하되, 한글 입력으로 판정되면 `Process`/229로 가장해 네 글자 모두에 켠다. 영문 입력이면 켜지 않는다(다음 글자를 막지 않게). **vendor 파일은 고치지 않는다.**
4. ExamPool 미리보기 칸(같은 편집기)도 같은 코드를 탄다 — 두 화면 모두 확인.
5. ⌘·Ctrl·⌥ 조합은 한글 입력 상태에서도 단축키로 처리하고, 수식키 없는 글자만 입력기에 맡긴다.

## 확인 방법 (사람이 해야 함)

- 실제 Safari, 한글 입력 상태에서: 칸 2개 블록 → M(합쳐지고 글자 없음) · S(나뉨) · H·W(같은 높이·폭).
- 구조 잠금이 켜져 있으면 네 키 모두 「구조 잠금 중」 안내만.
- 자동 검사에 「compositionstart가 keydown보다 먼저 오는」 순서를 흉내 내는 경우를 두어 재발을 막는다(추가 여부는 (확인 필요)).
- 교훈: 가짜 IME 이벤트 검사는 브라우저별 이벤트 순서 차이를 못 잡는다 → IME 관련 수정은 실제 Safari 확인이 필수.

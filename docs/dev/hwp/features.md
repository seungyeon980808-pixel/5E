# 5E_hwp 기능 목록·모드·역할

최종 확인: 코드(`js/rhwp-exam-modes.js`, `js/rhwp-exam-shortcuts.js`, `js/rhwp-exam-worksheet.js`, `js/rhwp-exam-layout-tools.js`) 기준. 사용자용 단축키 표는 [HWP_EXAM_SHORTCUTS.md](../../HWP_EXAM_SHORTCUTS.md)에 있고 여기서는 되풀이하지 않는다.

> **1.7.1에서 삭제 결정**: 「교사용 줄」(`[정답]`·`[해설]`·`[분류]` 등 문항 안 표시줄)에 기대는 기능 전부(정답표 자동 채움, 가·나형 정답 따라 고침, 정답·해설지, 분류표, 정답 분포 점검·고르게, 정답 QR, 학생용에서 교사용 줄 빼기)와 MCP 연결. 아래 표에서 「교사용 줄」 열이 ○인 것이 해당한다.

## 1. 역할 분담 (왜 이렇게 나눴나)

| | ExamPool(5E_exam) | 5E_hwp |
|---|---|---|
| 맡은 일 | **내용** — 문항 만들기·성취기준·정답·근거·해설·보관함 | **인쇄 전 최종 조판** — 시험지 전체 모양 |
| 문항 추가 | 여기서 만들어 보낸다 | 새로 쓰지 않는다(글자 고치기는 가능, 겹침은 받아들임) |
| 연결 | 「한글로 보내기」, 5E_hwp 열기 창의 「ExamPool 시험지」 | 고친 문항을 카드로 되돌리는 길은 없음(아직) |

이유: 내용과 모양을 한 화면에서 같이 다루면 조판 엔진 부담과 화면 복잡도가 함께 커져서 나눴다. 문항 틀 추가도 ExamPool 쪽에서 하는 것을 원칙으로 한다.

## 2. 도구 모드 3개 (`rhwp-exam-modes.js`, 반영됨)

| 모드 | 내용 | 기본 |
|---|---|---|
| 기본 | 한컴 리본 그대로(전체 기능) | |
| 집중 | 시험지·학습지에 필요한 도구 줄 + 왼쪽 칸 | ○ (기본값) |
| 없음 | 도구 없이 종이만. 「도구 보기」 단추나 모드 키로 복귀 | |

- 전환 키는 맨 위 줄 모드 단추와 앱 단축키(`appKeyLabel`, 코드의 `Digit4/5/6` = 기본/집중/없음). 문서 일부는 ⌘⌥1~3으로 적혀 있으나 코드가 기준이다.
- 집중 모드 도구 줄: **글자 · 문단 · 표 · 그림 · 문항 · 학습지 · 판짜기** 7묶음(묶음마다 「더 보기」). 오른쪽에 Ω 기호 · ⬚ 양식 저장 · ✓ 점검.
- 왼쪽 칸: 만드는 순서 안내(접힘) · 문항 목록(이동·↑↓·복제·지우기) · 조판 팔레트 · 문서의 그림.
- 설계 원칙: 집중 모드는 「5E 조판 기능 + 자주 쓰는 리본 기능」만 올리고, 취소선·도형·하이퍼링크·이력 관리 같은 일반 워드프로세서 기능은 기본 모드에만 둔다. 도구 줄이 1440px 너비에서 이미 꽉 차서 더 넣으려면 「더 보기」로 보낸다.

### 3-5. 문항 인식 (모든 기능의 바탕)

본문 「1.」 문항 · 묶음 문항 `[1~2]`(지문은 묶음 첫 문항에, 번호 다시 매기면 범위도 고침) · 서술형 `[서술형 1]`(따로 번호) · 여러 구역(1쪽 머리 구역 + 2단 본문) · **표 하나로 된 학교 시험 문항**(첫 칸 「1.」, 발문 칸 「(3점)」, 선지 칸). 마지막 형태를 못 알아보면 팔레트로 만든 학교 시험지에서 문항을 하나도 못 찾는다 — 회귀 검사 대상.

| 기능 | 상태 |

## 5. 알려진 한계·아직

1. **수식·그림 개체가 든 선지**: 엔진에서 수식이 글 위치(offset)에 잡히지 않아, 글 구간을 옮기면 수식이 제자리에 홀로 남는다 → 선지 열 바꾸기·섞기는 그런 문항을 건너뛴다.
2. **다른 파일에서 문항 가져오기**: 엔진 `importParagraphBlock`이 책갈피·구역 문단을 받지 못해 보류. 팔레트의 HWPX 패키지 가져오기 경로가 대안.
3. **ExamPool ↔ 5E_hwp 양방향**: 한글에서 고친 문항을 카드로 되돌리는 길 없음.
4. **선지 자동**은 10pt 글자 폭 어림이라 글꼴·크기가 크게 다르면 한 단계 어긋날 수 있음.
5. 시험지 잠금·버전 기록, 여러 선생님 검토(코멘트): 서버가 필요해 보류.
6. 5E_image 점군 회전 검사가 가끔 흔들림(그림 앱의 회전 입력 경쟁; 5E_hwp 코드와 무관, 원인 조사 필요).

## 6. 엔진(rhwp) 실측 메모 — 새 기능 만들 때

- 문단 간격은 쓴 값의 1/75로 돌려준다. `mergeParagraph(sec,p)`는 p를 앞 문단에 붙인다.
- 편집 묶음 안에서는 `flushDeferredPagination`으로 쪽 배치를 마저 해야 잴 수 있다.
- 0번 문단은 구역·단 설정을 품고 있어 지우면 안 된다.
- 꼬리말 필드는 글로 읽으면 `\u0015`(쪽)·`\u0016`(총 쪽). `getPageInfo(쪽)`에 단 위치·꼬리말 위치가 있다.
- 수식 크기는 `setEquationProperties(…, {fontSize})`. 쪽 그림(`renderPageToCanvas`)은 스튜디오 문서의 캔버스여야 글꼴이 맞다.
- 쪽 번호를 스튜디오 명령 + 글자 넣기로 만들면 불안정하다 → 꼬리말 마당(`applyHfTemplate`) + 총 쪽수 필드를 쓸 것.

## 7. 단축키 모듈 설계 (`js/rhwp-exam-shortcuts.js`)

- 다른 파일을 import하지 않는 독립 모듈. `rhwp-exam-bridge.js` 생성자에서 `installDocumentShortcuts(this)`가 `installTableShortcuts(this)` 앞에 한 번 호출된다.
- 한컴 한글의 Windows 키 조합이 기준. Mac은 한글 고유 조합을 Control로 입력하고, Control+F5~F8이 macOS 시스템 단축키와 겹쳐 Control+Shift 대체 키를 함께 둔다. Command+Shift 조합은 브라우저에 맡긴다.
- 여러 문단 선택 시 문단마다 자기 값에서 바뀌고, 실행 취소 한 번에 되돌아간다.
- 구조 잠금이 켜지면 표 크기·셀 합치기 등 틀 변경 단축키는 「구조 잠금 중」 안내만 한다. 표 칸 Shift+Tab은 한컴 방식(이전 칸).
- 검사: `tests/test-rhwp-exam-shortcuts.mjs`(키 매핑·들여쓰기 계산), `tests/test-rhwp-exam-shortcuts-browser.cjs`(Chromium·WebKit 실제 키 입력, 실행 취소, HWP/HWPX 재열기). 한글 입력(IME) 문제는 [safari-ime.md](safari-ime.md).

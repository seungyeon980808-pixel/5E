# 튜토리얼 실습 과제 재설계 계획 (2026-07-27)

> 대상: `js/tutorial-courses.js` 의 `TASKS` (P1~P10, `makeTask()` 로 생성)
> 성격: **계획 문서**. 이 문서 승인 전에는 코드를 고치지 않는다.
> 근거: `assets/exam-library` 실제 평가원 기출 도판 3,961장 표본 확인

## 1. 현재 실습 과제의 문제 — 무엇이 처참한가

`makeTask()` 가 만드는 과제 한 개의 구조는 이렇다.

```
[도면 보여주기] → (부품 고르기 → 캔버스에 놓기) × 2~3회 → [완성되었습니다]
```

여기서 나오는 결함은 네 가지다.

### (1) '부품 놓기'에서 끝난다 — 기출 도판은 부품이 절반도 안 된다

실제 기출(2027학년도 6월 물리Ⅱ 13번, 마찰 구간 문항)을 보면 도판 구성 요소는:

| 요소 | 개수 | 현재 과제가 가르치는가 |
|---|---|---|
| 지형 꺾은선 · 물체 | 2 | ✅ |
| **치수선 + 수식 라벨** (5h, h, d, 2h) | 4 | ❌ 전혀 없음 |
| **점선 기준선** (수평면·높이 안내선) | 3 | ❌ (outro 글로만 언급) |
| **회색 채움 밴드** (마찰 구간 Ⅰ·Ⅱ·Ⅲ) | 3 | ❌ |
| **텍스트 라벨** (p, q, 정지, 수평면, 마찰 구간 …) | 7 | ❌ |
| 화살표 (v) | 1 | ❌ |

즉 **17개 요소 중 2개**만 실습한다. 나머지는 outro 문장으로 "이렇게 하면 됩니다"라고
말로만 넘긴다("평형점 점선은 직선 도구로 긋고 …", "넓이는 사각형을 겹쳐 놓고 …").
말로 넘긴 것이 정확히 **교사가 실제로 헤매는 지점**이다.

### (2) 완성물이 기출 도판이 아니다

과제를 끝내도 화면에 남는 것은 '도르래 + 네모 하나' 같은 조각이다.
outro가 "나머지 줄은 직선 도구로 이어 주면 완성입니다"로 끝난다 —
**완성된 그림을 한 번도 못 본다.** 실습 과제의 목표가 "그림 한 장을 끝까지"인데
끝까지 가지 않는다.

### (3) 과목 편중 — 기출의 71%를 버린다

| 과목 | 도판 수 | 비중 | 현재 실습 과제 |
|---|---|---|---|
| 지구과학 | 1,225 | 31% | 0개 |
| 물리 | 1,164 | 29% | **10개 전부** |
| 생명과학 | 843 | 21% | 0개 |
| 화학 | 729 | 18% | 0개 |

5E 는 '과학교사'의 도구인데 실습은 물리 전용이다. 화학·생명 교사는 실습 10개 중
**자기 수업에 쓸 그림을 한 장도 만들어 보지 못한다.**

### (4) 5E 의 강한 기능이 실습에 안 들어 있다

이미 구현돼 있는데 실습이 안 건드리는 것:

- **길이표시(치수선) + 치수 라벨** — `lineMode: "lengthArrow"`, `dimensionLabel`
- **채우기 종류** — 색/도트/엑스/**헤칭** (`section-fill.js`)
- **선 종류 점선** — 기출 도판의 필수품
- **입체(solid3d) 경사 투영** — 지구과학 등압면·물리 3D 좌표계의 정답
- **데이터 표 → 산점도**(`data-plot.js`) — 성단 H-R도류 도판
- **함수 그래프 · 좌표평면 축 이름** — (가)/(나) 2패널의 오른쪽 절반

즉 **기능이 없어서 못 가르치는 게 아니다. 실습 설계가 기능을 안 쓴다.**

## 2. 기출 도판의 실제 장르 — 표본에서 뽑은 6종

무엇을 실습으로 만들지는 취향이 아니라 기출 분포에서 정해야 한다.
태그 상위 60종과 도판 표본을 보면 도판은 6개 장르로 갈린다.

| 장르 | 대표 태그(빈도) | 구성 요소 |
|---|---|---|
| **G1 좌표평면 그래프** | 별의물리량(120), DNA상대량(54), 반응속도(39) — 전 과목 최다 | 축 + **세로쓰기 한글 축이름** + 곡선/꺾은선 + 점선 보조선 + **회색 구간 밴드** + 범례 박스 |
| **G2 장치 그림 + 치수** | 마찰력(180), 실연결물체(56), 용수철(48), 빗면(51) | 지형/부품 + **치수선** + 점선 기준선 + 회색 채움 + 라벨 |
| **G3 회로도** | 저항과회로(229) — **단일 태그 1위** | 부품 심볼 + 연결선 + 단자 점 + 라벨 |
| **G4 경사 투영 입체** | 기압과날씨(133), 지질구조(50) | solid3d 면·기둥 + 점선 모서리 + 회색 면 + 라벨 |
| **G5 벡터 작도** | 점전하(86), 전기력(45), 케플러법칙(36) | 화살표 + 각도호 + 직각기호 + 점선 + 수식 라벨 |
| **G6 흐름도/개념도** | 세포호흡과광합성(157), 뉴런과흥분전도(52) | 둥근박스·원·네모 + 화살표 + 텍스트 |

추가로 **표본의 절반 가까이가 (가)/(나) 2패널**이다 — 왼쪽 장치, 오른쪽 그래프.
이건 장르가 아니라 **모든 장르에 걸리는 레이아웃 규칙**이므로 별도 과제로 뺀다.

## 3. 재설계 방향 — 3가지 원칙

### 원칙 1. 과제 = 기출 도판 1장 완성. 실제 도판을 옆에 띄운다

과제를 시작할 때 `reference-window.js`(기출 참고 창) 또는 도판 미리보기로
**목표 도판 원본을 실제로 보여준다.** 지금은 점선 도면만 보여줘서
"내가 지금 뭘 만드는지" 알 수 없다. 목표 도판은 exam-library 의 실제 id 로 지정한다
(예: `p2_2027_06_13`).

### 원칙 2. 단계를 '부품→라벨→치수→마감' 4국면으로 늘린다

`makeTask()` 를 확장한다. 지금은 `parts[]` 하나뿐이니 국면을 추가한다.

```
spec = {
  target,          // 목표 기출 도판 id (참고 창에 띄움)
  parts[],         // ① 뼈대 — 지금과 동일
  labels[],        // ② 이름표 — 텍스트/라벨러로 p, q, 수평면 …
  dims[],          // ③ 치수 — 길이표시 선 + dimensionLabel (5h, d …)
  finish[],        // ④ 마감 — 점선 바꾸기, 회색/헤칭 채우기, 정렬
  export: true,    // ⑤ 이미지로 내보내기까지
}
```

판정은 지금과 같은 방식을 쓴다(`countOf(type) >= n`, `state` 검사).
치수·채우기는 개수가 아니라 **속성값**으로 판정한다
(예: `objects().some(o => o.lineMode === "lengthArrow" && o.dimensionLabel)`).

이러면 과제 1개가 5~6분에서 **8~10분**으로 늘어난다. 대신 끝나면
**진짜 쓸 수 있는 도판 1장**이 남는다. 과제 수를 줄여 총 시간은 유지한다.

### 원칙 3. 장르 × 과목으로 재배치 — 10개 → 8개

과제를 늘리지 않고 **줄인다.** 같은 장르를 3번 반복하는 현재 구성(P1·P2·P3 모두 G2)을
장르 1개당 1~2개로 압축하고, 남은 자리를 화학·생명·지구과학에 준다.

| 새 과제 | 장르 | 과목 | 목표 도판(예시 id) | 이번에 처음 쓰는 것 |
|---|---|---|---|---|
| **P1 · 빗면과 마찰 구간** | G2 | 물리 | `p2_2027_06_13` | 꺾은선 지형 + **치수선 4개** + 회색 밴드 |
| **P2 · 실로 연결된 막대** | G2 | 물리 | `p2_2027_06_15` | 도르래·실 + **치수선 3개** + 헤칭 천장 |
| **P3 · 직류 회로와 검류계** | G3 | 물리 | `p2_2027_06_11` | 회로 심볼 + 연결선 스냅 + 단자 점 |
| **P4 · v–t 그래프와 넓이** | G1 | 물리 | (기존 P9 개선) | 좌표평면 + **축이름** + 회색 구간 + 넓이 헤칭 |
| **P5 · 용액 희석 (가)/(나)** | G2+2패널 | **화학** | `c2_2027_06_08` | 비커 작도(둥근 사각) + **화살표 전이** + (가)/(나) 캡션 |
| **P6 · 세포호흡 흐름도** | G6 | **생명** | `b2_2027_06_11` | 둥근박스·원·네모 + 화살표 + **정렬·간격** |
| **P7 · 등압면 경사 투영** | G4 | **지구** | `e2_2027_06_18` | **입체(solid3d) 면·기둥** + 점선 모서리 + 지시선 |
| **P8 · H-R도와 성단** | G1 | **지구** | `e2_2026_11_09` | **데이터 표 → 산점도** + 2패널 + 범례 박스 |

- G5(벡터 작도)는 심화 코스 쪽에 이미 각도호가 있으므로 P1·P7 안에 화살표 요소로 흡수한다.
- 기존 P10(기출 변형)은 과제가 아니라 **기본 트랙의 `exam-search` 코스가 이미 하는 일**이라
  중복이다 → 삭제하고, 대신 각 과제 끝에 `export` 국면(이미지 내보내기)을 붙인다.
- 기존 P2(용수철)·P3(단진자)·P6(볼록렌즈)·P7(정상파)·P8(전기력선)은 심볼 하나 놓는
  수준이라 과제로서 가치가 낮다 → **심화 트랙의 '심볼 찾아 쓰기' 코스 1개로 통합**한다.

## 3-1. 난이도 — 쉬움 / 어려움 (2026-07-27 추가 · 구현 완료)

튜토리얼을 열면 코스 목록 위에서 난이도를 고른다. 고른 값은 기억되고,
**코스를 시작하는 순간의 값으로 끝까지** 간다(중간에 바뀌면 혼란).
아무것도 안 해 본 사람은 `쉬움`이 기본, 한 번이라도 마친 사람은 `어려움`이 기본이다.

| | 쉬움 | 어려움 |
|---|---|---|
| 목표 | 만들어지는 과정과 흐름을 눈으로 따라간다 | 안내를 보며 직접 만든다 |
| 실습 요구 | 없음 (`wait` 를 걸지 않는다) | 있음 (조건을 만족해야 넘어간다) |
| 각 단계 | 커서 시연 뒤 **앱이 대신 그린다**(1.5초 뒤 `step.auto` 자동 실행) | 직접 만들거나 [대신 그려 주기] 단추 |
| 마지막 | 비교 창을 열어 볼 수 있다 | **기출 원본과 나란히 놓고 비교** |

구현 요점 — 새 축을 만들지 않고 **기존 `step.auto`(자동 단계) 훅을 재사용**한다.

- `tutorial.js` `showStep()`: `easy` 면 `waiting = false`, 그리고 `step.auto` 를
  `AUTOPLAY_DELAY`(1.5초) 뒤에 자동 실행한다(`runAuto`). 그래서 **모든 제작 단계에
  `auto` 가 있어야 한다** — 없으면 쉬움에서 그 요소가 빠진 그림이 남는다.
- 비교 창은 코스 데이터가 `compare: "<기출 id>"` 만 적고 엔진이 띄운다
  (`openCompare`). 내 그림은 내보내기와 같은 경로(`buildExportSvg`)로 뽑아
  편집 화면의 보조선이 섞이지 않게 한다.
- `auto.stay` = 창을 열어 보는 단추(비교 등). 단계를 넘기지 않고, 쉬움에서도
  자동으로 열지 않는다. 이 단계는 `[다음]`을 반드시 함께 남긴다(안 남기면 갇힌다).

### ⚠ 좌표는 손으로 짜지 않는다 — MCP 로 먼저 그려 보고 옮긴다 (2026-07-28)

첫 판은 좌표를 머리로 어림해 코스 데이터에 바로 적었다. 결과는 못 쓸 그림이었다:
글자가 지형선을 덮고, 마찰 구간 띠가 비탈에서 떨어져 나가고, 가로로 긴 원본을
세로로 긴 기본 판(90×60)에 그려 그림만 작고 글자만 커 보였다.

**올바른 순서** (사용자 지시):

1. `mcp-5e` 로 **실제 앱에 그린다** — `set_artboard` → `add_objects`
2. `export_image` 로 **눈으로 본다**
3. 어긋난 곳만 고쳐 다시 그린다 (2~3바퀴면 원본에 근접한다)
4. **그제야** 그 좌표를 코스 데이터로 옮기고, 국면별로 쪼개 단계에 배분한다

P0 의 좌표는 전부 이 절차로 나왔다. 앞으로 P1~P8 을 만들 때도 같은 순서를 지킨다.
좌표를 고칠 일이 생기면 숫자만 만지지 말고 **다시 MCP 로 그려 보고** 고친다.

**2차 수정 (2026-07-28, 사용자 재지적 "진정으로 비슷하다고 생각하는지")**

1차 MCP 판도 원본과 상당히 달랐다. 원본 PNG(1199×324px)를 **픽셀로 재서**
130mm 판으로 환산(1px = 0.1084mm, 원점 = 이미지 중심)한 뒤에야 맞았다.
그때 드러난 결정적 차이 다섯 가지:

| 원본 | 1차 MCP 판 | 고친 방법 |
|---|---|---|
| 지형의 꺾인 곳이 **둥글다** | 각졌다 | polyline `rounded: true, cornerRadius: 2.5` |
| p 옆에 **출발 위치 점선 원** | 없음 | dashed ellipse r=1.5 |
| 비탈선이 p 위로 **조금 더 뻗음** | 없음 | 짧은 직선 추가 |
| **d 는 띠 전체가 아니라 왼쪽 일부**만 잰다 | 띠 전체를 쟀다 | 27.2~35.6 (띠는 26.6~47.2) |

| `v` 가 **세리프 이탤릭**(물리량 서체) | 돋움 이탤릭 → 대문자처럼 보였다 | `EQUATION_FONT_FAMILY` |

**3차 수정 (2026-07-28, 사용자 재지적)**

| 원본 | 2차 판 | 고친 방법 |
|---|---|---|
| 마찰 구간 띠가 표면 **아래**로 들어간다(지면 두께) | **위로 얹혀** 장애물처럼 보였다 | `bandQuad` 법선 부호 반전 |
| 한글 글씨가 **명조** | 돋움(고딕) | `OBJECT_LABEL_TEXT_FONT_FAMILY` (신명중명조) |
| 수평면 점선 조각 1.1 / 틈 0.7 | 1.5 / 1.2 — 틈이 넓어 끊긴 선처럼 | `newDash(a, b, len, gap)` |
| 물체가 표면선 위에 그대로 앉는다 | 띠 두께만큼 떠 있었다 | 띠 두께를 더하지 않는다 |

같이 고친 튜토리얼 동작 둘:

- **첫 단계에는 '비교'가 없다.** 아직 그린 것이 없어 빈 칸과 나란히 놓는 것은
  비교가 아니다 → `step.exam` 을 새로 만들어 **원본만 한 칸**으로 보여 준다
  (`step.compare` 는 마지막 단계에만).
- **스페이스바 = [다음].** 단추를 매번 누르지 않아도 넘어간다. 단 5E 는 스페이스를
  화면 끌기·자르기 보조로 쓰므로(`tools.js`·`cut-tool.js`), **[다음]이 실제로 보이는
  단계에서만** 가로챈다. 실습을 기다리는 단계에서는 앱에 그대로 넘긴다.

**아직 원본과 다른 곳 (남김)**

- `h` 치수 라벨이 짧은 세로 치수선에 눌려 작게 나온다. 5E 의 길이표시 렌더가
  라벨을 선 **중앙**에 놓기 때문 — 원본은 치수선 **왼쪽**에 정상 크기로 둔다.
  코스 데이터로는 해결 불가. 인스펙터에 '치수 라벨 위치' 옵션이 필요하다(별도 사안).
- 지형 필렛이 원본보다 약간 크다(원본도 상당히 둥글어 큰 차이는 아니다).

이 과정에서 배운 것 둘:

- **판 비율이 먼저다.** 원본이 3.7:1 인데 기본 판은 1.5:1 이다. 판을 안 맞추면
  무엇을 해도 어그러진다 → P0 의 첫 제작 단계를 '아트보드 130×40 으로 맞추기'로 넣었다.
- **글자 크기는 판 크기에 매인다.** 130mm 판에서 구간 이름표는 3.0mm, 짧은 이름표는
  3.2mm 가 원본 비례와 맞는다(기본 3.7mm 는 크다).

**엔진에서 새로 필요했던 것 3가지** (모두 반영 완료):

1. 자동 실행 예약은 **단계 진입 시 한 번만** 걸어야 한다. `showStep()` 은 대상을 못 찾으면
   120ms 간격으로 최대 12번 다시 도는데, 그 안에서 예약을 다시 걸면 매번 뒤로 밀려
   끝내 실행되지 않는다(쉬움인데 아무것도 안 그려지는 증상).
2. `checkUntil()` 은 쉬움에서 **꺼야 한다.** 앱이 대신 그린 결과로 조건이 참이 되므로
   읽을 틈도 없이 화면이 앞질러 간다.
3. `auto.stay` 단추는 `revisiting` 이어도 **남겨야** 한다. 비교 창을 닫고 [이전]으로
   돌아오면 다시 열 수 없게 되기 때문. `[다음]`도 함께 남긴다(안 남기면 갇힌다).

**아직 원본과 다른 곳**(시범 판단 후 다듬을 것):

- `마찰 구간 Ⅰ` 이름표가 원본보다 왼쪽 아래로 떨어져 있다(원본은 띠 바로 아래 지시선)
- `v` 화살표와 라벨이 원본보다 위에 떠 있다
- `h` 치수 라벨이 짧은 세로 치수선에 눌려 작게 보인다
- 로마숫자 Ⅰ 이 얇은 막대처럼 보인다(글꼴 문제 — 원본도 같은 문자를 쓴다)

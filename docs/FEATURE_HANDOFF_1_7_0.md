## 2026-10-10 통합 문서 기준과 기능 경계

이 문서는 기존 RHWP·라벨러 기록을 보존하면서 승인된 그래프 인계의 고정 소스 `b1846e849656076b1c0c5da2f82abffff3813eb1`의 기능 계약을 합친다. 그래프 설계 세부는 [DESIGN 0-20~0-24](../DESIGN.md#0-20-그래프-편집-기존-탭과-선택-대상-편집-2026-10-08)를 따른다. 아래 날짜별 PASS·실패·호출·시간·Safari 기록은 **각 원본 세션 당시의 역사적 영수증**이다. 현재 통합 후보의 통과 수치나 출시 승인으로 옮기지 않는다. 이번 문서 정리는 제품·테스트 변경 또는 새 실행을 포함하지 않으며, 후보의 검증 결과는 별도의 해당 후보 영수증으로 판단한다.

- **공통 진입·저장**: 루트 `index.html`과 호환 `/preview/`는 canonical `/js/`와 같은 상태를 사용한다. 원본 문서의 `preview/js/` 경로는 이 공유 구현에 대응한다. 캔버스와 RHWP source tab은 같은 후보 materializer를 사용하고, 최신 편집 `graphResult`를 과거 raster 미리보기보다 우선한다. 후보 snapshot/checkpoint와 drawing/exam `.5e`·원본 포함 PNG에 그래프·라벨·출처·검수·수정 관계의 합집합을 보존한다.
- **RHWP**: [시험지 작업 공간](RHWP_EXAM_WORKSPACE.md)의 두 단계 크롭/삽입 확인, 고정 탭·그림 연결, 같은 탭 재전송 시 문서 그림 한 개 갱신, 복사본의 독립 ID, 미반영 원본/라벨/크롭 초안과 충돌 보관, 제한된 IPC와 `.5e`/HWP/HWPX/PNG 저장 경계를 유지한다. 그래프 작업대의 새 후보 추가와 문서 그림 갱신을 구분한다. SDK·WASM·폰트 provenance와 자원 검증을 과거 그래프 화면 PASS로 대신하지 않는다.
- **이미지·라벨**: [공통 처리 규칙](IMAGE_LABEL_WORKFLOW.md)의 RHWP 승인 프롬프트·`INPUT_SOURCE.png` 전처리·첫 RAW 보존, 동일 그림 요청의 배경 재사용, 기출 전체 생성 금지와 안전한 라벨 단위 제거를 유지한다. 새 관찰은 `1.4.0`의 `observationContractRevision`·`removalOnlyItems`·각 항목의 `disposition/semanticRole/reason`을 요구한다. 유효한 라벨·과학 객체는 유지하고 선택적 오류는 `deletionAuthority:false`로 격리하며 필수 루트/해시 오류는 차단한다. 분류·형태 관찰을 그림 생성 스타일 지시로 섞지 않는다.
- **차단·명시적 편집**: 일반 복원 대상이 0개인 기출은 원본 보존과 변경 픽셀/삽입 객체 0개를 유지한다. 정상 삽입은 차단하고 대상 0개라는 보존 사유를 보여주며, 빈 관찰에서 그래프 소유권을 추정하지 않는다. 실패/불확실 결과의 검토용 편집은 고정 계획·후보 바인딩이 유효한 경우의 별도 경로다. 현재 선택 결과의 승인된 박스 수정은 비교 후 명시적 취소/적용을 거치고 원본/고정 관찰을 유지한다. [박스 부분 수정 계약](BOX_SCOPED_EDIT_BORDER.md)에 따라 영역 밖 RGBA 변경 0과 세션 소유권을 검사한다. 자동 전체 재분석·전체 재생성이나 과거 숨은 정밀 복원 버튼을 복구하지 않는다.
- **기록의 우선순위**: 아래 초기 준비의 ‘그래프 미구현’, 관찰 `1.3.4`, 전체 롤백, 별도 복원 진입점, 전체 정밀 복원 UI와 옛 검사 수치는 그 날짜의 기록이다. 현재 기능 계약은 이 절, DESIGN 0-20~0-24 및 연결된 최신 계약을 우선한다. 실제 공급자 품질, 화면/물리 크기, 엔진 표현/편집, 합성 응답 재생과 현재 후보 검증은 각각 구분한다.

## 2026-10-10 라벨 옵션 전환 시 동일 배경 보존

사용자가 라벨 옵션 유무에 따라 그림이 달라지지 않도록 수정을 승인했다. 기존 전체 결과 캐시는 라벨 복원·관찰·검수 정책까지 묶었고 UI의 명시적 실행은 이를 우회하므로, 같은 그림 생성 문구여도 매번 새 PNG를 생성했다. 실행 `1.6.1`에서 실제 그림 요청만으로 배경을 식별하고 저장된 작업 또는 독립 RAW 저장소에서 재사용한다. 라벨 옵션을 바꿔도 그림 생성 호출은 추가하지 않고 편집 라벨만 붙이거나 생략한다. 실제 내용·입력·그림 모델·명시적 정밀 복원 요청 변경은 새 그림으로 구별한다.

새 모듈 `preview/js/ai-label-background.js`, 실행 모듈·작업대 연결과 회귀 검사를 추가했다. rhwp 승인 프롬프트와 PNG 전처리 및 RAW 반환, 기존 라벨 관찰·배치·글꼴·편집 처리는 바꾸지 않았다. RAW 저장은 품질 승인과 분리했다. 생성 출처 식별자가 없는 과거 후보를 최신 결과로 자동 인정하지 않는다. 이 작업은 새 그림의 라벨 제거·과학적 의미·장식 제거 품질을 승인한 것이 아니다.

회귀 결과·Safari 화면 확인·이번 작업만의 diff는 `.omo/evidence/label-background-invariance-20261010/REPORT.md`를 따른다. 커밋·푸시·배포하지 않았다.

## 2026-10-09 라이브러리 이미지의 로그인 후 작업대 복귀

사용자가 구현 계획을 승인했다. 로그인이 필요한 라이브러리 전송은 인증 전에 실제 크롭 이미지와 전송 의도를 IndexedDB에 저장하고 숨겨진 작업대를 준비한다. 인증 성공 시 준비한 작업대가 열린 뒤에만 라이브러리의 전송 완료로 처리한다. 종전의 즉시 완료 반환·대기 작업 삭제·3초 후 메인 화면 복귀를 제거했다. 로그인만으로 유료 생성은 시작하지 않는다. 이미 열린 AI 작업대에서 로그인 요청을 보낸 경우에도 같은 작업대를 다시 표시한다.

탭별 sessionStorage에는 `5e.aiLoginIntent.v1`의 의도 ID만 두며 이미지와 인증 비밀을 넣지 않는다. 이미지·크롭 출처·순서·묶음과 프롬프트·배치는 IndexedDB의 `ai-login-intent:` 기록에 보존한다. `ai-reference-import:` 작업대 저널은 생성 범위를 먼저 예약하여 로그인 중 새로고침이나 일부 저장 실패 후 재시도에서 중복 가져오기를 막는다. 취소하면 자동 복귀 포인터와 전송 의도 원문을 삭제하고 라이브러리 선택과 이미 준비한 초안은 유지한다. 늦은 인증 응답은 닫은 창을 다시 열지 않는다. 숨긴 작업대 준비가 일부만 성공해도 라이브러리의 크롭을 먼저 삭제하지 않는다.

라이브러리·로그인·AI 작업대에 공통 임계 감쇠 모션을 적용했다. 닫기/재열기 중 현재 진행 상태를 이어가며, 논리적으로 닫힌 창은 즉시 inert 처리하고 시각적 전환이 끝나면 숨긴다. 모션 감소 설정은 즉시 전환한다. 로컬 이미지 준비와 창 표시가 계정·모델 조회를 기다리지 않게 했으며 실제 생성 전 로그인·모델 확인은 유지한다.

검증: 관련 단위 23/23, 새 브라우저 시나리오 Chromium 8개·WebKit 8개 총 16/16, 기존 라이브러리 전송 9/9, 작업대 생명주기 관련 2/2 통과. 실제 공개 크롭 UI에서 만든 서로 다른 두 PNG의 바이트·이름·출처·순서·묶음 보존, 로그인 성공/취소/재시도/새로고침, 일부 IndexedDB 저장 실패, 중복 상태 응답, 포커스와 모션 감소를 확인했다. 측정한 전환 프레임에서 메인 화면만 보이는 공백은 0건이다. 전체 단위 724/725이며 기존 PNG 압축 바이트 재현성 실패 1건이 남는다. 오래된 작업대 브라우저 묶음은 관련 두 사례를 제외하고 초록 상태가 아니다. 소스 추출 검사 누락과 현재 없는 확인 창·이전 생성 흐름을 요구하는 대표 실패 세 사례는 작업 전 파일 재생에서도 재현했다.

인증 응답은 모의 값이며 실제 계정 로그인 전체 경로와 실제 이미지 생성은 미검증이다. 유료 AI 호출 0회. Safari의 해당 원본 세션의 로컬 미리보기에서 수정본을 새로고침해 실제 앱 표시를 확인했다. 사용자 작업을 대신 생성하거나 계정 인증을 수행하지 않았다. 커밋·푸시·배포하지 않았다. 상세 보고서와 증거는 `.omo/evidence/ai-login-resume-20261009/REPORT.md`에 있다.

## 2026-10-08 후속 실측과 제거 보류 처리

웹(Safari) 실제 사용에서 라벨러 변환이 모두 즉시 실패했다. 원인은 연결 서버 `desktop-bridge.cjs`가 `purpose: 'image'` 외 요청을 422로 거절한 것이다. 새 변환 흐름은 라벨 복원 여부와 관계없이 원본 라벨 관찰(`purpose: 'scene'`)을 먼저 보내므로 웹에서는 어떤 변환도 끝나지 않았다.

서버 커밋 `dfb57e9d`(브랜치 `codex/170-prep-server-labels`, 배포 브랜치 `codex/ai-runtime-model-selection`)에서 `scene` 요청을 받는다. 이미지 생성 기능을 끈 대화 턴으로 실행하고, 턴별 JSON 출력 형식(최대 200KB)을 그대로 전달한다. 결과는 `agentMessage`(final_answer) 1개와 `turn/completed`로 돌려주고 이미지 진행 이벤트는 보내지 않는다. 이미지 생성 감지·빈 답·실패 턴·잘못된 형식은 실패로 끝낸다. 로그인·첨부 크기·작업 공간별 1건·전체 동시 실행 한도는 그림 요청과 같다. `chat`·벡터 요청은 계속 지원하지 않는다. 미배포였던 `736ab86b`(그림 턴의 편집 라벨 계획 전달)도 함께 배포했다.

서버 단위 검증은 97개 중 96개 통과다. 실패 1건(`generation.test.cjs`의 동시 요청 409 기대)은 배포 전 `5eb98d76`에서도 같은 결과인 기존 문제다. 웹 사용자는 변환 1회에 그림 생성 1회와 분석 2~3회를 사용하므로 사용량·대기 시간이 늘어난다.

배포(`dep-db2bgfek1f9s739s6nhg`, healthz revision `dfb57e9d`) 후 Safari 로컬 프로그램에서 실제 계정으로 물리2 27년 6평 5번 자른 영역을 일반·라벨 복원 켜기·Sol 6.1로 변환했다. 원본 라벨 분석 약 1분, 그림 생성·대상 대응·검수를 포함한 전체 2분 51초에 끝났고 이전의 422 거절은 사라졌다. 그림은 라벨이 제거된 선화로 생성됐고 편집 라벨 13개(운동 방향, 광원, P·O·Q, B·C·A, x·y)가 원래 위치에 배치됐다. 다만 최종 검수는 미통과(확인 사항 14개: A·B·C 대상 소유 불확실, P/O 간격 등)였고 캔버스 삽입 버튼이 비활성화됐다. 이 그림은 기출이지만 일반 경로로 처리됐다. 증거: `.omo/evidence/web-scene-labeler-20261006/`.

`ai-settings-panel.js`의 두 버튼 행을 기존 `ai-panel.js` 요청·배경 처리·자동 분리 컨트롤에 연결했다. 새 작업은 Sol 6.1, 라벨 복원 끄기, 배경 제거 끄기, 객체 분리 끄기, 화살표 제거 끄기, 보조선 제거 켜기가 기본이다. 도움말은 그래프 패널의 색상·테두리·간격을 따르고 공통 Escape 계층으로 닫는다. 라벨은 Luna 6 보통을 사용한다. 기출 처리 종류는 기본 패널에서 제외하며 명시적 출처 또는 접힌 원본 처리 방식으로 결정한다. 이전 작업의 누락된 선택은 실행 차단을 유지한다.

`tests/test-ai-settings-panel-browser.cjs`는 실제 프로그램 DOM과 컨트롤러를 사용하고 모델 전송 응답만 고정한다. 기본값·버튼 정렬·저장 정책·도움말·요청 모델 분리·배경 투명화·네이티브 라벨 삽입을 확인한다. 이 UI 검증은 새 모델 그림 품질이나 하네스 개선을 입증하지 않는다. 상세 사용 정책은 `IMAGE_LABEL_WORKFLOW.md`의 최신 UI 항목을 우선한다.

## 자동 라벨러 구현 계약

`feature/1.7.0/auto-labeler`에서 이미지 종류(기출/일반)와 라벨 결과(삭제/편집 객체 복원)를 각각 명시적으로 선택한다. 이전 저장 작업에 선택 정보가 없으면 실행을 차단한다. 이 계약은 단일 실행, 작업별 일괄 실행, 파일 대기열, 재시도, 캐시, 복구에 동일하게 적용된다.

- `ai-image-label-workflow.js`: 정책 버전 `1.0.0`; 기출 보조 표식 유지/일반 제거 기본값, 과학 화살표 유지 기본값. 일반 라벨 소속 글자·지시선·접점·끝점은 이 옵션과 무관하게 함께 제거한다.
- `ai-exam-label-removal.js`: 확인된 도형/경로 마스크에 한정한 비AI 픽셀 처리. 보존 영역·불확실 소속을 지우지 않는다. 과학 구조와 겹친 영역은 국소 복원 최대 1회 후 독립 검수하며 실패 시 보류한다. 전체 화면의 50% 이상을 차지하는 crop은 국소 요청으로 보내지 않는다. PNG를 다시 디코딩하여 마스크 밖 RGBA 동일성을 검사한다.
- `ai-image-label-run.js`: 원본 데이터 해시·고정 계획 해시와 국소 복원 시도 기록을 저장한다. 제거/복원은 같은 관측을 재사용한다. 일반은 첫 이미지 생성 1회이며 자동 추가 교정이 없다. 사용자가 별도 그림 정밀 복원을 선택한 경우에만 직전 후보를 포함한 새 요청을 실행한다.
- `ai-label-target-placement.js`: 원본 관측과 후보 해시에 연결한 대상 대응. 일반은 생성 후 대상 위치를 대조하며 기출은 원본 좌표를 유지한다. 불확실 대응은 검수 필요로 표시한다. 대상 대응/합성 검수가 실패해도 첫 RAW 후보를 보존한다.
- 편집 객체는 기존 네이티브 생성기·렌더러·삽입 경로를 사용한다. 실제 이미지 삽입 직전에 대상 대응과 후보 해시를 다시 검사한다. 삭제 결과는 라벨 객체를 만들지 않는다.
- 캐시는 전체 정책·원본·계획·모델·요청·수동 복원 후보를 키에 포함한다. 잘못된 후보/대응 바인딩은 캐시를 무효화한다. 저장 용량은 이미지·합성물·계획 전체 JSON 크기를 계산한다. 취소는 해당 원격 턴만 중단하고 늦은 결과를 반영하지 않는다.

합성 하네스에서 네 조합, 취소/재시도/늦은 이벤트, 무라벨, 미선택 복구 차단, 캐시, 수동 정밀 복원, 혼합 일괄 실행과 네이티브 더블클릭·실행 취소·다시 실행·저장/재열기를 검증했다. 모델 출력은 하네스에서 제어하므로 실제 과학 그림의 판독·생성 성공률을 뜻하지 않는다. 로컬 증거는 `.omo/evidence/auto-labeler-implementation-20261004/`에 보존한다.

## 보존된 증거와 한계

기존 실제 모델 검증 증거는 로컬 `.omo/evidence/label-standard-policy-20261001/`에 보존되어 있다. 369개 단위 테스트, 5개 파이프라인 시나리오, 2개 합성 시나리오, 3페이지 14개 네이티브 라벨 편집 검증 기록이 있다. 이 수치는 기존 실행 기록이며 이번 준비에서 새로 수행한 검증은 별도 준비 보고서를 따른다.

최신 엄격한 주석 제거 검사에서 3개 중 2개가 통과했고 콩팥 혈관 단면에 흰 끝점이 남았다. 세 그림 모두 전체 그림 품질 검수는 실패했으며 가열 장치의 관 길이·끝 모양, 콩팥 혈관 연결, 네프론 구조·선/명암 변화가 남았다. 네이티브 편집 가능성과 그림 의미 보존 성공은 별개의 판정이다.

2026-10-03 준비 당시 미구현 항목 중, 위 구현으로 해결된 항목:

- 사용자 선택 두 가지의 실제 UI·공통 요청 분기와 모든 진입점 적용.
- 기출 전체 생성 차단 및 제거 마스크 밖 픽셀 보존 검증; 비AI 우선/최대 1회 국소 AI 경로.
- 보조선/과학 화살표 옵션과 고정 라벨 소속 제거 정책의 충돌 해소.
- 최종 생성 이미지에서 실제 대상 대응 재확인/재배치.
- 수동 그림 정밀 복원과 편집 라벨 복원의 UI·호출 기록 구별.

별도 검증/개발이 필요한 항목:

- 네 조합의 실제 모델 결과와 처리 시간의 보편성 검증. 이번 대표 사진형 원본을 기출 정책으로 처리한 실모델 두 조합은 전체 생성 0회/마스크 밖 픽셀 차이 0을 확인했으나, 불완전한 제거 소속 판독과 잔여 라벨로 품질 검수에 실패했다. 기계적 보존과 의미 품질을 분리해서 판정한다.
- 그래프 도구 요구 조사 및 AI 네이티브 그래프 재구성 개발. 이번 자동 라벨러 구현 범위에 포함하지 않았다.

## 현재 기준의 기존 검사 문제

# 원본 그래프 재구성 지원 범위와 검증

원본을 읽어 기존 `coordplane`·`funcgraph` 객체를 새로 삽입한다. 선택한 원본 이미지 객체는 삭제하거나 교체하지 않는다. 이미지 생성으로 그래프를 완성하는 경로는 사용하지 않는다. 축·눈금·내부 표기는 그래프 기능의 소유이며 일반 자동 라벨러와 중복 생성하지 않는다.

## 표현·편집 지원

| 항목 | 지원 및 수용 기준 |
|---|---|
| 선형 축 | 원본의 최소·최대·간격을 보관한다. 모달을 열고 그대로 적용해도 반올림·여백 추가·원점 변경이 없어야 한다. 양수로 시작하는 범위도 표시한다. |
| 제목·단위·눈금 | 빈 제목과 빈 눈금을 유지한다. 눈금은 `{value,label}`로 값과 표시를 분리하며 문자·수식·첨자는 기존 그래프 타이포그래피로 렌더링한다. |
| 복원 라벨의 기울임 | 복원 그래프의 영문·수식·내부 이름표는 정자로 표시한다. 새 객체는 `reconstruction.labelStyle:'upright'`를 기록하고, 이전 복원 저장본도 정자로 표시한다. 글씨 크기·굵기·좌표와 일반 그래프의 수학 변수 스타일은 유지한다. |
| 독립 y2 | 오른쪽 축의 범위와 명시 눈금, 계열의 읽는 축을 보관한다. 왼쪽 축의 배율로 조용히 환산하지 않는다. |
| 점·꺾은선·곡선 | 원본 수학 좌표와 렌더 좌표를 함께 보관한다. 관찰한 모양은 `observed`로 남기며 확정 데이터·함수식으로 승격하지 않는다. |
| 구간과 끝점 | `breaks`는 새 구간 시작 인덱스다. 베지어 핸들이 있어도 끊김을 가로질러 연결하지 않는다. 점 번호별 빈 원·채운 점을 편집한다. 단일 점도 표시한다. |
| 명시 함수식 | 원본에 적힌 식과 정의역만 사용한다. 기존 함수 편집기의 치역 제한도 재편집 때 보존한다. |
| 막대 | 실제 값을 축에 투영한다. 가장 큰 막대를 축에 맞추려고 값을 자동 축소하지 않는다. 기준선 0이 범위에 없는 막대는 검수 후 별도 지원이 필요하다. |
| 음영 | 지원하는 데이터 계열의 x축까지 음영과 x 구간을 보존한다. 끊긴 구간을 가로질러 채우지 않는다. 임의 다각형·두 곡선 사이 음영은 현재 지원하지 않는다. |
| 내부 표기 | 그래프 좌표에 연결된 글자·점·수선 표기를 저장한다. 글자 내용·위치·가로/세로/회전 방향을 모달에서 편집한다. 한글 세로쓰기에서도 수식 런은 분해하지 않는다. |
| 그래프 스타일 | 축·눈금 글씨 배율은 기존 실제 크기를 기준으로 조정한다. 원점 글씨 크기와 점선 굵기·선 조각 길이·빈 간격을 편집·저장·재열기해도 유지한다. `(가)`·`(나)` 같은 외부 패널 구분은 복원 대상에서 제외한다. |
| 이동·저장 | 평면과 계열은 그룹으로 함께 이동한다. 수정·실행 취소·다시 실행·저장·재열기 후 수학 좌표, 표기, 연결 정보가 유지되어야 한다. 음영 뒤에 축·표기를 그려 글자가 가려지지 않아야 한다. |

로그 축, 비등간격 축, 축 생략 기호가 있는 그래프와 data 모드의 수치를 읽지 못한 축·계열은 자동 삽입을 차단한다. observed 모드는 미확정 축 수치와 관찰 모양을 분리하여 편집 가능한 그래프를 삽입한다. 표현 불가 유형은 `variant` 또는 미확정 축으로 기록하고 검수 사유를 남긴다. 단순히 설명용 `review` 문구를 추가하는 것만으로 모든 미지원 형식을 자동 감지한다고 보장하지 않는다. 확정 데이터 좌표와 관찰용 정규화 좌표를 혼동해서는 안 된다.

2026-10-04 표현 보완: 물리량 축이 미확정이어도 명시적인 `coordinateMode:'observed'`로 원본 모양을
표시 좌표 0..1에서 편집한다. 실제 수치와 단위는 원본 메타데이터에 그대로 두며 데이터로 확정하지 않는다.
축선 위치, 구간별 직선/곡선, 과도한 굴곡 없는 자동 핸들, 닫힌 경로, 구간 진행 화살표,
곡선별 파선, 제목 위치·수식·개별 표기 크기와 굵기를 지원한다. 닫힘은 끊긴 구간을 가로질러 연결하지 않는다.
곡선 더블클릭은 해당 그래프의 편집기를 열며, 편집 적용은 기존 계열 ID·레이어·배열 순서와 수동 그룹을 보존한다.
실패한 안전한 분석 초안도 새로고침 후 검수할 수 있다. 잘못된 눈금은 UI에서 오류로 표시하고 삽입을 차단한다.
관찰 모드 눈금 편집은 `값 : 표기 | 위치 0~1 | 표시 수식`을 사용하여 수치와 위치를 구별한다.

## 분석 계약·호출·복구

- 계약: `5e.graph-reconstruction/v1`. 원본 ID·SHA-256·크기·그래프 영역을 바인딩하며, 다른 원본의 응답은 거부한다.
- 캐시 키: 계약 버전, 추출 프롬프트 버전(`graph-observation-v7`), 원본 ID·해시·크기, 선택한 모델·추론 수준·서비스 티어. 캐시를 사용하기 전에도 계약과 원본 바인딩을 다시 검사한다.
- 요청: 전용 그래프 작업 범위에서 이미지 첨부를 관찰하고 JSON 텍스트를 받는다. 이미지 생성 도구 호출을 요청하지 않는다. `requestedImageCalls`는 0이어야 하며, 이미지 생성 관련 이벤트가 오면 실패로 처리한다. 이 값은 요청 계측이며 실제 제공자 내부 도구 실행 수와 구분한다.
- 복구: 전송 전에 작업 상태를 저장한다. 중단된 실행은 중단 상태로 복구하고 자동 재호출하지 않는다. 재분석은 사용자가 선택한다. 취소된 요청의 지연 이벤트를 새 작업 결과로 받지 않는다. 유효한 수동 축 검수 변경도 복구 저장하며 원래 분석 캐시와 구별한다.
- 검수: 오류 또는 차단 항목이 있으면 객체를 삽입하지 않는다. `observed` 결과에는 검수 의무를 남기며 모델의 빈 검수 목록이 이를 지우지 못한다.
- 실패 초안: 원본 바인딩이 검증된 JSON 초안만 `unvalidatedPlan`으로 보존하며 정상 `plan`과 구별한다. 다른 원본 응답은 채택하지 않는다. 보정한 계획이 완전 검증된 뒤에만 정상 상태로 저장한다.

## 재현 가능한 하네스

지정된 그래프 워크트리 루트에서 Node `>=24.21.0 <25`를 사용한다. `node --version`으로 실제 버전을 확인한다. 브라우저 테스트는 설치된 Playwright를 사용한다. `PLAYWRIGHT_MODULE`에는 설치된 `playwright` 모듈의 절대 경로를 지정하며 제품 코드에 그 경로를 넣지 않는다.

```sh
node --version
node tests/test-graph-reconstruction-contract.mjs
node tests/test-native-graph.mjs
node tests/test-graph-reconstruction-workflow.mjs
node tests/test-graph-editing-reconstruction.mjs
node tests/test-graph-correctness.mjs
```

워크트리를 제공하는 미리보기 서버가 없다면 별도 터미널에서 다음을 실행한다. 이미 같은 포트에 서버가 있으면 해당 서버의 루트가 이 워크트리인지 확인하고 중복 실행하지 않는다.

```sh
PORT=55282 node scripts/preview-local-server.cjs
```

브라우저 하네스 터미널에서는 다음을 실행한다.

```sh
: "${PLAYWRIGHT_MODULE:?설치된 playwright 모듈의 절대 경로를 지정하세요}"
export PLAYWRIGHT_MODULE
export PREVIEW_URL=http://127.0.0.1:55282/preview/
EVIDENCE_DIR="$PWD/.omo/evidence/graph-reconstruction-acceptance/ui" node tests/test-graph-reconstruction-browser.cjs
EVIDENCE_DIR="$PWD/.omo/evidence/graph-reconstruction-acceptance/editing" node tests/test-graph-editing-reconstruction-browser.cjs
EVIDENCE_DIR="$PWD/.omo/evidence/graph-reconstruction-acceptance/selection" node tests/test-funcgraph-selection-browser.cjs
```

단위 테스트의 로컬 보고서는 `.omo/evidence/graph-reconstruction-20261004/` 하위에 보관한다. 계약·편집 테스트는 `EVIDENCE_DIR`로 재지정할 수 있다. 각 보고서의 실제 성공 필드·시나리오·생성 파일을 확인하며 과거 총 통과 수를 현재 실행 결과로 인용하지 않는다. 전체 회귀는 `npm run test:unit`과 프로젝트 브라우저 러너로 별도 수행한다. 새 브라우저 검사는 `node tests/run-browser-tests.cjs --only test-graph-reconstruction-browser.cjs` 및 `--only test-graph-editing-reconstruction-browser.cjs`로 실행하면 독립 미리보기 서버도 관리된다.

## 합성 검증과 실제 모델 검증의 구분

합성 계약·모의 전송 테스트는 해시 바인딩, 호출 횟수, 취소·캐시·복구, 차단 경로를 검증한다. 편집 브라우저 테스트는 실제 5E 모달 입력·렌더·실행 취소·저장/재열기를 검증한다. 이동 시나리오는 제품의 `translateObject`를 호출하며, 별도 선택 회귀가 브라우저 선택·이동을 다룬다. 이 검증들은 모델의 원본 해석 정확도를 증명하지 않는다.

### 2026-10-04 자동 관찰 하네스 개선 결과

실제 인증 CLI 이미지 관찰은 11회다. v5의 파동·순환 2회, v6의 기존 기출 5종 5회,
v7의 파동·두 곡선 재분석 2회, v7의 새 표본 물리학Ⅰ 14·16번 2회다.
표본 제목과 검수 기대값은 모델 프롬프트에 제공하지 않았다. 이미지와 원본 바인딩만 제공한다.
각 요청은 새 증거 디렉터리를 사용하며 실패 결과를 보존하고 자동 재시도하지 않는다.

v6 시각 검수는 막전위·순환 PASS, 파동·두 곡선 WATCH, 화학 FAIL이었다.
곡선 어깨·극값과 지시선 접점 추출 지시를 개선해 파동·두 곡선을 실제 재분석했다.
화학은 같은 원문 응답을 유지하고 그래프 라벨에서 `\mathrm{}`·`\text{}`·간격 명령과
중첩·한글 분수를 지원하여 고쳤다. 미리보기·삽입도 원본 plotBox 비율을 유지한다.
최종 7종 모두 주요 곡선·축·점·지시선 관계와 라벨 읽힘 검수, 실제 더블클릭·무변경 적용·
관찰점 수정·실행 취소/재실행·원래 모양 복구·저장/재열기·동일 SVG·편집 재열기를 통과했다.
원문 응답과 최종 계획은 시스템의 review 추가를 제외하고 같으며 수동 좌표·스타일 보정은 없다.
이는 주요 관계와 편집 기능에 대한 수용 판정이며 픽셀 단위 복제나 모든 기출 유형 보장은 아니다.

자동 관찰과 제품 편집을 연결하는 재생 검사는 다음과 같이 실행한다. 원문 응답을 새 모델 호출
없이 사용하며, 원본 해시와 다시 파싱한 계획의 동일성을 검사한다.

```sh
GRAPH_AUTOMATIC_BATCH_EVIDENCE="/absolute/path/to/recorded-batch" \
EVIDENCE_DIR="/absolute/path/to/fresh-editor-evidence" \
node tests/test-graph-exam-refinement-browser.cjs
```

이때 호출 장부는 0이고 `providerTransportPasses`와 `recordedProviderResponsePasses`를 구별한다.
원본 픽셀 기준 지시선-계열 간격과 실제 눈금 라벨 위치를 별도 기록한다. 비교 페이지의 첫

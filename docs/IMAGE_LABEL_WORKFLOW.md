# 이미지·라벨 처리 공통 규칙

상태: 2026-10-03 사용자 합의 고정, 2026-10-04 자동 라벨러 브랜치 구현. 아래 정책은 개발 계약이다. 하네스 통과와 실제 모델 그림 품질은 구별하며 현재 결과는 인계 문서를 따른다.

## 2026-10-10 라벨 복원 옵션과 배경 PNG 분리

실행 버전은 `1.6.1`이다. 일반 이미지의 배경은 실제 그림 생성 요청(원본·전처리 첨부·rhwp 프롬프트·사용자 내용 요청·그림 모델/추론/속도)이 같으면 최초 RAW PNG를 그대로 재사용한다. 라벨 복원 켜기/끄기, 원본 라벨 관찰 JSON, 라벨 검수 정책은 배경의 저장 키에 넣지 않는다. 전체 결과의 검수 캐시를 우회하는 명시적 재시도도 같은 배경을 다시 생성하지 않는다. 라벨 복원 옵션은 이 배경에 붙이는 편집 객체만 바꾼다. 그림 내용 요청·입력·모델 또는 명시적 정밀 복원 첨부가 바뀌면 별개의 그림 요청이다.

`ai-label-background.js`가 배경 식별과 재사용을 담당한다. 저장된 작업의 생성 출처·원본 해시·PNG 해시를 먼저 확인하고, 없으면 독립 IndexedDB `5e.preview:5e-ai-label-background`에서 찾는다. 동시 동일 요청도 그림 생성 한 번을 공유한다. RAW 저장 완료는 그림·라벨 품질 승인과 다르며 승인 캐시를 대체하지 않는다. 저장 실패 시에도 작업에 보존된 PNG를 사용할 수 있다. 이전 결과 중 실제 요청 식별자가 없는 후보를 최신 요청의 결과로 추정하지 않는다.

rhwp 생성 프롬프트와 전처리, 라벨 관찰·배치·5E 객체 편집 로직은 유지한다. 별도로 새로 생성한 rhwp 결과와 픽셀까지 같다는 보장은 아니며, 같은 라벨러 요청에서 라벨 옵션 때문에 그림을 재생성하지 않는 규칙이다. 검증과 남은 기존 검사 문제는 `.omo/evidence/label-background-invariance-20261010/REPORT.md`를 따른다.

## 2026-10-09 rhwp 이미지 하네스와 생성 조건 통일

사용자 승인에 따라 일반 그림 생성은 rhwp 작업판의 `js/ai-approved-first-png.js` 승인 프롬프트·첨부 전처리·RAW PNG 보존 조건을 사용한다. 실행 버전은 `1.6.0`, 검수 스타일 계약은 `2.0.0`이다. 기존 이미지 캐시는 이 버전과 생성 하네스·전처리 입력 해시·사용자 요청이 다르면 재사용하지 않는다. rhwp 기준 프롬프트 SHA-256은 `8d6180f311791d497469d93cbc0eff98919b0d376d84a958f2b391c475e14067`이다.

라벨 관찰은 원본을 사용한다. 그림 생성에는 긴 변 1536 px·최대 250만 픽셀의 동일 전처리를 거친 `INPUT_SOURCE.png` 사본과 승인 프롬프트 및 실제 사용자 요청만 보낸다. 화살표 제거·보조선 유지의 명시적 UI 선택은 내용 요청으로 전달하되 생성 스타일은 바꾸지 않는다. 관찰 JSON의 스타일·윤곽 추적·기하 고정 지시를 생성 요청에 추가하지 않는다. 분석·검수에도 이전 라벨러 전용 스타일 요청을 주입하지 않는다. 반환된 첫 PNG는 재그리거나 필터링하지 않고 보존하며, 라벨 복원과 최종 대상 대조는 별도로 처리한다. 일반 최초 생성 1회·자동 추가 생성 금지·기출 전체 생성 금지 규칙은 유지한다.

표현과 검수는 rhwp가 허용하는 필요한 회색 채움·절제된 음영을 따른다. 피스톤/유체 명도 구분과 도르래의 필요한 음영을 독자적인 무음영 규칙으로 거절하지 않는다. 기존 검사 ID `kice-flat-style`, `flat-gray-regions`는 저장 형식 호환을 위해 유지하되 판정 설명은 새 기준으로 바꿨다. 구조 손상·라벨 잔존은 여전히 별도 확인 대상이다.

일반 AI 라벨의 이름 구간(`labelRuns`의 `name`)이 저장된 돋움 설정을 명조로 덮어쓰던 오류를 수정했다. 기존 5E 일반 글꼴·3.7 mm를 사용하며 저장된 사용자 글꼴 변경을 유지한다. 이전 AI 객체도 저장된 일반 글꼴을 따르고, 물리량·화학식·단위·첨자의 수학적 서체는 유지한다. 저장된 명조를 사용자가 선택했는지는 추정하지 않아 일괄 변경하지 않는다.

검증과 한계는 `.omo/evidence/rhwp-image-harness-alignment-20261009/REPORT.md`를 따른다. 동일 생성 조건의 검증은 모델이 매번 동일한 픽셀이나 과학적 품질을 생성한다는 증거가 아니다.

## 2026-10-08 항목 격리와 라벨 단위 복원

이 절의 당시 실행은 `1.5.4`, 원본 관찰 계약은 `1.4.0`이다. 복원할 `labels`, 제거만 할 `removalOnlyItems`, 그래프 소관 `graphOwnedLabels`, 삭제 권한 없는 `quarantinedItems`를 분리한다. 교과서 본문·캡션·말풍선·장식은 native 라벨로 만들지 않으며 과학적 확대 삽화는 `geometryLock.objects`의 `scientific-inset`으로 보존 요구에 남긴다. 실제 생성 그림에서 제거·보존이 지켜졌는지는 별도로 확인한다.

선택적 관계 묶음이나 개별 후보·제거 영역 오류는 항목별 사유와 `deletionAuthority:false`로 격리한다. 유효한 개별 라벨과 경계가 확인된 과학 객체는 유지하되 잘못된 관계를 추정하지 않는다. 필수 루트, 원본·프레임·후보 해시 계약 오류는 계속 차단한다. 새 모델 응답에는 현재 분류 계약을 요구하며, 이전 응답의 호환 파싱·명시적으로 주석을 추가한 fixture·실제 새 호출을 구분한다.

기출은 글자·소속 지시선·끝점 전체가 안전한 라벨 단위만 제거한다. 한 구성 요소가 불확실하면 그 라벨 전체를 보류한다. `removedLabelIds`에 대응하는 subset만 native로 복원하며 `deferredLabels` 원문 위에는 복원하지 않는다. `removalReport.removalBinding`은 원본·전체 관찰 계획·후보 해시, 제거/복원 ID, 승인 픽셀 마스크 해시를 함께 묶는다. 부분 결과는 `needs-attention` 초안이며 전체 승인이나 승인 캐시가 아니다. 완전히 안전한 라벨이 없을 때는 원본 반환과 별도 편집 목록을 유지한다. 명시적 재시도·국소 복원 예약 규칙과 자동 유료 재시도 금지는 그대로 적용한다.

회색·흐린 글자도 실제 획을 검증한다. 배경 표본은 탐색 범위 바깥의 닫힌 인접 테두리에서 측정하며 삭제 범위는 늘리지 않는다. 바깥 구조와 연결되거나 보호 영역과 겹치는 획은 보류한다. typography/OCR 사각형 자체는 삭제 권한이 아니다. 일반 복원 대상이 없는 기출은 원본 보존 `out-of-scope` 분기이며 그래프 대조군은 복원 성공률 분모에서 제외한다.

native 객체는 기존 라벨러의 Dotum/system Gothic, 기본 3.7 mm, 선·끝점 기본값과 편집 기능을 공유한다. 원본 bbox는 위치·제거 근거로 보관하고 표시 크기를 맞추는 데 사용하지 않는다. 물리량·기호·수식·첨자의 의미별 변형은 유지한다.

이번 증거는 `.omo/evidence/labeler-diagnosis-fix-20261008-session-1039/`에 있다. 실제 모델 요청과 같은 세션 응답의 최신 코드 재생을 분리한다. 파이프라인 종료·native 객체 제공을 과학적 그림 품질이나 일반 래스터 제거 성공으로 계산하지 않는다. 저장 결과 검토 서버에는 새 AI 생성 transport가 없다.

## 이전 실행 1.4.6의 제거 보류 실험 기록

아래는 이전 전체 롤백 계약과 측정 기록이다. 현재 항목별 계약은 위 절을 따른다.

실행 `1.4.6`, 원본 관찰 계약 `1.3.4`다. 일반 변환은 사용하지 않는 픽셀 제거 명세를 요구하지 않는다. 기출은 각 라벨의 `textInkSearch`를 요청한다. `confirmed-flat`은 별도로 관찰한 좁은 글자 탐색 범위, `confirmed-candidates`는 원본을 직접 확인해 별도로 탐색을 허가한 원본 후보 ID와 2픽셀 검사 여백, `needs-review`는 구체적인 보류 사유다. 제거 대상이 아닌 scope에만 `not-applicable`을 사용한다. typography/OCR bbox만으로 삭제 마스크를 생성하지 않는다. 탐색 허가는 픽셀 검증을 대신하지 않으며 단색 배경 표본·닫힌 연결 성분·보호/불확실 영역·외부 연결 검사를 통과한 실제 획만 처리한다.

기출 제거가 불완전하면 부분 후보도 폐기하고 원본 전체를 반환한다. `verifiedInkPixels`는 국소 검사에서 분리한 픽셀 수이고 반환본 `changedPixels`는 0이다. `partialCandidateDiscarded`로 이를 기록한다. 편집 라벨을 지우지 않은 원문 위에 중복 삽입하지 않고 승인/캐시 저장도 하지 않는다. `원본 유지 · 라벨 제거 보류` 결과를 자동 표시하고 결과 확인에서 라벨별 사유를 제공한다. 명시적 재시도에서는 제거 실패 관찰을 재분석하지만 국소 복원 예약은 유지하며 자동 유료 재시도는 없다.

실제 후속 실험은 원본 4개, 관찰 11회, 그림 생성 1회와 통합 검수 1회다. 일반 그림 79.616초/편집 라벨 6개, 최신 기출 분석 16.379~18.478초였으며 완전한 제거 0/3과 일반 품질 uncertain을 그대로 기록했다. 원본 반환과 실제 응답 재생을 새 변환 성공으로 세지 않는다. 단위 104/104, 브라우저 6/6 통과이며 `.omo/evidence/labeler-removal-fix-20261008/index.html`에 원본/이전/수정 후를 보존했다. 별도의 네이티브 모델 실험이며 사용자 Safari 웹 계정에서 동일 심장 그림을 새로 생성한 검증은 아니다.

## 2026-10-06 실제 변환 설정 패널

사용자 승인에 따라 그래프 패널과 같은 행 배치로 실제 프로그램에 반영했다. 기본 옵션은 모두 두 버튼이며 같은 크기와 시작 위치를 사용한다. 각 행 오른쪽 `?`로 설명을 열고, 바깥 클릭 또는 Escape로 도움말만 닫는다.

| 기능 | 두 선택 | 새 작업 기본값 |
|---|---|---|
| 변환 모델 | Sol 6.1 / Luna 6 | Sol 6.1 (계정 카탈로그에서 사용 가능할 때) |
| 라벨 복원 | 끄기 / 켜기 | 끄기 |
| 배경 제거 | 끄기 / 켜기 | 끄기 |
| 객체 분리 | 끄기 / 켜기 | 끄기 |
| 화살표 제거 | 끄기 / 켜기 | 끄기 |
| 보조선 제거 | 끄기 / 켜기 | 켜기 |

라벨 관찰·복원·검수는 그림 변환 모델과 관계없이 Luna 6 보통을 사용한다. 연결 서버의 실제 모델 목록에 두 그림 모델이 없으면 해당 버튼을 비활성화하며 다른 모델을 같은 이름으로 표시하지 않는다. 로그인 전에 이미지를 넣고 설정을 준비할 수 있으나 실제 AI 요청은 기존 로그인 확인을 통과해야 한다.

속도는 `빠르게 · 고정`으로 표시하며 별도 선택하지 않는다. 그림·라벨 요청에 `serviceTier: priority`를 적용하고, 기존 저장 작업의 새 실행·일괄 실행·명시적 재시도도 같은 값을 사용한다. 모델이 빠르게 처리를 지원하지 않으면 전송 전에 차단하며 표준 속도로 몰래 대체하지 않는다. 추론 강도와 기존 생성 품질 설정은 유지한다. 하단은 `연결 정보`로 표시하고 중복 모델·추론·속도 선택을 제공하지 않는다.

직접 넣은 이미지는 `general` 스타일 변환으로 준비한다. 명시적 기출 출처(`imageKind`, `sourceKind`, `libraryKind`)가 전달된 이미지는 `exam` 원본 보존 경로로 준비한다. 그림 픽셀이나 파일 이름을 보고 기출 여부를 분류하는 기능은 구현하지 않았다. 출처가 없는 기출 파일은 접힌 `원본 처리 방식`에서 지정할 수 있다. 기존 저장 작업의 누락된 처리 종류·라벨 선택을 자동 확정하지 않으며 실행 차단을 유지한다.

배경 제거는 가장자리와 연결된 흰 배경만 투명하게 하고 내부 흰 면은 보존한다. 전체 흰색 제거와 그래프 추세선 선택은 기본 UI에서 제공하지 않는다. 객체 분리를 켜면 기존 자동 분리를 사용하고 배경 제거가 함께 적용되며, 분리를 끄면 단일 이미지의 이전 배경 선택을 복구한다. 설정은 기존 요청·저장 컨트롤에 연결한다. 검수된 RAW 바이트와 라벨 바인딩을 보존하고 배경 처리본은 별도 표시·삽입 변형으로 만든다. 별도 업스케일러나 새 생성 하네스를 도입하지 않았다.

|---|---|---|

## 제거와 유지

- 일반 라벨 글자, 그 글자의 지시선 전체, 시작 접점·화살촉·채운 점·빈 원 끝점은 항상 함께 제거한다. 이를 편집 객체로 덮는 방식으로 제거 성공을 판정하지 않는다.
- 기타 보조선·확대 연결선·강조틀은 새 UI 작업에서 제거가 기본이다. 저장된 작업의 정책은 유지하며 소속이 불명확한 실제 구조를 임의로 제거하지 않는다.
- 실제 과학적 방향/힘/이동/혈류/전류 화살표는 유지/제거 옵션을 제공하고 기본 유지한다. 유지 옵션도 라벨 소속 지시선·끝점을 남기는 근거가 되지 않는다.
- 실제 관·혈관·배선·물체 윤곽·구조·눈금은 보존한다. 소속을 판단할 수 없으면 추측해 지우지 않고 해당 영역을 검수 대상으로 표시한다.
- 제거 전에 원본 라벨과 소속 요소를 하나의 고정된 관찰 계획으로 기록한다. 제거 이후 이미지에서 원본 라벨을 다시 추출하지 않는다.

흰 배경 등 비AI 국소 처리를 우선한다. 라벨과 실제 구조가 겹쳐 필요한 경우에만 제거 영역에 한정해 AI 국소 복원을 최대 1회 허용한다. 해결되지 않으면 실패·불확실 영역을 보고한다. 국소 처리가 실패했다고 전체 생성으로 전환하지 않는다. 별도 화질 복원·업스케일러는 도입하지 않는다.

## 일반 이미지 변환 경로

원본 라벨은 별도 관찰하고 rhwp 승인 프롬프트로 글자·라벨 지시선이 없는 첫 그림을 1회 생성한다. 관찰 계획을 독자적인 생성 스타일 지시로 넣지 않는다. 지우기 위해 별도 전체 변환을 반복하지 않는다. 첫 RAW 결과는 자동 추가 교정 없이 보존한다. 검수 실패·불확실 후보는 정상 완료나 성공 캐시로 승격하지 않으며, 현재의 명시적 검토 편집 경로로 사용자가 다듬을 수 있다.

일반 이미지의 표현은 rhwp 승인 하네스의 흰 배경·검정 윤곽과 필요한 회색 채움·절제된 음영을 따른다. 피스톤/유체 명도 구분과 도르래의 필요한 음영을 허용하고 불필요한 질감·반사·장식을 정리한다. 실제 내부 구조선·의미 있는 해칭·과학적 화살표를 장식으로 오인해 지우지 않는다. 라벨러 전용 무음영·윤곽 추적 프롬프트로 생성 스타일을 덮어쓰지 않는다.

독립 검수의 `kice-flat-style`과 `flat-gray-regions`는 일반 변환 결과의 필수 조건이다. 금지 스타일, 누락된 검사, 불확실 판정은 다른 항목의 성공으로 상쇄하지 않는다. 이 스타일 조건은 원본 표현을 그대로 보존하는 기출 경로에는 적용하지 않는다. 이미지 생성 성공과 검수·채택 성공을 별도 상태로 기록한다.

사용자가 `그림 정밀 복원`을 선택했을 때 추가 교정한다. 원본 라벨 텍스트를 편집 객체로 복원하는 `편집 라벨 복원`과 구별한다. 이 수동 옵션도 기출의 전체 재생성 금지를 덮어쓰지 않는다. 현재 구현은 일반 이미지에서 원본·직전 후보와 같은 고정 계획을 첨부해 별도 이미지 요청을 한 번 실행한다. 기출에는 이 옵션을 적용하지 않는다.

## 편집 라벨과 대상 대응

5E의 기존 `text`/`formula`/`labeler` 객체, 등록 글꼴, 의미별 수식 스타일을 사용한다. 수능 형태의 표준 가독성을 우선하며 원본 글꼴의 외관을 그대로 모사할 필요는 없다. 내용·단위·기호·위아래첨자 의미·가리키는 대상은 보존한다.

합성 미리보기와 실제 삽입은 같은 객체 생성·글꼴 측정·렌더를 사용한다. 2026-10-07 승인된 편집 동작은 선택 도구에서 라벨 글자를 한 번 클릭하여 문구를 직접 수정하고, 더블클릭하여 기존 상세 편집기에서 글꼴·크기·기호·수식을 수정하는 것이다. 지시선이 없는 라벨러와 기존 AI `text`/`formula` 라벨도 지원한다. 세로쓰기와 잠긴 객체는 기존 상세 편집 경로를 유지한다. 드래그 이동, 지시선 제어점 편집, 실행 취소/다시 실행, 저장/재열기를 확인한다. 실제 편집 검증과 AI 시각 검수를 구별한다.

원본 관찰 좌표를 최종 생성 이미지 좌표와 같다고 가정하지 않는다. 일반 이미지에서 구조 위치가 바뀌면 최종 후보의 대상 대응을 확인하고 재배치한다. 라벨/대상/끝점을 대응할 수 없으면 검수 필요로 남긴다.

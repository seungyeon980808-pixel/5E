# 기출문항 라이브러리 — 프리셋 개편 기획

> 이미지 라이브러리(v1.4.0+, `feat/image-library`)에서 쓴 **프리셋 + 고급 기능** 방식을
> 기출문항 라이브러리에도 옮기는 안. **승인 전까지 구현하지 않는다.**
> 작성 2026-08-02.

---

## 1. 지금 무엇이 문제인가

기출문항 라이브러리에는 **이미지 처리 옵션이 하나도 없다.** 카드를 고르고 누르면
원본 PNG가 그대로 들어간다.

| 버튼 | 하는 일 | 조절 가능한 것 |
|---|---|---|
| 이미지 삽입 | 원본 PNG를 그대로 넣음 | **없음** |
| 오브젝트 변환 | 선을 따 객체로 만듦 | **없음** |
| 참고창 | 별도 창에 띄움 | 해당 없음 |

그래서 넣은 뒤에 **매번 손으로 뒤처리**를 한다 — 여백을 정리하고, 크기를 줄이고,
흐린 스캔이면 다시 지운다. 이미지 라이브러리에서 프리셋으로 해결한 것과 같은 문제다.

---

## 2. 제안 — 프리셋 4개 + 고급 기능

이미지 라이브러리와 **같은 규약**을 쓴다. 새 규약을 만들지 않는다.

- 프리셋 한 줄이 기본이고, 웬만하면 여기서 끝난다
- `[고급 기능]` 을 누르면 **프리셋이 잠기고** 슬라이더가 열린다
- 고급을 끄면 프리셋으로 돌아온다

### 프리셋

| 이름 | 언제 쓰나 | 하는 일 |
|---|---|---|
| **원본** | 문항 전체를 그대로 보관할 때 | 손대지 않음 |
| **문항용** (기본) | 대부분 | 바깥 여백 잘라내고 폭 맞춤 |
| **도판만** | 그림만 오려 쓸 때 | 여백 자르고 흑백 대비를 올림 |
| **흐린 스캔** | 옛 기출처럼 흐릴 때 | 이진화 임계를 올려 선을 살림 |

### 고급 기능에서 여는 값

| 값 | 범위 | 왜 필요한가 |
|---|---|---|
| 여백 여유 | 0~5 mm | 딱 붙여 자르면 글자가 잘린다 |
| 넣는 폭 | 20~120 mm | 시험지 단 너비에 맞춘다 |
| 흑백 임계 | 0~255 | 스캔 품질이 문항마다 다르다 |
| 흑백으로 변환 | 켜기/끄기 | 컬러 기출은 그대로 둘 때가 있다 |

---

## 3. 새로 만들 것이 거의 없다

필요한 처리는 이미 저장소 안에 있다. **엮기만 하면 된다.**

| 필요한 처리 | 이미 있는 곳 |
|---|---|
| 여백 잘라내기 | `js/cut-geometry.js` (상자 좁히기) · `js/erase-tool.js` |
| 흑백·이진화 | `js/image-objectify.js` · `js/image-line-extract.js` |
| 넣는 폭 | `js/image-paste.js` (`insertImageFromSrc`) |
| 프리셋 UI | `js/parts-library.js` + `css/parts-library.css` (이번에 만든 것) |

새로 짜야 하는 것은 **프리셋 값을 이 함수들에 배분하는 얇은 층** 하나다.

---

## 4. 손대는 파일

```
js/exam-library.js       프리셋 줄 · 고급 패널 · 삽입 시 옵션 전달
css/exam-library.css     partslib 와 같은 모양 (클래스만 examlib-*)
```

`id` 는 전부 유지한다(`DESIGN.md` 13장) — 이벤트 배선을 안 건드려도 된다.

---

## 5. 이건 하지 않는다

- **오브젝트 변환에는 프리셋을 붙이지 않는다.** 그쪽은 성격이 달라 따로 봐야 한다
- 기본값을 바꾸지 않는다 — 지금 쓰던 대로 넣으면 지금과 같은 결과가 나와야 한다
- 여러 장 한꺼번에 넣을 때도 프리셋은 하나만 적용한다(장마다 다르게 주지 않는다)

---

## 6. 확인이 필요한 것

1. **프리셋 이름 네 개가 맞는가** — 특히 "도판만"과 "흐린 스캔"이 실제로 쓰는 상황인지
2. **기본 프리셋을 "문항용"으로 할지 "원본"으로 할지** — 기본을 바꾸면 기존 습관과 달라진다
3. 고급 값 네 개면 충분한지, 더 필요한지

승인되면 위 두 파일만 고쳐 구현한다.

# macOS 프로젝트 저장·열기 개발 반영 (2026-09-18)

커밋 인계 업데이트: 기능 커밋 `bf08683f7c40a3b3b0ea20dcdddac0edaeb026c2`. 통합 범위와 최신 확인 기록은 [인계 문서](HANDOFF_PROJECT_LAUNCHER_20260918.md)에 있다. 아래 미커밋 표시는 커밋 이전 개발 검증 당시의 기록이다. 푸시·배포·설치본 생성은 하지 않았다.

> 아래는 macOS 반영 시점의 기록이다. 이후 추가한 Windows 구현과 현재 검증 범위는 [WINDOWS_PROJECT_OPEN_0918.md](WINDOWS_PROJECT_OPEN_0918.md)를 기준으로 한다.

반영 범위는 프로젝트 저장 파일과 열기 수신 처리, 선택한 파란 파일 아이콘이다. 기존 AI 문서 공유와 그 권한은 별도 기능이며 그대로 유지한다. 커밋·프리뷰 배포·설치본 교체는 하지 않았다.

## 파일과 동작

맥 웹의 ZIP은 당시 `.app` 폴더 패키지를 브라우저에서 한 파일로 전달하기 위해 구현자가 선택한 포장이다. 사용자가 별도로 요청한 프로젝트 기능이 아니다. 웹에서 내려받은 ZIP은 압축을 풀어 `.app`을 여는 추가 단계가 있다. 이번 Windows 경량화에서는 이 Mac 전송 흐름을 변경하지 않았다.

- macOS 개발 앱의 프로젝트 저장은 `.app` 패키지로 저장한다. macOS에서 실행 중인 제품 웹 게이트웨이는 같은 패키지를 ZIP으로 내려준다. ZIP은 압축을 풀고 그 안의 `.app`을 연다.
- 원본 UTF-8 `.5e` 프로젝트 데이터는 패키지의 `Contents/Resources/document.5e`에 들어 있다. 현재 그림 프로젝트 스키마와 포함 범위는 그대로다. 링크 만료나 브라우저 데이터 삭제가 다운로드한 원본을 삭제하지 않는다.
- 파일 아이콘은 승인한 파란 시안으로 만든 `BlueDocument.icns`다. 아이콘의 5E/.5e 글자는 브랜드 표시이며 바깥 파일의 실제 확장자는 `.app`이다.
- `com.5e.editor` 설치 앱이 파일 수신 지원 표시 `FIVEEDocumentLaunchVersion=1`을 가진 경우 그 앱으로 연다. 해당 기능이 없는 구버전 설치본은 빈 문서를 열지 않도록 웹으로 보낸다. 개발 앱에서 저장한 파일은 해당 개발 실행기와 프로필을 사용하므로 다른 컴퓨터로 배포하는 파일이 아니다.
- 웹으로 열 때 원본 데이터만 임시 전송하며 쿠키·AI 인증·세션은 전송하지 않는다. 열기 토큰은 1시간 유효하고 임시 서버 재시작 시 사라질 수 있다. 원본 패키지를 다시 열면 새 전송을 한다. 서버 연결이 실패하면 원본을 유지하고 오류를 표시한다.
- 편집 중인 작업은 기존 저장 상태의 전체 프로젝트 지문으로 확인한다. 빈 페이지의 크기·이름·레이어 변경도 보호한다. 현재 작업이 변경됐으면 열기/취소를 묻는다.
- 기존 프로젝트 패키지를 덮어 저장하면 이전 패키지는 `.previous-시각` 이름으로 남긴다. 다른 설치 앱은 덮어쓸 수 없다. 일반 `.5e`와 예전 `.json` 불러오기는 유지한다.
- 네이티브 패키지 API가 없는 정적 웹 환경과 Windows 저장은 기존 JSON 프로젝트 저장을 유지한다. 실행형 웹 다운로드가 전체 공개 웹에 활성화된 상태는 아니다.

## 구현 및 실행

네이티브 실행기는 macOS 13 이상을 대상으로 arm64/x86_64를 합친 범용 바이너리다. 빌드는 `node scripts/build-project-launcher.cjs`. Swift 6 최적화 빌드와 SourceKit 진단을 확인했다. JavaScript 언어 서버는 사용자가 설치를 거절한 상태여서 구문 검사 및 실행 검증을 사용했다.

개발 실행은 `scripts/start-library-repair-dev.command`를 사용한다. 사용자 개발 프로필과 기존 PDF 자료 경로를 유지하며, 테스트는 `FIVE_E_SMOKE_USER_DATA`로 분리한 프로필에서 수행했다.

웹 개발 확인 주소는 `http://127.0.0.1:19624/`다. 현재 Mac에서 실행 중인 별도의 제품 개발 서버이며 기존 19618 서버는 중단하거나 교체하지 않았다.

## 직접 검증한 내용

- 변경 범위 관련 테스트 29개 통과. 실제 파일을 쓴 뒤 실행 권한, ICNS, 두 아키텍처의 최소 OS 13, 코드 서명, 이전 파일 보존, 다른 설치 앱 보호를 검사했다.
- 실제 개발 앱에서 두 페이지(객체 3개/1개), 한국어 텍스트·사각형·내장 이미지 복원, 프로젝트 메뉴의 `.app` 저장을 확인했다.
- 저장한 네이티브 실행기를 통해 실행 중인 같은 개발 앱으로 다시 파일을 보냈다. 미저장 빈 도해와 변경한 아트보드에서 취소 시 보존, 열기 시 원본 복원을 확인했다.
- 분리 브라우저에서 제품의 웹 수신 기능으로 같은 프로젝트를 복원하고 파일 메뉴에서 `5E 프로젝트.zip` 다운로드를 확인했다. ZIP을 풀어 서명을 다시 검사했다.
- 현재 실행기의 웹 전송은 HTTP 201, 쿠키 없음, 원본 JSON 바이트 일치, 프로세스 종료 코드 0이었다.
- 초기 새 번들은 macOS RunningBoard 로그에 정상 실행 및 종료가 기록됐다. 이전 파란 시제품의 로그는 LSApplicationProxy/POSIX22 실행 실패였다. 새 번들은 매번 새 식별자와 파일로 완성한 뒤 서명하며, 등록한 번들을 제자리에서 수정하지 않는다. 기존 실패의 단일 원인을 완전히 분리한 토글 증거는 확보하지 못했다.
- 기존 PDF 자료팩 72개 문서/288쪽, 실제 PDF 열기, 검색 항목 1,312개와 ‘생명’ 검색 결과 38개를 확인했다.

## 사용자 확인 및 남은 검증

Computer Use가 기본 브라우저의 현재 URL 접근을 차단해 해당 UI 세션을 종료했다. 따라서 실제 Finder 마우스 더블클릭 → 기본 브라우저의 최종 복원 화면을 끝까지 확인한 것은 아니다. 프로그램의 직접 실행과 분리된 개발 앱/브라우저 검증을 더블클릭 검증으로 대체해 주장하지 않는다.

1. 아래 별도 확인 파일 폴더에서 `웹으로 열기.app`을 Finder에서 더블클릭한다. 정상은 웹앱에 `5E 실행기 테스트 · 0918` 텍스트, 검은 사각형, 시험지 이미지, 두 페이지 탭이 나타나는 것이다.
2. 개발 실행창의 파일 → 프로젝트 저장을 눌러 새 이름으로 저장한다. 정상은 파란 아이콘의 `.app` 파일이 생기는 것이다.
3. 도해를 변경한 상태로 저장한 파일을 연다. 정상은 열기/취소 확인이 나오고, 취소하면 변경 작업이 남으며 열기하면 저장한 도해가 복원되는 것이다.

배포 전에는 공개 웹의 패키지 생성 서버와 수신 API 연결, 업데이트된 실제 설치 앱의 수신 동작, Developer ID 서명 및 개별 생성 파일의 공증·다운로드 보안 검증이 필요하다. 현재 컴퓨터의 배포 서명 인증서 수는 0이다. 임시 서명 검사를 통과한 파일이 인터넷 다운로드 후 Gatekeeper를 통과한다고 보장하지 않는다. Windows 실행형 프로젝트 내보내기와 실제 Windows 더블클릭도 미구현·미검증이다.

# 시험지 조판 안정화 — 2026-10-14

## 확인한 원인

RHWP Studio의 `handleResizeHover`는 표 경계의 `hitTestBorder` 결과에 따라 파란 크기 조절선을 표시한다. 마우스 이동만으로 문서 크기를 변경하지는 않지만, 같은 경계를 누르고 드래그하면 `resizeTableCells`를 실행한다. 투명 테두리 표시를 끄는 기존 설정과는 별개의 기능이다.

표 바깥 경계를 클릭하면 표 전체 선택과 이동 경로도 열린다. 표시만 CSS로 숨기면 원래 드래그 영역과 문서 변경 동작이 남으므로 해결되지 않는다.

## 반영한 조치

- 문항 조판에서 표 경계 판정·크기 조절 시작·표 전체 선택을 기본 잠금한다. 일반 시험지 편집기는 기존 동작을 유지한다.
- `표 크기 조절` 버튼을 켠 경우에만 경계 드래그를 허용한다. 문항을 다시 열면 잠금 상태로 시작한다.
- 잠금 상태의 Ctrl+방향키, 셀 선택 상태의 Command+방향키 크기 변경을 차단한다. 본문과 셀 텍스트 편집 및 내어쓰기는 유지한다.
- 문서 재열기 때 새 입력기나 공유 렌더러가 설치되어도 현재 입력기의 잠금 상태를 사용한다.
- 짧은 조합 선지는 원본 기출처럼 번호 다섯 개를 한 줄로 배치한다. 긴 선지는 사용 가능한 너비에 맞춰 열 수를 줄이고 번호 뒤 내어쓰기를 적용한다. 글·수식·표는 한글에서 편집 가능한 상태로 유지한다.
- 기존 글 겹침·셀 넘침·단 너비 검사와 HWPX 재열기 배치 검사를 계속 적용한다.

## 이번 검수와 남은 검수

실제 브라우저의 A4 2단 문항에서 보기·발문·짧은 선지의 배치를 확인했으며, HWPX 재열기 배치 검수를 통과한 파일을 `choice-layout.hwpx`로 저장했다. 표 경계 크기 조절을 끈 첫 버전의 드래그에서도 표 너비가 유지되었다. 그 검수 중 발견한 표 전체 선택 경로를 추가로 잠갔다.

2026-10-14 실행 환경이 복구되었다. 표 전체 선택·공유 렌더러·입력기 교체·단축키 잠금을 포함한 관련 회귀 검사 45개를 통과했다. 좁은 문항 용지의 네이티브 HWPX 재열기는 7종을 검수했다.

추가로 규격 변경 직후 엔진의 메모리에 남은 표 흐름 위치가 잘못되는 원인을 확인했다. 새 규격은 분리된 문서에서 재열기·높이 조절·배치 검수를 거쳐 표시한다. A4→B4→A4 변환과 이전 문서의 서식을 4종에서 확인했다. 또 HWPX 작성기가 명시적 줄바꿈의 줄 높이를 생략해 발문 다음 그림 선지가 위로 올라오는 문제가 있어, 네이티브 HWP의 실제 줄 높이를 HWPX에도 보존했다. 중첩 표와 수식의 기존 줄 배치도 보존한다.

별도 한컴 한글 앱의 설치 글꼴과 실제 출력은 검수 대상이며, 포함된 엔진의 재열기 검수가 이를 대신하지 않는다.

최종 로컬 검수: 현재 워크트리 서버의 식별자를 확인하고 macOS Safari에서 실제 86mm 본문 폭의 문항 용지를 열었다. 인앱 브라우저에서 표 안쪽·바깥쪽 경계 드래그와 Ctrl+Right, 잠금 켜기/끄기를 수행한 전후 HWPX의 글·표·그림 좌표가 모두 같았다. A4→B4→A4 규격 변경 뒤 저장 및 실제 492mm 초과 문항 다운로드도 통과했다. 검수용 임시 문항은 되돌리기 가능한 삭제로 정리했다.

## 보기 여백과 작은 패널

기존 보기 줄바꿈은 사용 가능한 폭에서 40px를 먼저 빼고, 기호 뒤 내어쓰기까지 별도로 적용했다. 실제 글꼴보다 거친 너비 추정도 사용해 줄이 일찍 바뀌었고, 마지막 줄 뒤에 전체 줄 간격을 확보하여 아래 여백이 커졌다. 실제 네이티브 글꼴 너비, 좌우 6px 여백, 첫 줄과 이어지는 줄의 다른 사용 폭으로 계산을 수정했다. 마지막 줄 뒤에는 4px 기본 여백만 확보한다. 중첩 보기의 셀 높이는 명시적으로 지정하고 엔진이 부족하게 계산하는 높이 3px를 보정한다. 셀·상위 셀 넘침 검사는 그대로 적용한다.

화면의 넓은 빈 공간은 문서 폭보다 훨씬 큰 전체 화면 대화상자에서 발생했다. 문서 자체를 다시 조판하지 않고 오른쪽 500px 패널에 임베드하여 화면 확대율을 맞춘다. 메뉴·눈금자·리본을 접는 것은 화면 표시만 바꾸며 문서의 물리 규격과 저장 배치에는 영향을 주지 않는다.

규격 변경이 비동기로 진행되는 동안 다른 문항으로 전환하면 저장이 잘못된 문항에 연결될 수 있는 경합도 확인했다. 규격 변경 완료를 기다리고 변경된 조판을 원래 ID에 저장한 뒤 다음 문항을 연다. 빠른 열 선택은 직렬 처리하며 마지막 요청을 표시한다. 내용이 동시에 달라지거나 조판 대화상자가 열려 있으면 전환을 중단하여 기존 편집을 유지한다.

수정 후 회귀 검사 46개와 네이티브 문항 7종의 재열기 배치 검수, 기존 보기 조판의 글·그림 보존, Safari 실제 화면 및 작은 화면을 확인했다. 별도 한컴 앱의 글꼴 대체·실제 인쇄 검수와 도구 안의 내용 역반영은 별도 범위다.

# 문제 신고 운영

푸터의 벌레 아이콘, AI 작업대·라이브러리의 신고 버튼에서 하고 싶은 말과 이미지 첨부만 입력합니다. 현재 원본·결과 이미지를 미리 보여 주며 원하지 않는 이미지는 제외할 수 있습니다. 보내기를 누르면 표시된 이미지와 최근 오류·조작 기록을 함께 보냅니다. 오류 로그는 같은 창에서 펼쳐 확인합니다. 제목·재현 순서·기대 동작을 따로 입력하거나 별도의 동의 상자를 누르는 절차는 없습니다. 전체 문서나 인증 값을 수집하지 않습니다. 이미지 안의 개인정보는 작성자가 전송 전에 확인합니다.

실패한 전송은 입력과 이미지를 유지합니다. 같은 내용의 재시도는 같은 접수 번호를 사용하고, 내용을 바꾸면 새 번호를 사용합니다. 현재 신고 창에는 JSON 파일 저장 버튼이 없습니다. 로컬 접수함 검증 성공과 외부 운영 서비스의 연결 완료를 구분합니다.

## 로컬 접수함

`scripts/bug-report-server.cjs`를 Node 24.21 이상으로 실행합니다. `FIVE_E_REPORT_ADMIN_TOKEN`에 최소 24자 임의 키를 설정해야 합니다. 키를 저장소·URL·브라우저 저장소에 넣지 않습니다.

- 기본 주소: `http://127.0.0.1:61909/admin`
- 저장 위치: `~/Library/Application Support/5E/bug-reports`
- 변경 가능한 환경 변수: `PORT`, `FIVE_E_REPORT_DIR`, `FIVE_E_REPORT_ORIGINS`
- 직접 API 호출 시 기본 신고 허용 origin: `http://127.0.0.1:61808`, `http://127.0.0.1:50189`
- 신고 파일은 원본 그대로 보관하며 처리 상태와 메모는 별도 `.review.json` 파일에 보관합니다.

관리자 키로 최근 100건을 열고 원본·결과·상황·설정·오류를 확인합니다. 상태는 새 접수 → 조사 중 → 수정 완료이며 정보가 부족하면 추가 정보 필요로 표시합니다. 메모에 재현 조건·수정 커밋·검증 결과를 남깁니다. 현재 목록은 최근 100건만 표시하지만 이전 원본 파일은 삭제하지 않습니다.

로컬 미리보기 서버는 같은 origin의 `/api/bug-reports` 요청을 접수 서비스로 전달합니다. `FIVE_E_REPORT_PORT`로 서비스 포트를 지정할 수 있으며 기본값은 61909입니다. 미리보기 서버를 이전 코드로 실행 중이면 새 검수용 서버를 열어 확인합니다.

## 1.7.0 운영 연결

현재 수신 서버는 Mac의 로컬 주소에만 바인딩됩니다. 외부 사용자 신고를 받는 운영 서비스는 아직 배포하지 않았습니다. 배포 시 HTTPS 수신 API와 관리자 인증, 저장 공간·보존 기간·백업, 목록 페이지 나누기를 연결해야 합니다. 웹앱은 기본 `/api/bug-reports`를 사용하며 필요하면 `5e-bug-report-endpoint` 메타 태그로 수신 주소를 지정할 수 있습니다. 로컬 관리자 키를 운영 사용자에게 공개하지 않습니다. 방문자 집계 역시 사용자의 결정대로 1.7.0 배포 시 연결합니다.

2026-10-14 야간 읽기 전용 확인에서 `https://5e.ai.kr/api/bug-reports`는 HTTP 404를 반환했습니다. 1.7.0 프리뷰 파일의 공개와 신고 운영 서비스 연결은 별도이며, 현재 외부 신고가 관리자에게 전달된다고 안내하면 안 됩니다. 실제 운영 수신 주소·저장 공간·인증을 구성한 뒤 외부 접수와 관리자 확인을 검증해야 합니다.

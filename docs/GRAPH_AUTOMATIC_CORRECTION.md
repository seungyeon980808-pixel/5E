# 그래프 자동 복원과 최대 3회 보정

2026-10-05 사용자 승인 범위: 새 엔진 기능을 AI 출력 지시에 연결하고, 현재 8개 원본을 사람 보정 없이 복원하며, 원본과 실제 렌더를 비교해 최초 포함 최대 3회 시도한다. 처음 보는 20개 추가 검증이나 AI 이미지 패널 통합은 별도 후속 작업이다.

## 구현

- 추출 지시 v8: 박스/열린 축, 로그 눈금, 좌우축, 점 기호, 독립적인 데이터선/보조선 파선, 화살촉, 회색 영역, 범례, 정자 라벨과 보호점 설명. 하단 패널 표기는 제외하고 점 옆 분류 표기는 유지한다. 실제 실행 후 v9에서는 사용하지 않는 마커/화살촉 크기 필드를 0으로 쓰지 않고 생략하도록 명시했다. v9는 단위 검증이며 이번 실제 24회 결과는 v8이다.
- 기본 분석은 기존처럼 1회다. 그래프 복원 모달에서 `최대 3회` 보정 옵션을 선택하면 한 작업에서 최초 응답과 최대 두 번의 보정 응답을 받는다.
- 보정은 원본과 직전 plan의 **실제 네이티브 렌더 PNG**를 첨부한다. 구조 오류로 렌더할 수 없으면 원본과 검증 오류만 전달한다. 수동 기준 입력이나 사례별 정답 좌표를 주입하지 않는다.
- 원본 바인딩/분석 버전/모델 설정/보정 모드는 캐시에서 구별된다. 각 응답과 검증, 첫 결과와 마지막 유효 결과를 보존한다. PNG 해시와 원본 연결 정보도 기록한다.
- 미리보기와 삽입은 그래프 프레임 폭 70mm와 원본 비율을 사용한다. 스타일의 mm 크기와 원본 글자의 픽셀 크기를 구별한다.
- 취소 중 렌더가 완료되거나 늦은 이벤트가 도착해도 다음 요청을 보내지 않는다. 원본 바인딩이 다른 응답은 차단한다. 실패한 마지막 응답을 복구해도 이전 결과가 자동 합격하지 않으며 사용자가 이전 결과를 명시적으로 선택해야 삽입할 수 있다.
- 반복 곡선의 실제 관찰이 요청당 165~183초 걸렸으므로 제품과 CLI의 요청별 시간 제한을 240초로 맞췄다. 취소는 이 제한을 기다리지 않고 처리한다.
- 이미지 생성/외부 도구 이벤트는 감지 시 실패 처리하고 해당 작업을 중단한다. 이벤트 감지를 백엔드에서 실행을 사전에 막았다는 증거로 보고하지 않는다.

## 실행과 증거 구분

`tests/test-graph-reconstruction-iterative.mjs`는 인증된 CLI의 텍스트 관찰 요청을 사용한다. 모델과 reasoning 설정을 임의 지정하지 않는다. 8개 원본만 읽고, 동시 2개, 각 원본 최대 3회, 전체 최대 24회로 제한한다. 요청을 보내기 전에 append-only ledger에 기록하며 실패/시간 초과도 한 번으로 계산한다. 새 증거 폴더만 허용하여 기존 요청을 몰래 반복하거나 덮어쓰지 않는다.

`tests/fixtures/graph-engine-coverage/manifest.json`에서는 `id/sourceFile/sourceHash`만 읽는다. `planFile`, 기존 관찰 응답, 수동 추적점, 필수 기능 정답은 입력으로 사용하지 않는다. 모든 원본의 해시와 이미지 디코딩을 최초 요청 전에 확인한다. 실제 호출 기록과 모의 전송 검증은 폴더와 수치를 분리한다.

모델이 이전 이미지의 문제를 수정했다고 기술해도 새 plan 렌더의 시각적 합격을 확정하지 않는다. 생성/구조 검사/편집 가능/시각 품질은 다른 판정이다. `review.status:'proposed'`는 수정 제안이지 검증 완료가 아니다. 3회 뒤에도 차이가 남으면 그대로 기록한다.

## 확인 방법

결과는 `outputs/graph-auto-harness-20261005/`에 원본·최초 응답·마지막 유효 결과, 응답 JSON, SVG, 개별/통합 `.5e`로 보존한다. 첫 응답이 구조 검사를 실패한 경우 빈 그래프를 성공 결과처럼 그리지 않고 실패 이유를 표시한다.

`tools/package-graph-automatic.mjs`는 원문 응답과 plan이 동일한지 확인한 뒤 실제 웹앱에서 더블클릭, 무변경 적용, 점 데이터 수정, 다른 계열 보존, 실행 취소/다시 실행, 저장/빈 장면에 재열기/재편집을 확인한다. 테스트 편집은 실행 취소해서 원본 AI 결과로 전달한다. `tools/build-graph-automatic-report.mjs`는 동일한 화면 범위의 비교 이미지를 보고서로 묶는다.

실제 CLI 관찰과 웹앱 편집 검증을 수행해도 인증된 데스크톱 앱의 전송부터 삽입까지 실서비스로 실행한 것은 아니다. 브라우저 모달 전송은 모의 이벤트와 실제 DOM/PNG로 검증한다. 통합·출시·배포 완료로 간주하지 않는다.

## 검증 기록

- 모의 workflow 34개와 실제 DOM/PNG 브라우저 14개 통과: `.omo/evidence/graph-auto-correction-20261005/`.
- 독립 CLI 가드/모의 요청 13개, 동일 증거 루트에서 반복 실행 통과: `.omo/evidence/graph-iterative-20261005/guards-repeat/`.
- 전체 단위 검사 331개 중 330개 통과. 기존 PNG 압축 바이트 재현 검사 1개 실패 유지: `.omo/evidence/graph-ai-20261005/regression/unit.log`. 이미지 디코딩 내용이 같은 기존 문제와 구별하여 기록하며 전체 통과라고 보고하지 않는다.
- 실제 원본 처리와 최종 편집/시각 판정: `.omo/evidence/graph-ai-20261005/actual/`, 전달 폴더의 `delivery-verification.json`과 `visual-review.json`을 따른다.

## 실제 실행 결과

원본 8종에 각각 3회, 실제 모델 요청 24회다. 도구·이미지 생성 이벤트는 0회이며 사람의 plan 보정도 0회다. 첫 응답의 구조 검증은 2/8 통과했다. 6종은 비활성 크기 필드를 0으로 써서 거절됐고 두 번째 응답에서 복구됐다. 최종 8/8이 실제 그래프로 만들어지고 편집·저장 검증을 통과했다. 처음 실패한 응답을 첫 성공으로 바꿔 집계하지 않는다.

독립 시각 검수는 6종 사용 가능, 2종 추가 검수, 재현 실패 0종이다. 로그 그래프는 원본의 세로 쌓기 제목을 회전 제목으로 바꿨고, 반복 곡선은 오른쪽 두 눈금 글자가 붙어 있다. observed 좌표이므로 정확한 물리 데이터 회수로 주장하지 않는다. 원본과 픽셀 단위로 완전히 같다는 판정도 아니다.

동시 2개 처리의 모델 실행 총 시간은 약 24분 14초다. 한 원본의 3회 관찰 합계는 약 4~8.6분이며 가장 복잡한 반복 곡선이 오래 걸렸다. 이 수치는 CLI 실행 시간이고 데스크톱 전송 속도나 전체 UI 사용 시간을 대표하지 않는다.

범례 이름이 계열 끝에 중복 표시되는 엔진 기본값을 일반화 수정했다. 명시한 endLabel은 보존하고 범례만 있는 이름은 자동 추가하지 않는다. 이번 최종 AI plan은 이미 빈 끝점 라벨을 반환했으므로 수정 전후 8개 최종 객체가 동일하다. 첫 실패 원문과 24개 프롬프트 해시도 보존한다. strict 러너 exit 1은 최초 6개 실패를 포함한 전체 시도 판정이며 최종 8개 실패를 뜻하지 않는다.

# 실행형 프로젝트 파일 작업 목록

- [x] macOS 개발 앱의 파란 아이콘 `.app` 저장과 프로젝트 수신 연결.
- [x] macOS 개발 웹 서버의 ZIP 저장과 인증 정보 없는 원본 데이터 수신.
- [x] 미저장 빈 도해·아트보드 변경의 열기 취소/확인 보호 및 실제 개발 앱 검증.
- [ ] 사용자 Finder 더블클릭부터 기본 브라우저의 최종 복원 화면까지 확인. 자동화 UI 세션은 URL 제한으로 종료됨.
- [ ] 업데이트한 실제 설치 앱을 통한 cold/warm 파일 수신 및 `.5e` 연결 검증. 설치본 생성·교체는 배포 확인 단계에서 진행.
- [ ] macOS 웹의 ZIP 전달 흐름 재검토. 이전 `.app` 웹 전송을 위한 구현 선택이며, 압축 해제가 필요하다는 점을 더블클릭 요구와 함께 명확히 설명해야 함. 이번 Windows 경량화에서는 Mac 코드를 변경하지 않음.
- [ ] 공개 웹의 네이티브 패키지 생성 서버/API 연결. API 없는 정적 웹은 기존 데이터 파일 저장 유지.
- [ ] 배포용 Developer ID 인증서 준비, 개별 생성 패키지 공증 및 인터넷 다운로드 후 Gatekeeper 검증. 현재 배포 인증서 없음.
- [x] Windows 실행기를 C/운영체제 기본 API로 경량화: 아이콘 포함 88,576바이트, 기존 대비 98.77% 감소.
- [x] Windows x64 실행형 `.exe` 저장, 파란 ICO, 호환 설치 앱 우선/웹 대체, 실행하지 않는 원본 데이터 불러오기 구현.
- [x] 웹 저장/복원 및 실제 제품 수신 코드의 임시 복사본 정리 검증. 호스트는 macOS이며 Windows 운영체제 검증과 구분한다.
- [ ] 실제 Windows의 탐색기 아이콘·더블클릭·설치 앱 cold/warm 수신·NSIS 설치 등록 및 인터넷 다운로드 보안 검증.
- [ ] 개별 Windows 프로젝트 실행 파일 Authenticode 서명과 공개 패키지/수신 API 배포.

현재 결과와 사용자 조작 순서는 [PROJECT_OPEN_0918.md](PROJECT_OPEN_0918.md) 및 [WINDOWS_PROJECT_OPEN_0918.md](WINDOWS_PROJECT_OPEN_0918.md)에 기록한다. 커밋·배포는 아직 하지 않았다.
